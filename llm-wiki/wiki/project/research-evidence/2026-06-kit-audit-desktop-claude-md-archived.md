# КИТ — валидация механики спринта, слабые места и паттерн авто-синхронизации `docs/`

## 0. Область проверки и честный статус (по правилу `verification-before-completion`)

Скилл `verification-before-completion` запрещает заявлять «работает / проходит», не показав свежих доказательств. Поэтому — граница честности сразу, до выводов.

**Что я реально проверил (есть доказательства):**

| Проверка | Как | Результат |
|---|---|---|
| Внутренняя целостность `docs/` (битые `[[ссылки]]`) | `grep` по всем 13 страницам, сверка с 13 каноническими слагами из README | **~22 битых ссылки на 5 страницах** (см. §4) — ПОДТВЕРЖДЕНО |
| Расхождения инвентарей (агенты/хуки/скиллы) | чтение `probely-i-uluchsheniya.md` + перекрёстная сверка страниц | **Подтверждены самим китом**: 11 vs 15 агентов, 6 vs 7 хуков, 5 vs 8 скиллов, 13 vs 14 superpowers |
| Дыра «имя ветки» в хуках | чтение `khuki-mehanicheskie-barery.md`, `faza-3-4-plan-execute.md` | **ПОДТВЕРЖДЕНО документами**: S56 шёл на `chore/...`, хуки `sprint-flow-check`/`phase-advance` на нём молча не сработали |
| Покрытие фаз механическими барьерами | сверка 9 фаз × хуки/скиллы | Только **3 точки принуждения** из 9 (2 хука + внутренние HARD-GATE `sprint-finish`) |

**Что я НЕ могу проверить из этой среды (и не буду утверждать):**

- Живой kit (`~/.claude/`, `.claude/skills/`, `settings.json`, `~/.claude/hooks/*.sh`) сюда **не примонтирован**. Я вижу только пользовательскую документацию `docs/` и справочные PDF проекта.
- Поэтому я **не могу подтвердить**, что «на каждом спринте всё запускается». Заявления «pytest зелёный», «хук реально блокирует», «скилл действительно выстрелил» требуют запуска на вашей машине.
- Ключевой вывод сразу: **сейчас у кита нет способа доказать, что скилл выстрелил.** Скиллы грузятся по совпадению `description` (progressive disclosure), а телеметрии «скилл X загрузился» нет. Значит «всё всегда запускается» — это **надежда, а не гарантия**. Как её превратить в гарантию — §3 (P1-MANIFEST) и §5.

**Команды, которые дают свежие доказательства на вашей машине** (запустить и приложить вывод — это и есть `verification-before-completion` применённый к самому киту):

# 2) Синтаксис всех хуков (guard-the-guards, §3 P1-BASHN)
for h in ~/.claude/hooks/*.sh; do bash -n "$h" && echo "OK $h" || echo "BROKEN $h"; done

source .venv/bin/activate && python -c "from src.execution.state_machine import TRANSITIONS,ExecutionState,ExecutionEvent; from src.risk.reason_codes import ReasonCode; print(len(list(ExecutionState)),len(list(ExecutionEvent)),len(TRANSITIONS),len(list(ReasonCode)))"

# 4) Битые ссылки в docs/ прямо сейчас (закрывает §4)
grep -rEho '\[\[[^]|]+' docs/ | sed 's/\[\[//' | sort -u   # сверить с ls docs/**/*.md

## 1. Мастер-карта: 9 фаз × механизм × уровень принуждения

Легенда принуждения: **МЕХ** = автоматический хук физически блокирует; **HARD-скилл** = HARD-GATE внутри скилла (`sprint-finish` останавливает сам себя); **МЯГ** = только дисциплина / описание в CLAUDE.md, ничто не блокирует; **ОТСУТ** = не покрыто.

| Фаза | Основной скилл | Артефакт-доказательство | Барьер | Уровень | Дыра |
|---|---|---|---|---|---|
| 1 Orient | `sprint-orient` (проектный) | глава помечена, сводка ≤8 | SPRINT_STATE прочитан + git verified | **МЯГ** | нет проверки, что orient вообще был |
| 2 Brainstorm | `brainstorm-init` → `trader-expert` | `pre-s{N}-backlog.md` | каждый Q → ROUND 1, REVISE→ROUND 2 | **МЯГ** | прямой `Agent()` вместо скилла — анти-паттерн, но ничем не блокируется |
| 3 Plan | `superpowers:writing-plans` | файл плана в `plans/` | `sprint-flow-check.sh` | **МЕХ** ⚠️ | срабатывает ТОЛЬКО на `feature/sprint-NN-*` → см. P0-BRANCH |
| 4 Execute | `superpowers:subagent-driven-development` + `test-driven-development` | per-task коммиты + строки в SPRINT_STATE | обновление SPRINT_STATE после каждой задачи | **МЯГ** | ровно то, что деградировало в S16–S27; хука нет |
| 5 Verify | `superpowers:verification-before-completion` | `Phase 5 = done` + pytest/mypy вывод | `phase-advance.sh` | **МЕХ** ⚠️ | по описанию тоже привязан к sprint-ветке → P0-BRANCH; проверяет только строку статуса, не сам факт прогона |
| 6 Review | L5-ревьюеры + `requesting-code-review` + `receiving-code-review` | отчёты ревьюеров, вердикты | все BLOCKER устранены | **ОТСУТ** ❗ | **нет хука.** Именно тут в S55 поймали 2 BLOCKER (unbounded-loss OCO). Мердж возможен с Phase5=done и не проведённым Phase6 |
| 7 Sync | `wiki-update` (проектный) | правки `components/`, счётчики | `wiki-broken-link-check`, `adr-*-sync` (на push) | **МЕХ** (для wiki) | покрывает `llm-wiki/`, **не `docs/`** → P0-DOCS |
| 8 Ship | `sprint-finish` → `superpowers:finishing-a-development-branch` | `sprint-NN.md`, тег `v0.1.0-alpha.N` | `sprint-finish` HARD-GATE (страница, счётчики, ADR в index) | **HARD-скилл** + МЕХ | зависит от того, что оператор реально вызвал `sprint-finish`, а не смёржил руками |
| 9 Close | ручное: SPRINT_STATE `between-sprints` + запись в `log.md`; `consolidate-memory` кратно 5 | обновлённый SPRINT_STATE | — | **МЯГ** | — |

**Вывод по §1.** Из девяти переходов автоматически принуждаются два (Фаза 3 и Фаза 5), и оба — через привязку к имени ветки, которую тривиально обойти. Самая дорогая по цене ошибки фаза (**6, ревью денежного ядра**) не имеет механического барьера вообще. Это прямо противоречит ожиданию «всё всегда запускается».

**Пробел 2.1-a — `using-git-worktrees` не используется.** Worktrees дают изоляцию параллельных веток без переключения контекста. Прямое применение у вас есть: `autoresearch/*` toy-ветки и параллельные спринты. Сейчас они не изолированы → риск загрязнения рабочего дерева и лишних `git stash`/переключений (это токены и ошибки). **Рекомендация:** привязать `using-git-worktrees` как Optional-скилл к запуску `autoresearch-iterate` и к любому спринту, стартующему поверх незакоммиченных изменений.

**Пробел 2.1-b — `writing-skills` без места в цикле = корень дрейфа инвентарей.** Изменение самого кита (новый агент, правка хука, новый скилл) не имеет фазы. Отсюда — расхождения §4 (5→8 скиллов, 11→15 агентов не внесены в каноны). Это тот самый ваш пункт задачи №3 «если кит правим — документация обновляется». **Рекомендация:** ввести лёгкий тип «kit-maintenance спринт» (§5, шаг 5), где `writing-skills` — основной скилл, а Фаза 7 обязательно обновляет и `docs/`, и `kit-overview-ru.md`/`tooling-inventory-ru.md`.

### 2.2 Семейства: TRIGGER vs DEPTH

Правило кита корректно: **superpowers ведёт процесс (TRIGGER), addy-agent-skills добавляет глубину чеклиста (DEPTH)**. Слабое место — DEPTH-скиллы **чисто совещательные**: ничто не проверяет, что `agent-skills:code-review-and-quality` реально применён при ревью. Это допустимо (когнитивный чеклист неавтоматизируем), но оператор должен понимать: покрытие DEPTH = 0 % гарантии, 100 % дисциплины.

## 3. Реестр слабых мест и исправления (P0 → P2)

Приоритеты: **P0** — ломает цель «всё запускается» или несёт риск денег/секретов; **P1** — систематически подтачивает надёжность/токены; **P2** — гигиена и долг.

### P0-BRANCH — механические барьеры обходятся именем ветки
**Что.** `sprint-flow-check.sh` активен только на `^feature/sprint-([0-9]+[a-z]?)-.+$`. По описанию `phase-advance.sh` тоже привязан к sprint-ветке. На `chore/…`, `fix/…`, `autoresearch/…` — оба **молча пропускают** (fail-OPEN).
**Доказательство.** `faza-3-4-plan-execute.md`: спринт S56 целиком шёл на `chore/kit-integrate-headroom-ponytail`; при `git push` хук «не печатает ни ошибку, ни успех — работает, будто его нет». То есть реальный спринт прошёл вне обоих гейтов.
**Почему бьёт по цели.** «Каждый спринт → всё запускается» ложно ровно тогда, когда ветка названа иначе. Барьер, который отключается переименованием, — не барьер.
**Фикс.** Источник истины «идёт ли спринт» — не строка ветки, а `SPRINT_STATE.md`. Переписать оба хука так, чтобы условие было: `SPRINT_STATE.phase ∈ {2..8}` (активный спринт) **И** имя ветки НЕ соответствует `feature/sprint-*` → **блок** с требованием либо переименовать ветку, либо явно пометить `phase: between-sprints`/`autoresearch`. Тогда план-гейт и verify-гейт срабатывают на любой ветке, где SPRINT_STATE говорит «спринт идёт». Проверка после фикса: `git checkout -b chore/test && git push` при `phase:4-execution` → должен блокировать.

### P0-REVIEW — нет механического барьера на Фазе 6 (ревью денежного ядра)
**Что.** Мердж принуждается только по `Phase 5 = done`. Фаза 6 (доменные ревьюеры) — «все блокеры устранены» на честном слове.
**Почему бьёт.** В S55 именно доменные ревьюеры поймали **TL-01 (live-runtime не вооружал OCO → неограниченный убыток)** и **BYBIT-01 (testnet/mainnet рассинхрон)** — оба прошли ручное ревью незамеченными. Оставлять самую дорогую по цене ошибки фазу без гейта — главный незакрытый риск.
**Фикс.** Ввести хук `review-gate.sh` на `gh pr merge`: если diff тронул денежные пути (`src/signalgen/`, `src/execution/`, `src/risk/`, `src/backtest/`, `override.py`, пути с ключами) → требовать зафиксированный артефакт вердикта ревью — строку `| 6 Review | done |` в SPRINT_STATE **и** файл-след `review-sNN.md` со списком запущенных ревьюеров и их вердиктами (Blockers=0). Иначе — блок. Это распространяет доказанную механику `phase-advance` на Фазу 6 и закрывает graduation-путь autoresearch (P2-RESEARCH) заодно, т.к. он тоже про денежные пути.

### P0-DOCS — у `docs/` нет цепочки актуальности (ядро вашей задачи №3)
**Что.** Для `llm-wiki/` есть полный контур: скилл `wiki-update` + агент `doc-reviewer` + хук `wiki-broken-link-check.sh`. Для `docs/` — **ничего автоматического**. Часть 3 S56 (MCP-поиск + авто-обновление доков) отложена оператором.
**Доказательство прямо сейчас.** §4: ~22 битых `[[ссылки]]` уже висят в `docs/`. Гарантия `doc-linker` про двусторонние ссылки не удержалась, потому что её никто не перепроверяет на финальных именах файлов.
**Почему бьёт.** «Красиво, но неверно» и «код уехал — доки устарели» — обе беды кит уже осознал для wiki, но не закрыл для `docs/`. Плюс это буквально ваш пункт №3.
**Фикс.** Паттерн «Docs-Sync Gate» — §5 целиком (переиспользует уже построенные S56-агенты `doc-writer`/`doc-reviewer-depth`/`doc-linker`, которые сейчас осиротели без интеграции).

### P0-KITVCS — сам кит не под контролем версий (и не переносим)
**Что.** Хуки/агенты/скиллы живут в `~/.claude/` вне репозитория. `khuki-…` прямо пишет: «если кто-то клонирует репозиторий, хуки работать не будут».
**Почему бьёт.** Весь слой принуждения не версионируется, не ревьюится и молча дрейфует между реальным состоянием машины и тем, что заявляют доки (это и есть механическая причина §4). «Quis custodiet ipsos custodes» — код сторожат, но сторожей не сторожит ничто.
**Фикс.** Зазеркалить кит в репозиторий: `kit/agents/`, `kit/skills/`, `kit/hooks/`, `kit/settings.example.json`. Реальный `settings.json` с секретом — **в `.gitignore`**, в репо только шаблон без токена (см. P0-SECRET). Это (а) делает кит переносимым, (б) подчиняет кит его же гейтам, (в) — предпосылка для чистой версии docs-staleness-хука (диффом по `kit/`, а не по mtime вне git).

### P0-SECRET — `GITHUB_TOKEN` открытым текстом в `settings.json`
**Что.** `probely-…` §5: `env.GITHUB_TOKEN = "ghp_…"` (классический PAT) в открытом виде; плюс harness впрыскивает протухший токен, обход `unset GITHUB_TOKEN GH_TOKEN` + Keychain.
**Фикс.** (1) Ротировать токен **сейчас**. (2) Вынести в Keychain/переменную ОС, из `settings.json` убрать. (3) Добавить `~/.claude/settings.json` и `kit/settings.example.json` в зону наблюдения `security-auditor` — сейчас он аудитит `src/`, но не конфиг кита. (4) Никогда не вписывать полный токен в `docs/` (страница под git).

### P1-MANIFEST — «всё запускается» превратить из надежды в проверяемый факт
**Что.** Нет способа увидеть, что скилл фазы выстрелил.
**Фикс.** Проверять **по артефакту**, а не по факту загрузки (это философия `verification-before-completion`, применённая к киту). В `sprint-finish` (Фаза 8) добавить шаг «Skill-firing manifest»: для типа спринта проверить наличие обязательных артефактов:

| Фаза | Артефакт-доказательство (проверяемо `test -f`/`grep`) |
|---|---|
| 2 | `pre-sNN-backlog.md` существует (если брейнштурм не пропущен легально) |
| 3 | план-файл существует (уже под хуком) |
| 4 | `git rev-list --count feature/sprint-NN..` ≈ числу строк в таблице задач SPRINT_STATE |
| 5 | `Phase 5 = done` + сохранённый вывод pytest/mypy (лог в `sprints/sprint-NN.md`) |
| 6 | `review-sNN.md` с вердиктами (после P0-REVIEW) |
| 7 | `git diff` тронул `components/` **и** `docs/` (после P0-DOCS) |
| 8 | `sprint-NN.md` + тег существуют |

Манифест печатается в конце спринта и пишется в `sprints/sprint-NN.md`. Расхождение = STOP. Так «скилл выстрелил» (ненаблюдаемо) заменяется на «артефакт скилла появился» (наблюдаемо и дёшево).

### P1-CASCADE — правило каскада BINDING, но ничем не принуждается
**Что.** `wiki → mem → grep → read` (ADR 0043) — обязательное, но держится на дисциплине. Единственный токен-сторож `context-budget-warn` только предупреждает.
**Фикс (частично механизируемо).** Хук на `Read`/`cat` больших файлов: если цель входит в banned-from-full-read (`llm-wiki/Docs/00-All.md`, планы, `log.md`) и вызов без `offset`/`limit` → **блок** с напоминанием читать частями/через grep. Это единственная часть каскада, которую можно превратить из правила в барьер (проверка аргументов команды), и она прямо экономит токены — цель проекта.

### P1-BASHN — «сторожа сторожей»: синтаксис хуков не принуждается
**Что.** Известная ловушка: обратный апостроф в heredoc ломает bash-хук молча (`khuki-…`). Правило «`bash -n` после правки хука» — дисциплина.
**Почему критично.** Сломанный хук падает **fail-OPEN** — то есть тихо снимает барьер. Это худший режim отказа всей системы принуждения.
**Фикс.** `SessionStart`-хук `hooks-selfcheck.sh`, который прогоняет `bash -n` по всем `~/.claude/hooks/*.sh`. Для этого одного случая политика — **fail-CLOSED**: если хук синтаксически битый, лучше громко предупредить/заблокировать пуш, чем работать с дырой в обороне.

### P1-INVENTORY — авто-генерация канонов вместо ручного счёта
**Что.** §4: 11→15 агентов, 6→7 хуков, 5→8 скиллов, 13→14 superpowers — расходятся, потому что каноны обновляются руками.
**Фикс.** Скрипт `kit-inventory.sh` регенерирует счётчики (`ls ~/.claude/agents | wc -l`, `ls .claude/skills`, `jq` по `settings.json`) в размеченные блоки `kit-overview-ru.md`/`tooling-inventory-ru.md`. Запускать в Фазе 7 kit-maintenance-спринта. Дрейф счётчиков как класс исчезает.

### P1-TUNING — недокументированные и неизмеренные рантайм-настройки
**Что.** `probely-…` §8: `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50` и `MAX_THINKING_TOKENS=10000` без обоснования.
**Разбор под цель «экономия токенов».**
- `AUTOCOMPACT=50 %` — очень раннее сжатие. Компакция **лоссовая**: агрессивно жмёт → теряет детали середины спринта → провоцирует **повторные чтения**, а это лишние токены, т.е. можно получить эффект, обратный цели. Ваш kit де-рискован тем, что состояние на диске (SPRINT_STATE), но 50 % стоит **измерить**, а не выставлять молча.
- `MAX_THINKING=10000` высоко для механических haiku-задач; в идеале бюджет мышления масштабируется по тиру модели.
**Фикс.** ADR с обоснованием + A/B: суммарные токены на спринт при 50 % vs 65 %. Решение — по цифрам, не по интуиции.

### P2 — гигиена и долг
- **P2-RESEARCH.** Возврат из `autoresearch/*` в полный kit-цикл — дисциплина. Стратегия — денежное ядро; graduation должен идти через гейт. Закрывается P0-REVIEW (гейт по путям diff, не по имени ветки).
- **P2-MEMPART.** «Bridges 2-4» (партиции памяти на 4 corpora) описаны, но не внедрены (`probely-…` §7). Память плоская → с ростом mem-search шумит → растёт токен-цена поиска нужного урока. `consolidate-memory` кратно 5 смягчает, но не партиционирует. Долгосрочно — на критическом пути токен-экономии.
- **P2-PINPOLICY.** Смесь пинов (`claude-opus-4-8[1m]`, `claude-opus-4-7`) и алиасов (`sonnet`,`opus`) намеренна, но нет политики «когда пинить, когда алиас» и триггера ревью при смене платформенного дефолта.
- **P2-COMPRESS.** `caveman:compress` — ручной. После правки CLAUDE.md/промпта агента легко забыть пережать → токен-крип. Можно свернуть в `hooks-selfcheck` («промпт не в сжатой форме?» — WARN).
- **P2-DOCLINKS.** ~22 битых `[[ссылки]]` (§4) — исправить сейчас; после P0-DOCS они бы не появились.

## 5. ПАТТЕРН «Docs-Sync Gate»: любая правка проекта → обновление `docs/` (и правка кита → тоже)

Это прямой ответ на задачу №3. Паттерн намеренно **клонирует уже доказанную механику кита** и переиспользует уже построенные агенты — нового почти не строим.

### 5.1 Принцип
Симметрия с wiki-контуром: у `docs/` появляется свой скилл (обновляет), свой ревью (S56-агенты) и свой хук (блокирует устаревание и битые ссылки). Триггер — не «код изменился вообще», а **привязка «источник → страница»**, которая **уже существует** во frontmatter каждой страницы (`source_files:`). Ничего нового авторить не нужно — только читать.

Пример уже имеющейся привязки (из реальных страниц):
```yaml
# faza-1-2-orient-brainstorm.md
source_files: llm-wiki/.../sprint-flow-ru.md, .claude/skills/sprint-orient/SKILL.md, .claude/skills/brainstorm-init/SKILL.md
# faza-3-4-plan-execute.md
source_files: ..., ~/.claude/hooks/sprint-flow-check.sh
```
Это обратный индекс «файл-кита/кода → страница docs», который нужен и коду, и киту. Правка агента/скилла/хука тоже покрыта — они уже перечислены как `source_files`.

### 5.2 Компонент A — хук `docs-staleness-check.sh` (клон `adr-agent-sync-check.sh`)
**Событие:** `PreToolUse` / `Bash`, `case *"git push"*`. **Логика:**
1. Собрать изменённые файлы диапазона пуша: `git diff --name-only <range>` по `src/**` и `kit/**` (kit версионирован — P0-KITVCS).
2. Построить обратный индекс: для каждого `docs/**/*.md` распарсить frontmatter `source_files:` → карта «источник → [страницы]».
3. Для каждого изменённого источника найти привязанные страницы. Если источник в диффе, а его страница в этом же пуше **не** тронута → собрать в список «устаревшие доки».
4. Список пуст → `exit 0`. Непуст → `exit 2` + перечень: `src/risk/kelly.py изменён → docs/03-риск/kelly-sizing.md не обновлён`.
5. `fail-OPEN` при инфра-ошибке (нет python/git) — как все хуки кита.
**Почему это работает:** ровно тот же приём, что `adr-agent-sync-check` (ADR изменён → агент не тронут → блок). Проверен в бою. Покрывает **и код→docs, и кит→docs** одним механизмом.

### 5.3 Компонент B — хук `docs-broken-link-check.sh` (клон `wiki-broken-link-check.sh`)
На `git push`, если тронуты `docs/**`, запустить `lib/docs_broken_link_scan.py`: распарсить `[[…]]`, проверить существование целей, при битых — `exit 2` со списком. **Немедленный эффект:** ловит те самые ~22 ссылки из §4. Python-логика — во внешнем файле (не heredoc), по правилу P1-BASHN. `fail-OPEN`, если скрипт отсутствует.

### 5.4 Компонент C — скилл `docs-update` (симметричен `wiki-update`, инкрементальный)
Проектный скилл `.claude/skills/docs-update/SKILL.md`. Шаги:
1. `git diff --name-only` по `src/**` и `kit/**`.
2. Через обратный индекс `source_files:` найти затронутые страницы `docs/` (**только их**, не полный ребилд — дёшево по токенам).
3. Прогнать **уже существующий** S56-конвейер, ограниченный этими страницами: `doc-writer` → `doc-reviewer-depth` (opus) → для денежного ядра дополнительно доменный ревьюер (`trading-logic-reviewer`/`quant-stats-reviewer`/…) → фикс → `doc-linker`.
4. Прогнать `docs-broken-link-check` локально до пуша.
**Ключевой выигрыш:** активирует осиротевшие агенты `doc-writer`/`doc-reviewer-depth`/`doc-linker`, которые `agenty-doc-kit.md` прямо помечает как «не интегрированы в хуки». Новых агентов — ноль.

### 5.5 Компонент D — генератор `kit-inventory.sh` (закрывает P1-INVENTORY)
Регенерирует счётчики агентов/хуков/скиллов в размеченные `<!-- AUTO:agents -->…<!-- /AUTO -->` блоки `kit-overview-ru.md` и соответствующих страниц `docs/10-как-работает-кит/`. Дрейф §4 исчезает как класс.

### 5.6 Интеграция в фазу
Свернуть в **Фазу 7 (Sync)**: теперь «Sync = синхронизировать И `llm-wiki/`, И `docs/`». Расширить HARD-GATE `sprint-finish`: перед тегом требовать «docs-staleness clean» + «docs-broken-link clean». Отдельная фаза не нужна — избегаем размножения фаз, но docs-sync — отдельный проверяемый шаг.

### 5.7 «kit-maintenance спринт» — правка кита как первоклассная работа (закрывает 2.1-b)
Даже мелкая правка кита (новый агент, правка хука) идёт по мини-циклу **Plan(крошечный) → Execute → Sync(docs/ + каноны через `kit-inventory.sh`) → Ship**, основной скилл — `writing-skills`. Так «правим кит → обновляется документация» становится принуждаемым, а не добровольным.

### 5.8 Правило для `CLAUDE.md` (готово к вставке)
```markdown
## Docs-Sync Gate (BINDING)
Любая правка src/** ИЛИ kit/** обязана в ТОМ ЖЕ пуше обновить привязанные
страницы docs/ (привязка — frontmatter `source_files:`). Принуждение:
- docs-staleness-check.sh  → git push: источник изменён, страница нет → БЛОК
- docs-broken-link-check.sh → git push: битые [[ссылки]] в docs/ → БЛОК
Фаза 7 (Sync) = wiki-update + docs-update (S56-конвейер, только затронутые страницы).
Правка кита = kit-maintenance спринт; Фаза 7 гоняет kit-inventory.sh (авто-каноны).
НЕ вписывать секреты в docs/ (страницы под git). Anti-pattern: «обновлю доки потом».
```

### 5.9 Что переиспользуется vs строится заново
| Уже есть — переиспользуем | Строим (мало) |
|---|---|
| frontmatter `source_files:` (обратный индекс) | `docs-staleness-check.sh` (клон adr-agent-sync) |
| механика `adr-agent-sync-check.sh` | `docs-broken-link-check.sh` + `lib/docs_broken_link_scan.py` (клон wiki-варианта) |
| механика `wiki-broken-link-check.sh` | скилл `docs-update` (клон `wiki-update`) |
| агенты `doc-writer`/`doc-reviewer-depth`/`doc-linker` (S56) | `kit-inventory.sh` (простой `ls`/`jq` → размеченные блоки) |
| Фаза 7 (Sync) как место интеграции | строки в CLAUDE.md + расширение HARD-GATE `sprint-finish` |

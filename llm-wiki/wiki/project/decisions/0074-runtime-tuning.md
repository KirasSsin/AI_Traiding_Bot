# 0074. Runtime-tuning kit (AUTOCOMPACT_PCT / MAX_THINKING)

**Status:** proposed (S62 — решение по цифрам после A/B, пока фиксируем методику)
**Date:** 2026-07-02

## Контекст (P1-TUNING)

`~/.claude/settings.json` env содержит два недокументированных рантайм-параметра:
- `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE = 50` — сжатие контекста при 50% заполнения (дефолт платформы обычно выше).
- `MAX_THINKING_TOKENS = 10000` — бюджет thinking на вызов.

Оба выставлены без записанного обоснования и без измерения. Цель проекта — токен-экономия; настройки, влияющие на неё, должны решаться по цифрам, а не по интуиции.

## Разбор

### AUTOCOMPACT = 50%
Компакция **лоссовая**: чем раньше жмём, тем агрессивнее теряем детали середины сессии → провоцируем **повторные чтения** (лишние токены — эффект, обратный цели). Контр-довод: kit де-рискован тем, что состояние на диске (SPRINT_STATE, sprint-NN, log, review-артефакты) — потеря из контекста восстановима чтением. Но раннее сжатие всё равно может увеличить суммарные токены за спринт. **Гипотеза:** 50% может быть хуже 65% по total-токенам на спринт-профиле кита.

### MAX_THINKING = 10000
Высоко для механических haiku-задач (scaffolding/config/DDL). В идеале бюджет мышления масштабируется по тиру модели: haiku=low, sonnet=medium, opus/fable=high. Единое 10000 переплачивает на механике и может недодавать на judgment-heavy.

## Решение (методика A/B — BINDING; значения — pending измерения)

**НЕ менять значения молча.** Прогнать A/B на 2 сопоставимых kit-спринтах:
- **A:** AUTOCOMPACT=50 (текущее). **B:** AUTOCOMPACT=65.
- Метрика: суммарные output-токены на спринт (из session-логов) при сопоставимом объёме работы (≈равное число задач/фаз).
- Аналогично для MAX_THINKING: 10000 vs масштаб по тиру (haiku 4000 / sonnet 8000 / opus-fable 12000) — если харнесс позволяет per-agent override.
- Решение — по total-токенам, порог значимости ≥10% разницы.

## Последствия

- До измерения значения ОСТАЮТСЯ текущими (50 / 10000) — не трогаем в mega-run.
- A/B требует ≥2 спринтов → уходит оператору/後 mega-run (нужны сопоставимые прогоны).
- Статус ADR: `proposed` → `accepted` после A/B с цифрами.

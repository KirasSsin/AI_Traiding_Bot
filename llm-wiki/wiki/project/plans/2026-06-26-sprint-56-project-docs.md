# Sprint 56 — Project Documentation (Obsidian, для человека с улицы) + doc-kit агенты

> **For agentic workers:** subagent-driven через Workflow. Все участники — `model` opus-4-8[1m] / sonnet-4-6, `effort: max` (ТОЛЬКО S56 — задаётся per-dispatch, деф-файлы не меняются → откат автоматический). Описание строго ИЗ кода. Читатель — НЕ программист и НЕ трейдер.

**Goal:** Создать в `docs/` полноценную, связанную (Obsidian `[[ ]]`) документацию всего бота на русском, понятную человеку без IT/трейдинг-бэкграунда: каждый компонент, стратегия, алгоритм, расчёт, процедура — что делает, зачем, как устроено У НАС (с цитатами `file:line`). Денежное ядро — функция-за-функцией. Плюс раздел «Как работает кит» (наши агенты/фазы/хуки/скиллы) по образцу Wiki-SA, и раздел-обзор с результатом 50+ спринтов.

**Out of scope (отложено по решению оператора):** Часть 3 — MCP-сервер поиска места в доках + skill авто-обновления доков после кода + правило-паттерн. Решим после просмотра docs/.

## Архитектура решения

**Слои документации (без дублирования):**
- `docs/` (НОВОЕ, этот спринт) — человеко-понятный слой «понять весь бот без знания кода». Ссылается ВГЛУБЬ в llm-wiki за тех-деталями.
- `llm-wiki/` (существует) — dev/maintainer база (components, ADR, architecture). НЕ трогаем.
- Устаревшие корневые `.md` (Спецификация*, FULL_PROJECT_DOCUMENTATION, IMPLEMENTATION_NOTES, BACKLOG, TASKS) — после готовности docs/ заменяем на указатель → docs/ (PHASE 7).

**doc-kit агенты (адаптация Wiki-SA, созданы в `~/.claude/agents/`):**
- `doc-writer` (sonnet-4-6) — пишет ИЗ кода для не-программиста, цитирует file:line, пересчитывает числа.
- `doc-reviewer-depth` (opus-4-8[1m]) — проверяет КАЖДОЕ утверждение/число против `src/`.
- `doc-linker` (sonnet-4-6) — Obsidian `[[ ]]` + MOC + граф.
- **Точность денежного ядра** — существующие доменные ревьюеры (trading-logic / quant-stats / data-integrity / bybit-api / security-auditor / architecture-reviewer), per-dispatch на opus/sonnet + effort max. Гибрид: кит-агенты ПИШУТ, доменные ревьюеры гарантируют ТОЧНОСТЬ.
- В S56-воркфлоу doc-writer/depth/linker запускаются как general-purpose с их дисциплиной в промпте (деф-кэш активен со след. сессии); деф-файлы = переиспользуемая адаптация на будущее.

## Структура docs/

```
docs/
├── README.md                   — вход + граф-навигатор по разделам (MOC)
├── 00-обзор/                   — что за бот, зачем; РЕЗУЛЬТАТ 50+ спринтов (что доказано/опровергнуто); статус
├── 01-как-работает-бот/        — поток end-to-end простыми словами (данные→сигнал→риск→исполнение→учёт)
├── 02-стратегии/               — каждая стратегия: EMA / mean-reversion / Donchian / volume / ATR breakout / Supertrend / Kronos ML — логика входа/выхода простыми словами + формулы + наша реализация
├── 03-индикаторы-и-расчёты/    — RSI/EMA/ATR/Bollinger + DSR/Sharpe/Sortino/MC/WFA-метрики: что считает, зачем, наша реализация
├── 04-риск-менеджмент/         — Kelly sizing, circuit breakers, HaltGate, kill-switch, override (ЯДРО — функция-за-функцией)
├── 05-исполнение-ордеров/      — FSM (16/30/76), OCO-bracket эмуляция, Bybit-адаптер, reconciler (ЯДРО — детально)
├── 06-бэктест-и-валидация/     — replay engine, WFA, DSR, MC permutations, acceptance gates T1-T6 (ЯДРО — детально)
├── 07-данные/                  — OHLCV ingest, bar-builder, gaps, источники Bybit
├── 08-дашборд/                 — UI: что показывает, как читать результаты
├── 09-глоссарий/               — термины для не-трейдера/не-программиста
├── 10-как-работает-кит/        — НАШ кит: 9 фаз, агенты (11+3), скиллы, хуки, память, SPRINT_STATE, когда что создаётся (образец — Wiki-SA «Как работает кит»); цель — найти пробелы в процессах
└── _навигация/                 — индекс + карта связей + (под)папка review/ для отчётов ревью
```
Каждая страница: `TL;DR` → `Простыми словами` → `Как это работает у нас (file:line)` → `Формулы/расчёты` (если есть) → `Примеры` → `Подводные камни` → `## Связанные документы` (+ ссылка вглубь llm-wiki).

## Фазы исполнения (Workflow)

- **WF-1 Scan/Inventory** — параллельные читатели картируют весь `src/` (16 подсистем, 102 файла) + кит (15 агентов / 6 скиллов / 8 хуков / 9 фаз) → структурный инвентарь по разделам docs/: список страниц + код-якоря (file) на каждую. Контроллер читает → финализирует точный список страниц.
- **WF scaffold** — создать дерево docs/ + скелеты страниц + README-MOC разделов (контроллер inline или мелкий WF).
- **WF-2 Fill→Verify→Link (pipeline)** — на каждую страницу: doc-writer (из кода) → depth-review (opus, против src/) [+ доменный ревьюер для страниц ядра] → fix → линковка. Денежное ядро — обязательный доменный проход.
- **WF финал** — глоссарий, корневой README-граф, сквозная вычитка (битые ссылки/сироты), читабельность для не-программиста.

## Acceptance (PHASE 5)

- Денежное ядро (стратегии/риск/исполнение/бэктест) прошло доменную проверку точности — 0 BLOCKER от depth/domain ревью.

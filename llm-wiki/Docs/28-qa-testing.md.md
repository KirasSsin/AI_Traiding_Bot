## 1. Анализ осуществимости стратегии

### 1.1 Математическое ожидание на сделку

```
Ожидаемая прибыль = (W × AvgWin) − (L × AvgLoss) − Commissions − Slippage

где:
  W = вероятность выигрыша
  L = вероятность проигрыша = 1 − W
  AvgWin = средний выигрыш (%)
  AvgLoss = средний проигрыш (%)
```

#### Пример расчёта

```
W = 0.55, AvgWin = 1.8%, AvgLoss = 1.2%
Commissions = 2 × 0.1% = 0.2% (вход + выход)
Slippage = 0.05%

Ожидаемая прибыль = (0.55 × 1.8) − (0.45 × 1.2) − 0.2 − 0.05
                  = 0.99 − 0.54 − 0.20 − 0.05
                  = 0.20% на сделку
```

**Критерий прохождения:** Ожидаемая прибыль ≥ 0.1% после всех издержек.

### 1.2 Безубыточный процент выигрышей

```
Безубыточность = (AvgLoss + Commissions + Slippage) / (AvgWin + AvgLoss) × 100

Для примера:
  = (1.2 + 0.2 + 0.05) / (1.8 + 1.2) × 100
  = 1.45 / 3.0 × 100
  = 48.33%
```

**Критерий:** Фактический WinRate должен превышать безубыточный минимум на 3+ процентных пункта.

### 1.3 Критерии прохождения

- [x] Математическое ожидание ≥ 0.1% после всех издержек
- [x] WinRate превышает безубыточность на 3+ п.п.
- [x] Slippage учитывается по 95-му перцентилю (не среднему)
- [x] Выборка ≥ 500 сделок для статистической значимости
- [x] Комиссии включают вывод, налоги, storage costs

## 2. Граничные случаи (Edge Cases)

### 2.1 Модуль загрузки данных

| # | Ситуация | Проблема | Решение |
|---|----------|----------|---------|
| 1 | Гэпы в данных | Биржа не возвращает данные за периоды | Интерполяция (1–5 баров) или флаг `incomplete` (>5 баров) |
| 2 | Нулевые значения | Volume = 0 на малоликвидных парах | Фильтрация, не допускать деления на ноль |
| 3 | Отрицательные значения | Ошибки переполнения или парсинга | Валидация всех входящих данных |
| 4 | Дубликаты записей | Повторные ответы биржи | Дедупликация по (exchange, pair, timestamp) |
| 5 | Некорректные timestamps | Бары не в хронологическом порядке | Сортировка + логирование аномалий |

### 2.2 Модуль расчёта индикаторов

| # | Ситуация | Проблема | Решение |
|---|----------|----------|---------|
| 1 | Период прогрева | Первые N−1 баров: значение невалидно | Возвращать `NaN`, блокировать сигналы до заполнения |
| 2 | NaN / Infinity | Расхождение MA, деление на малые числа | Проверка на конечность перед использованием |
| 3 | Переполнение буфера | Бесконечная работа → неограниченный рост | Ring buffer фиксированного размера |
| 4 | Единичные выбросы | Flash crash искажает индикатор | Winsorize на 1%/99% перцентилях |

### 2.3 Модуль генерации сигналов

| # | Ситуация | Проблема | Решение |
|---|----------|----------|---------|
| 1 | Противоречивые сигналы | EMA → LONG, RSI → SHORT | При конфликте — FLAT (воздержание) |
| 2 | Нулевые сигналы | Нет сигналов длительное время | Лог предупреждений при >24ч без сигналов |
| 3 | Лавина сигналов | High vol → переторговка | Лимит: максимум N сделок в час |
| 4 | Сигнал при недостаточных данных | Индикаторы не вышли из прогрева | Блокировка обязательна |

### 2.4 Модуль исполнения ордеров

| # | Ситуация | Проблема | Решение |
|---|----------|----------|---------|
| 1 | Отклонённые ордера | Недостаточный баланс, лимиты, сбой | Обработка по типу ошибки: уменьшение объёма / ожидание / retry |
| 2 | Частичное исполнение | Ордер исполнен на 60% | Отслеживание остатка, решение: ждать / отменить / новый ордер |
| 3 | Таймауты ордеров | Ордер висит дольше лимита | Автоматическая отмена + логирование |
| 4 | Slippage > ожидаемого | Цена ушла от заявленной | Slippage cap: не исполнять если slippage > threshold |

## 3. Anti-Patterns (запрещённые паттерны)

### 3.1 Look-Ahead Bias

```
ЗАПРЕЩЕНО:
  - Использовать данные из будущего бара для текущего решения
  - StandardScaler на всём датасете (использует будущие данные для нормализации)
  - Индикаторы, которые смотрят вперёд (DPO с look-ahead)

РАЗРЕШЕНО:
  - Только данные до текущего бара включительно
  - Rolling window / expanding window для Z-score
  - Purged K-Fold с embargo для валидации
```

### 3.2 Data Snooping

```
ЗАПРЕЩЕНО:
  - Перебор 1000 параметров и выбор лучшего на одном датасете
  - Множественное тестирование без коррекции (Bonferroni, Deflated Sharpe)
  - Использование тестового набора для выбора модели

РАЗРЕШЕНО:
  - Walk-Forward Analysis (обучение на прошлом, тест на будущем)
  - Один набор параметров на все фолды
  - Sensitivity analysis: ±20% от параметра → Sharpe не падает >50%
```

### 3.3 Overfitting

```
ЗАПРЕЩЕНО:
  - Стратегия с 50+ параметрами
  - In-sample Sharpe >> Out-of-sample Sharpe (разница > 50%)
  - Использование «идеальных» параметров из бэктеста

РАЗРЕШЕНО:
  - Максимум 5–7 свободных параметров
  - OOS Sharpe ≥ 50% от IS Sharpe
  - Sensitivity analysis на каждом параметре
```

## 4. Тестирование

### 4.1 Unit Tests

```
Каждый индикатор: тест на корректность формулы
  - EMA: сравнить с эталоном (TradingView / TA-Lib)
  - RSI: edge cases (все растут → RSI=100, все падают → RSI=0)
  - ATR: True Range при gap > обычного диапазона

Каждый модуль: тест на edge cases из §2
  - Data Collector: gap detection, zero volume, duplicates
  - Signal Generator: conflicting signals, warmup period
  - Risk Manager: Kelly ≤ 0, MaxDD trigger, flash crash
  - Order Executor: rejected orders, partial fills, timeouts
```

### 4.2 Integration Tests

```
Полный цикл: tick → indicators → signal → risk check → order → fill → P&L
  - На исторических данных (replay)
  - С симулированными edge cases (flash crash, gap, API error)
  - Проверка: P&L в бэктесте совпадает с ручным расчётом
```

### 4.3 Backtest Validation

```
Walk-Forward Analysis:
  - train_ratio = 0.8
  - K ≥ 5 фолдов
  - Embargo = 2 × holding_period
  - OOS Sharpe ≥ 1.0 (годовой)

Monte Carlo Permutation:
  - M = 10,000 перестановок
  - p-value < 0.05 для подтверждения значимости

Deflated Sharpe Ratio:
  - Скорректировать на количество протестированных стратегий
  - DSR > 0 после коррекции
```

### 4.4 Performance Tests

```
Бенчмарк-цели:
  - WebSocket parse: < 5µs на сообщение
  - Indicator update (O(1)): < 20ns
  - XGBoost inference: < 1ms на бар
  - Полный цикл (tick → decision): < 2ms
  - QuestDB batch write: < 500µs за 100 тиков
```

## 5. Формулы проверки

### Sharpe Ratio (проверка)

```
Sharpe = (Mean_Return - R_f) / Std_Return

Для крипты: R_f = 0 (или USDT lending rate ≈ 3–8%)
Годовой: Sharpe_annual = Sharpe_daily × √365

Порог: ≥ 1.0 (годовой)
Подозрительно: > 4.0 (проверить на overfitting)
```

### Sortino Ratio (проверка)

```
Sortino = (Mean_Return - MAR) / Downside_Deviation
Downside_Deviation = √(1/n × Σ min(R_i - MAR, 0)²)

Порог: ≥ 1.5
```

### Max Drawdown (проверка)

```
MaxDD = max((Peak - Trough) / Peak) за весь период

Порог: < 25% для Half-Kelly стратегии
```

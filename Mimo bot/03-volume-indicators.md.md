## Часть I: Полный каталог объёмных индикаторов

### 1. OBV (On-Balance Volume)

#### Формула

```
OBV(t) = OBV(t-1) + V(t),    если Close(t) > Close(t-1)
OBV(t) = OBV(t-1) - V(t),    если Close(t) < Close(t-1)
OBV(t) = OBV(t-1),            если Close(t) = Close(t-1)
```

- **Начальное значение:** произвольно (0 или Volume первого бара)
- **Период:** кумулятивный (бесконечный)
- **Диапазон:** неограничен, не нормализован
- **Магические числа:** нет (вся магия в визуальном анализе тренда)

#### Математические свойства

OBV — монотонная кумулятивная сумма. Абсолютное значение бесполезно — важен **тренд** и **дивергенция**. Каждый бар классифицируется целиком: бычий или медвежий, на основе Close vs Close(t-1). Это **грубое** упрощение: внутри бара может быть 70% продаж, но если Close > prev Close — весь объём считается бычьим.

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Volume = 0 | OBV не меняется | Корректно, логировать |
| Flash crash wick (длинная тень) | OBV резко падает/растёт, хотя цена вернулась | Winsorize: если \|delta\| > 3σ от средней за 20 баров → обрезать до 3σ |
| Gap (API-сбой, пропущенный бар) | OBV пропускает бар | Логировать gap, интерполяция не нужен |
| Wash trading (намыв) | OBV искажается нереальным объёме | Фильтр: если Volume > 5× средней за 20 баров → медиана-фильтр |
| Не нормализован | Нельзя сравнивать BTC vs SOL | Z-score нормализация для портфельных стратегий |

#### Решение: ✅ ВКЛЮЧЕН (MVP v0.1)

**Роль:** Дивергенция OBV vs цена → ранний сигнал разворота. Простейший и надёжнейший объёмный индикатор.

### 2. VWAP (Volume-Weighted Average Price)

#### Формула

```
Typical Price (TP) = (High + Low + Close) / 3
VWAP = Σ(TP_i × Volume_i) / Σ(Volume_i)
```

Суммирование внутри «сессии». На крипте 24/7 — обычно сброс в 00:00 UTC.

Онлайн-реализация:

```python
cum_vp = 0.0
cum_vol = 0.0
for bar in session:
    tp = (bar.high + bar.low + bar.close) / 3.0
    cum_vp += tp * bar.volume
    cum_vol += bar.volume
    if cum_vol > 0:
        VWAP = cum_vp / cum_vol
    else:
        VWAP = tp  # fallback при нулевом объёме
```

#### Магические числа

| Параметр | Значение | Обоснование |
|---|---|---|
| Сброс сессии | 00:00 UTC | Стандарт для крипты (нет естественных сессий) |
| Price source | Typical Price (H+L+C)/3 | Стандарт, лучше Close |
| Отклонения VWAP (bands) | 1σ, 2σ | Статистический аналог Bollinger Bands |

#### VWAP Bands (расширение)

```
Variance = Σ(Volume_i × (TP_i - VWAP)²) / Σ(Volume_i)
σ = √Variance
Upper Band = VWAP + k × σ    (k = 1, 2)
Lower Band = VWAP - k × σ
```

#### Crypto-specific: VWAP на 24/7 рынке

**Проблема:** Классический VWAP привязан к торговой сессии (open → close). На крипте 24/7 нет естественных границ.

**Решения:**

| Подход | Сброс | Плюсы | Минусы |
|---|---|---|---|
| **Дневной VWAP** | 00:00 UTC | Стандарт, институциональные алгоритмы привязаны | Игнорирует overnight накопление |
| **Rolling VWAP** | Окно N периодов | Нет произвольного сброса | Не «якорная» цена дня |
| **Anchored VWAP (AVWAP)** | Ручной якорь | Привязка к значимому событию | Требует выбора якорной точки |
| **Weekly VWAP** | Понедельник 00:00 UTC | Подходит для swing | Грубый для скальпинга |

**Рекомендация:** Использовать **дневной VWAP** (00:00 UTC) как primary + **Rolling VWAP(20)** как дополнительный фильтр. AVWAP — отложен до v0.3.

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Нулевой объём в начале сессии | VWAP = NaN (0/0) | VWAP = Typical Price первого тика |
| Cum_vol = 0 (сбой данных) | VWAP = undefined | Восстановление из бэкапа, VWAP = TP |
| Китовый тик ($10M сделка) | VWAP сдвигается к цене кита | VWAP на крипте менее «честен», чем на акциях — использовать VWAP bands |
| Flash crash внутри дня | VWAP искажается | VWAP bands: если цена за 2σ → игнорировать VWAP как support/resistance |

#### Решение: ✅ ВКЛЮЧЕН (v0.2)

**Роль:** «Справедливая цена» дня. Институциональные алгоритмы (VWAP execution) привязаны к этому уровню. Цена ниже VWAP = «дёшево», выше = «дорого». Мощный уровень поддержки/сопротивления.

### 3. AVWAP (Anchored VWAP)

#### Формула

Та же формула, что VWAP, но суммирование начинается не с начала сессии, а с **якорной точки** (anchoring point):

```
AVWAP(anchor) = Σ(TP_i × Volume_i) / Σ(Volume_i),    для i = anchor..t
```

Якорная точка — экстремум (high/low), IPO, листинг, значимое событие.

#### Магические числа

Нет фиксированных — якорная точка определяется вручную или алгоритмически.

**Автоматическое якорение** (для бота):
- Локальный high/low за 30 дней
- Перелом тренда (EMA crossover)
- Significant volume spike (> 3σ от средней)

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Якорная точка не выбрана | AVWAP не определён | Fallback: дневной VWAP |
| Якорная точка в «тихом» периоде | AVWAP неинформативен | Требует фильтрации: якорь должен быть на высоком объёме |
| Долгий период накопления | AVWAP сходится к средней | Автоматически пересчитывать якорь каждые 30 дней |

#### Решение: ⏳ ОТЛОЖЕН до v0.3

**Причина:** Требует ручного или полуавтоматического выбора якорной точки. Для MVP — дневного VWAP достаточно.

### 4. MFI (Money Flow Index)

#### Формула

```
TP(t) = (High(t) + Low(t) + Close(t)) / 3
MF(t) = TP(t) × Volume(t)

Positive MF = Σ MF(i) для всех i, где TP(i) > TP(i-1), в окне N
Negative MF = Σ MF(i) для всех i, где TP(i) < TP(i-1), в окне N

MFR = Positive MF / Negative MF
MFI = 100 - 100 / (1 + MFR)
```

**Период:** 14 (стандарт)
**Диапазон:** [0, 100]

#### Магические числа

| Параметр | Значение | Обоснование |
|---|---|---|
| Период | 14 | Стандарт Уайлдера (аналогично RSI) |
| Перекупленность | > 80 | Стандарт (vs RSI > 70 — MFI более «жёсткий») |
| Перепроданность | < 20 | Стандарт |
| Равновесие | ~50 | Нейтральная зона |

#### Математические свойства

MFI — **взвешенный по объёму RSI**. Каждое изменение Typical Price умножается на объём, что делает MFI более информативным: движение цены на высоком объёме весит больше.

**Ключевое отличие от RSI:** MFI > 80 означает не просто «перекупленность», а «перекупленность **с объёмным подтверждением**». Это более надёжный сигнал.

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Volume = 0 | MF = 0, бар не учитывается | Корректно |
| High = Low (doji) | TP = High = Low = Close, MF = TP × Vol | Корректно (нет деления на ноль в MFI) |
| Все TP растут (N периодов) | Negative MF = 0 → MFR = ∞ → MFI = 100 | Корректно (максимальная перекупленность) |
| Все TP падают | Positive MF = 0 → MFR = 0 → MFI = 0 | Корректно (максимальная перепроданность) |
| Flash crash с моментальным возвратом | TP резко меняется, MF даёт ложный сигнал | Winsorize MF при spike > 3σ |
| Суточная сезонность | На 1H период 14 = 14 часов ~ 0.6 дня | Рассмотреть период 10 для более быстрых стратегий |

#### Решение: ✅ ВКЛЮЧЕН (v0.2)

**Роль:** Объёмный RSI — подтверждение перекупленности/перепроданности с объёмом. Чёткие пороговые зоны (0-100).

### 5. CVD (Cumulative Volume Delta)

#### Формула

```
CVD(t) = CVD(t-1) + BuyVolume(t) - SellVolume(t)
```

Классификация через **tick rule** (упрощённый Lee-Ready):

```
Если trade_price > prev_trade_price:
    BuyVolume += trade_volume
Elif trade_price < prev_trade_price:
    SellVolume += trade_volume
Else:  # trade_price == prev_trade_price
    Наследуем направление предыдущего тика
```

#### Магические числа

| Параметр | Значение | Обоснование |
|---|---|---|
| Tick rule | Last tick direction | Lee-Ready без L2 данных |
| Outlier threshold | 3σ от средней за 20 баров | Winsorize spike |

#### Математические свойства

CVD — кумулятивная разница агрессивных покупок и продаж. В отличие от OBV (весь объём бара — одно направление), CVD классифицирует **каждую сделку** через tick rule.

**CVD + цена растут** = здоровый тренд (покупатели агрессивны).
**CVD падает + цена растёт** = дивергенция → умные деньги выходят.

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Один крупный тик (кит) | CVD скачок | Winsorize до 3σ |
| Tick rule неточность | Неправильная классификация без L2 | Для v0.5: Lee-Ready с bid-ask |
| Volume = 0 | CVD не меняется | Корректно |
| Кумулятивный дрейф | CVD уходит в миллионы | Нормализация: CVD / cumulative_volume |
| Сброс между сессиями | Стандартно — не сбрасывать | Хранить дневную версию для сравнения |

#### Решение: ✅ ВКЛЮЧЕН (v0.3)

**Роль:** «Order flow lite» — давление покупателей vs продавцов без L2 данных. Подтверждение тренда.

### 6. Volume Profile

#### Формула

```
Для каждого ценового уровня P (с шагом bin_size):
  Volume_at_P = Σ Volume_i для всех баров i,
                чей диапазон [Low_i, High_i] включает P

POC = P, где Volume_at_P максимальна
VAH = верхняя граница зоны, содержащей 70% объёма
VAL = нижняя граница зоны, содержащей 70% объёма
```

#### Магические числа

| Параметр | Значение | Обоснование |
|---|---|---|
| Bin size | 0.1–0.5% от текущей цены | Адаптивный, не фиксированный |
| Value Area | 70% объёма | Стандарт (1σ нормального распределения) |
| POC | Максимум гистограммы | Уровень максимального объёма = «магнит» |
| Период профиля | День / Неделя / 30 дней | По стратегии |

#### Volume-at-Price (VAP) — упрощённая версия

```
Price_level = Round(TP / bin_size) * bin_size
VAP[Price_level] += Volume
```

VAP присваивает **весь** объём бара одному уровню (TP), а не распределяет пропорционально по High-Low. Разница в точности POC: ~5–15%.

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Длинные тени (wicks) | VAP неточен (весь объём на Close) | Использовать Volume Profile (пропорциональное распределение) |
| Multi-modal distribution | Несколько POC | Брать ближайший POC к текущей цене |
| 24/7 без сессий | Нет естественных границ | Задавать период вручную (1D, 7D, 30D) |
| Оффлайн пересчёт | Требует хранения всех сделок | Streaming VAP для онлайн; полный Volume Profile для бэктеста |

#### Решение: ✅ ВКЛЮЧЕН (v0.3)

**Роль:** POC — магнит для цены. Value Area — зона справедливой стоимости. Выход за Value Area → импульс. VAP для Dashboard, полный Volume Profile для сигналов.

### 7. A/D Line (Accumulation/Distribution Line)

#### Формула

```
CLV = ((Close - Low) - (High - Close)) / (High - Low)
A/D(t) = A/D(t-1) + CLV(t) × Volume(t)
```

CLV ∈ [-1, +1]:
- CLV = +1: Close = High (максимальная аккумуляция)
- CLV = -1: Close = Low (максимальная дистрибуция)
- CLV = 0: Close = середина диапазона

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| **High = Low (doji)** | CLV = 0/0 = undefined | CLV = 0 (нейтрально) или пропуск бара |
| Длинная тень вниз, Close = High | CLV = +1 (весь объём — аккумуляция) | Может быть неверно (wick = распродажа) |

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. Менее интуитивен, чем OBV
2. Неустойчивость при High = Low (деление на ноль)
3. Дублирование функционала: OBV даёт дивергенцию, MFI даёт объёмный RSI
4. A/D Line — промежуточный инструмент без уникального преимущества

### 8. Chaikin Money Flow (CMF)

#### Формула

```
AD = Σ(CLV_i × Volume_i) для i = t-N+1..t
CMF = AD / Σ(Volume_i) для i = t-N+1..t
```

где CLV = ((Close - Low) - (High - Close)) / (High - Low)

**Период:** 20
**Диапазон:** [-1, +1]

#### Магические числа

| Параметр | Значение | Обоснование |
|---|---|---|
| Период | 20 | Стандарт (≈1 торговый день на 1H) |
| Нет порогов | — | Нет устоявшихся зон перекупленности/перепроданности |

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. Дублирует MFI (оба измеряют объёмное давление)
2. MFI имеет стандартные пороги (20/80), CMF — нет
3. Зависит от CLV — неустойчивость при High = Low
4. Нет статистического преимущества перед MFI в бэктестах

### 9. Force Index (Elder's)

#### Формула

```
Raw Force Index(t) = Volume(t) × (Close(t) - Close(t-1))
Force Index(13) = EMA(Raw_Force_Index, 13)     # сглаженная версия
Force Index(2) = EMA(Raw_Force_Index, 2)        # короткосрочная
```

#### Магические числа

| Параметр | Значение | Обоснование |
|---|---|---|
| EMA период (длинный) | 13 | Стандарт Элдера |
| EMA период (короткий) | 2 | Стандарт Элдера |
| Порог | нет | Не нормализован |

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Volume = 0 | FI = 0 | Неинформативно |
| Flash crash | FI = -огромное значение | Без outlier filter — ложный сигнал |
| EMA(13) сглаживание | Теряет моментальные импульсы | Теряется главное преимущество FI |

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. Слишком шумный на крипте (wicks 2-3% + неравномерный объём)
2. Нет нормализации и порогов
3. Дублируется CVD (давление покупателей/продавцов) + MFI (объёмный моментум)

### 10. Elder's Force Index (EFI) — продвинутая версия

> **Отличие от обычного Force Index:** EFI использует нормализацию и более сложную логику сигналов. В некоторых источниках «EFI» и «Force Index» используются как синонимы, но EFI включает дополнительные правила интерпретации.

#### Формула

```
EFI_raw(t) = Volume(t) × (Close(t) - Close(t-1))
EFI_smoothed(t) = EMA(EFI_raw, 13)

# Сигналы (Элдер):
# 1. EFI > 0 и растёт → бычий моментум
# 2. EFI < 0 и падает → медвежий моментум
# 3. Дивергенция EFI vs цена → разворот
# 4. EFI пересекает ноль → смена тренда
```

#### Решение: ❌ ОТКЛОНЕНО (вместе с Force Index)

**Причина:** Та же проблема — шумность. EFI лучше организован (правила Элдера), но формула та же. CVD + OBV покрывают всё, что делает EFI, но надёжнее.

### 11. Volume Oscillator (VO)

#### Формула

```
Short MA = SMA(Volume, short_period)    # обычно 5
Long MA = SMA(Volume, long_period)      # обычно 10

VO = ((Short MA - Long MA) / Long MA) × 100
```

#### Магические числа

| Параметр | Значение | Обоснование |
|---|---|---|
| Short period | 5 | Стандарт |
| Long period | 10 | Стандарт |
| Пороги | нет | Нет устоявшихся зон |

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. Нет пороговых зон (может быть +200% или -80%)
2. Не учитывает направление цены (не различает объём на росте vs падении)
3. Дублируется VROC
4. Слишком общий, не даёт конкретных сигналов для алгоритма

### 12. VROC (Volume Rate of Change)

#### Формула

```
VROC = ((Volume(t) - Volume(t-N)) / Volume(t-N)) × 100
```

**Период:** 14 или 25

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Volume(t-N) = 0 | Деление на ноль | VROC = NaN, fallback = 0 |
| Суточная сезонность | VROC захватывает сезонность как «сигнал» | Фильтрация или нормализация |

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. Не даёт направления (не различает объём на росте vs падении)
2. Нет порогов
3. Суточная сезонность объёма создаёт ложные сигналы
4. На крипте объём меняется в 5-10 раз от часа к часу → VROC постоянно в экстремумах

### 13. NVI (Negative Volume Index)

#### Формула

```
NVI(0) = 1000

Если Volume(t) < Volume(t-1):
    NVI(t) = NVI(t-1) × (1 + ΔClose / Close(t-1))
Иначе:
    NVI(t) = NVI(t-1)
```

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. Слишком мало сигналов на крипте (NVI меняется только при падении объёма)
2. Теория «умных денег на низком объёме» разработана для фондового рынка (Norman Fosback, 1976) — не проверена на крипте
3. Нет порогов
4. На 1H таймфрейме даёт сигнал раз в несколько дней — недостаточно для статистической значимости

---

### 14. PVI (Positive Volume Index)

#### Формула

```
PVI(0) = 1000

Если Volume(t) > Volume(t-1):
    PVI(t) = PVI(t-1) × (1 + ΔClose / Close(t-1))
Иначе:
    PVI(t) = PVI(t-1)
```

#### Решение: ❌ ОТКЛОНЕНО

**Причины:** Те же, что для NVI. PVI — зеркальная версия. Комбинация NVI+PVI интересна концептуально, но слишком редка для бота.

### 15. Volume-Weighted MACD (VW-MACD)

#### Формула

```
VW-EMA_fast = VW-EMA(Volume × Close, 12) / VW-EMA(Volume, 12)
VW-EMA_slow = VW-EMA(Volume × Close, 26) / VW-EMA(Volume, 26)
VW-MACD = VW-EMA_fast - VW-EMA_slow
Signal = EMA(VW-MACD, 9)
```

где VW-EMA — EMA с весами, умноженными на объём бара.

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Volume = 0 | VW-EMA = 0/0 | VW-EMA = обычная EMA при нулевом объёме |
| Неравномерный объём | VW-EMA «застревает» на high-volume барах | Может быть фичей (фильтр шума) |

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. MACD уже в наборе (обычный MACD(12, 26, 9))
2. MFI уже покрывает «объёмный моментум»
3. Сложность реализации VW-EMA без доказанного выигрыша
4. Нет статистического преимущества в бэктестах

---

### 16. Market Profile (TPO — Time Price Opportunity)

#### Формула

```
Для каждого 30-минутного периода (TPO-период):
  Каждому ценовому уровню, через который прошла цена,
  присваивается буква (A, B, C, ...)

TPO Count на уровне P = количество букв (периодов) на уровне P
```

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. Требует внутридневных данных (30-минутные периоды)
2. Крипта 24/7 — «Initial Balance» не определена
3. Volume Profile даёт ту же информацию, но на основе объёма (более надёжно)
4. TPO — инструмент визуализации, не автоматических сигналов

---

### 17. TWAP (Time-Weighted Average Price)

#### Формула

```
TWAP = Σ Price_i / N
```

TWAP — **простое среднее** цен за период. В отличие от VWAP, не учитывает объём — каждый бар имеет одинаковый вес.

Вариант для исполнения:

```
TWAP_execution: разбить большой ордер на N равных частей,
исполнять каждую часть через равные интервалы времени.
```

#### Магические числа

| Параметр | Значение | Обоснование |
|---|---|---|
| Количество слайсов | 10-60 | Зависит от размера ордера и ликвидности |
| Price source | Close или Mid-price | Close проще |

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| Аномальная цена (спайк) | TWAP искажается (вес каждого бара одинаков) | VWAP надёжнее (весит по объёму) |
| Нулевой объём в баре | Цена неактуальна, но TWAP учитывает | VWAP не учитывает нулевой объём |

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. TWAP — инструмент **исполнения** ордеров, а не аналитический индикатор
2. Для анализа VWAP строго лучше (учитывает объём)
3. На крипте с неравномерным объёмом TWAP менее «честен», чем VWAP
4. Единственное применение: алгоритмическое разбиение крупных ордеров (v0.5, микроструктура)

**Единственное применение в системе:** Algo-execution (разбиение ордеров) — отложено до v0.5.

---

### 18. Klinger Oscillator

#### Формула

```
# Шаг 1: Force Volume (KV Force)
DM = High - Low  (диапазон бара)
Trend = +1 если (H+L+C) > (H(t-1)+L(t-1)+C(t-1)), иначе -1
VF (Volume Force) = Volume × |DM/AVG_DM_34 - 1| × Trend × 100

# Шаг 2: Klinger Oscillator
KO = EMA(VF, 34) - EMA(VF, 55)

# Шаг 3: Сигнальная линия
Signal = EMA(KO, 13)
```

где AVG_DM_34 = SMA(|DM|, 34)

#### Магические числа

| Параметр | Значение | Обоснование |
|---|---|---|
| Быстрая EMA | 34 | Стандарт Клингера |
| Медленная EMA | 55 | Стандарт Клингера |
| Сигнальная EMA | 13 | Стандарт Клингера |
| DM average period | 34 | Та же, что быстрая EMA |

#### Сигналы

1. KO пересекает сигнальную линию снизу вверх → бычий сигнал
2. KO пересекает сигнальную линию сверху вниз → медвежий сигнал
3. Дивергенция KO vs цена → разворот

#### Edge Cases

| Ситуация | Поведение | Решение |
|---|---|---|
| DM = 0 (doji) | VF = Volume × \|0/AVG - 1\| × Trend × 100 | Ложный сигнал на doji-барах |
| Нулевой объём | VF = 0, KO сглаживается | Корректно |
| Слишком много параметров | 3 EMA периода — настройка сложна | Стандартные значения Клингера |

#### Решение: ❌ ОТКЛОНЕНО

**Причины:**
1. Слишком много параметров (3 EMA периода + DM average)
2. Сложная формула — труднее интерпретировать и отлаживать
3. Дублирует CVD (давление) + MFI (объёмный моментум)
4. Сигнальная линия добавляет лаг
5. Не популярен в крипто-сообществе → меньше ресурсов для поддержки
6. Формула Force Volume = Volume × \|DM/AVG_DM - 1\| × Trend — нестандартная, менее проверенная

### 19. Дополнительные индикаторы (рассмотрены кратко)

| Индикатор | Формула (ядро) | Решение | Причина |
|---|---|---|---|
| **Relative Volume (RVOL)** | RVOL = Volume / SMA(Volume, 20) | ❌ | Производный от Volume Oscillator, нет направления |
| **Up/Down Volume Ratio** | Up_Vol / Down_Vol за период | ❌ | Дублирует CVD |
| **Ease of Movement (EOM)** | EOM = ((H+L)/2 - (H+L)/2_prev) / (V/(H-L)) | ❌ | Нестабилен при малых H-L (doji), сложная интерпретация |
| **Volume Weighted RSI** | RSI с весами объёма | ❌ | MFI уже делает это |
| **Price Volume Trend (PVT)** | PVT(t) = PVT(t-1) + ((C-C_prev)/C_prev) × V | ❌ | Похож на OBV, но сложнее — без преимущества |
| **Intraday Intensity (II)** | (2×C - H - L) / (H - L) × V | ❌ | CLV-зависимость — деление на ноль при H=L |
| **Money Flow Multiplier** | ((C-L) - (H-C)) / (H-L) | ❌ | Это CLV — та же неустойчивость |
| **Trade Volume Index (TVI)** | Кумулятивный, с порогом изменения цены | ❌ | Слишком специфичен, мало документирован |

## Часть III: ТОП-3 индикатора для крипторынка

### 🥇 1. CVD (Cumulative Volume Delta)

**Почему #1:**

CVD — **единственный** объёмный индикатор, который показывает **агрессивное давление покупателей vs продавцов** на уровне отдельных сделок. Это ближе всего к order flow без L2 данных.

**Уникальное преимущество:**
- Показывает **накопление** — не просто «что происходит сейчас», а «что происходило последние N баров»
- Дивергенция CVD vs цена — самый надёжный сигнал разворота из всех объёмных индикаторов
- На крипте с китами и маркет-мейкерами: CVD видит их активность (крупные агрессивные ордера)

**Почему не OBV:** OBV считает весь объём бара одним направлением. CVD классифицирует каждую сделку. На крипте с высокой внутрибарной волатильностью разница критична.

**Rust-реализация:**
```rust
struct CVD {
    value: f64,
    prev_price: f64,
    prev_direction: i8,  // +1 buy, -1 sell, 0 unknown
}

impl CVD {
    fn update(&mut self, trade_price: f64, trade_volume: f64) {
        let direction = if trade_price > self.prev_price {
            1
        } else if trade_price < self.prev_price {
            -1
        } else {
            self.prev_direction  // tick rule: наследуем
        };

        self.value += direction as f64 * trade_volume;
        self.prev_price = trade_price;
        self.prev_direction = direction;
    }
}
```

**Конфликты:**
- CVD растёт + OBV падает → внутрибарный дисбаланс: закрытие было ниже, но покупки внутри бара доминировали. **CVD более точен.**
- CVD растёт + MFI > 80 → противоречие: давление покупателей есть, но перекупленность. **Фильтровать: не входить при MFI > 80, даже если CVD бычий.**

---

### 🥈 2. VWAP

**Почему #2:**

VWAP — **единственный** индикатор, который определяет «справедливую цену» сессии. На крипте 24/7 — это якорная точка, к которой привязаны институциональные алгоритмы.

**Уникальное преимущество:**
- Институциональные алгоритмы (VWAP execution) **всегда** привязаны к VWAP. Цена ниже VWAP = они покупают, выше = продают.
- VWAP acts as support/resistance **сам по себе** (в отличие от произвольных уровней)
- VWAP bands (1σ, 2σ) дают статистически обоснованный канал

**Почему не MFI:** MFI — осциллятор (перекупленность/перепроданность). VWAP — уровень (support/resistance). Они дополняют друг друга, не заменяют.

**Crypto-specific на 24/7 рынке:**

| Аспект | Решение |
|---|---|
| Нет сессий | Сброс VWAP в 00:00 UTC (стандарт де-факто) |
| Институциональные алгоритмы | Привязаны к 00:00 UTC VWAP — это «де-факто сессия» |
| Ночные часы (низкий объём) | VWAP становится нестабилен → использовать VWAP bands |
| Китовые сделки | VWAP сдвигается → VWAP bands показывают степень искажения |

**Rust-реализация:**
```rust
struct VWAP {
    cum_vp: f64,   // Σ(TP × Vol)
    cum_vol: f64,   // Σ(Vol)
    session_start: Timestamp,
}

impl VWAP {
    fn new(session_start: Timestamp) -> Self {
        Self { cum_vp: 0.0, cum_vol: 0.0, session_start }
    }

    fn update(&mut self, bar: &OHLCV) {
        let tp = (bar.high + bar.low + bar.close) / 3.0;
        self.cum_vp += tp * bar.volume;
        self.cum_vol += bar.volume;
    }

    fn value(&self) -> Option<f64> {
        if self.cum_vol > 0.0 {
            Some(self.cum_vp / self.cum_vol)
        } else {
            None  // NaN — нет объёма
        }
    }

    fn reset(&mut self, new_session: Timestamp) {
        self.cum_vp = 0.0;
        self.cum_vol = 0.0;
        self.session_start = new_session;
    }
}
```

**Конфликты:**
- Цена > VWAP + MFI > 80 → **сильный сигнал перекупленности.** Цена «дорого» относительно дня И объёмный RSI перегрет.
- Цена < VWAP + CVD растёт → **накопление под VWAP.** Институциональные алгоритмы покупают «дёшево». Сильный бычий сигнал.

### 🥉 3. MFI (Money Flow Index)

**Почему #3:**

MFI — **единственный** нормализованный объёмный осциллятор с чёткими пороговыми зонами (0-100). В отличие от OBV и CVD (не нормализованы), MFI можно сравнивать между активами и таймфреймами.

**Уникальное преимущество:**
- Чёткие пороги: MFI > 80 = перекупленность с объёмным подтверждением
- Нормализован в 0-100 — сравним между BTC, ETH, SOL
- Объёмный RSI — каждое ценовое изменение весит по объёму

**Почему не OBV:** OBV не нормализован и не имеет порогов. MFI даёт конкретные зоны для автоматической торговли.

**Rust-реализация:**
```rust
struct MFI {
    period: usize,
    pos_mf: Vec<f64>,  // Positive Money Flow окно
    neg_mf: Vec<f64>,  // Negative Money Flow окно
    prev_tp: Option<f64>,
}

impl MFI {
    fn new(period: usize) -> Self {
        Self {
            period,
            pos_mf: Vec::with_capacity(period),
            neg_mf: Vec::with_capacity(period),
            prev_tp: None,
        }
    }

    fn update(&mut self, bar: &OHLCV) -> Option<f64> {
        let tp = (bar.high + bar.low + bar.close) / 3.0;
        let mf = tp * bar.volume;

        if let Some(prev) = self.prev_tp {
            if tp > prev {
                self.pos_mf.push(mf);
                self.neg_mf.push(0.0);
            } else if tp < prev {
                self.pos_mf.push(0.0);
                self.neg_mf.push(mf);
            } else {
                self.pos_mf.push(0.0);
                self.neg_mf.push(0.0);
            }

            // Скольжение окна
            if self.pos_mf.len() > self.period {
                self.pos_mf.remove(0);
                self.neg_mf.remove(0);
            }

            if self.pos_mf.len() == self.period {
                let pos_sum: f64 = self.pos_mf.iter().sum();
                let neg_sum: f64 = self.neg_mf.iter().sum();

                let mfi = if neg_sum == 0.0 {
                    100.0
                } else if pos_sum == 0.0 {
                    0.0
                } else {
                    let mfr = pos_sum / neg_sum;
                    100.0 - 100.0 / (1.0 + mfr)
                };
                self.prev_tp = Some(tp);
                return Some(mfi);
            }
        }
        self.prev_tp = Some(tp);
        None  // Недостаточно данных
    }
}
```

**Конфликты:**
- MFI > 80 + OBV дивергенция (OBV не делает high) → **мощнейший сигнал разворота.** Перекупленность + умные деньги выходят.
- MFI < 20 + CVD растёт → **накопление на перепроданности.** Покупатели активны, но цена ещё не отреагировала.


## Часть VI: Rust Optimization Notes

### Общие принципы

1. **Использовать `f64`** — не `f32`. На крипте с ценами 50,000+ и объёмами в миллионах, `f32` теряет точность.
2. **Ring buffers** для оконных индикаторов (MFI, VWAP bands) — избегать `Vec::remove(0)` (O(n) на каждом шаге).
3. **Кумулятивные суммы** (OBV, CVD, VWAP) — `O(1)` на каждый бар, не нужен буфер.
4. **Avoid allocation в hot path** — все структуры индикаторов должны быть на стеке или с pre-allocated capacity.
5. **SIMD** для Batch-расчётов (например, VWAP bands variance: `Σ(Vol × (TP - VWAP)²)` — dot product, vectorizable).

### Структуры данных

```rust
// Ring buffer для оконных индикаторов
struct RingBuffer<const N: usize> {
    data: [f64; N],
    head: usize,
    len: usize,
}

impl<const N: usize> RingBuffer<N> {
    fn push(&mut self, val: f64) {
        self.data[self.head] = val;
        self.head = (self.head + 1) % N;
        if self.len < N { self.len += 1; }
    }
    fn sum(&self) -> f64 { self.data[..self.len].iter().sum() }
    fn mean(&self) -> f64 { self.sum() / self.len as f64 }
}
```

### Модульная архитектура

```rust
trait Indicator {
    fn name(&self) -> &'static str;
    fn update(&mut self, bar: &OHLCV) -> Option<f64>;
    fn value(&self) -> Option<f64>;
    fn is_ready(&self) -> bool;
}

// Реализации:
struct OBV { value: f64, prev_close: f64 }
struct VWAP { cum_vp: f64, cum_vol: f64 }
struct MFI { pos_mf: RingBuffer<14>, neg_mf: RingBuffer<14>, prev_tp: f64 }
struct CVD { value: f64, prev_price: f64, prev_dir: i8 }
```

```yaml
    value_area_pct: 70.0
    period_days: 1          # дневной профиль
```

## Часть VII: Сигнальная логика (интеграция)

### Подтверждение входа в LONG

```
LONG = EMA20 > EMA50
   AND ADX > 25
   AND Цена > Supertrend
   AND OBV_тренд_вверх  (OBV > EMA(OBV, 20))
   AND MFI < 80          (не перекуплен)
   AND CVD_растёт        (CVD > EMA(CVD, 10) на 3 последних бара)
   AND Цена > VWAP       (цена «дёшево» для институционалов)
```

### Фильтр перегретости

```
Если MFI > 80 И Цена > VWAP + 2σ:
    → Предупреждение: рынок перегрет
    → Сократить позицию на 50%
    → Переместить SL в безубыток
```

### Дивергенция (сигнал разворота)

```
Если Цена_новый_high И (OBV_не_делает_high ИЛИ CVD_падает):
    → Возможный разворот
    → Подтверждение: Supertrend flip ИЛИ SAR flip
    → Не входить в новые лонги
```

### Комбинации для сильных сигналов

| Сигнал | Комбинация | Сила |
|---|---|---|
| **Сильный BUY** | MFI < 20 + Цена < VWAP + CVD растёт | ⭐⭐⭐ |
| **Сильный SELL** | MFI > 80 + OBV дивергенция + CVD падает | ⭐⭐⭐ |
| **Умеренный BUY** | MFI < 30 + Цена > VWAP | ⭐⭐ |
| **Умеренный SELL** | MFI > 70 + OBV плоский | ⭐⭐ |
| **Нейтральный** | MFI ~50 + OBV тренд совпадает с ценой | — |

## Заключение

Из **23 рассмотренных** объёмных индикаторов:
- **5 включены** в ядро бота: OBV (v0.1), VWAP + MFI + VAP (v0.2), CVD + Volume Profile (v0.3)
- **1 отложен** (AVWAP → v0.3, TWAP → v0.5)
- **17 отклонены** по причинам: дублирование, отсутствие направления/порогов, неустойчивость, сложность без преимущества

**ТОП-3 для крипторынка:**
1. **CVD** — единственный видит агрессию покупателей/продавцов на уровне сделок
2. **VWAP** — единственная «справедливая цена» сессии, якорь для институционалов
3. **MFI** — единственный нормализованный объёмный осциллятор с чёткими порогами

**Ключевой принцип:** объёмные индикаторы — **подтверждения и фильтры**, не primary сигналы. Цена и тренд первичны, объём вторичен. Но без объёма — слепая торговля.

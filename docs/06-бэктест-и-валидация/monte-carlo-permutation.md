# Monte-Carlo тест перестановок: не случайна ли прибыль?

**TL;DR:** Бот 2000 раз «перемешивает» результаты сделок случайными знаками — если случайные перестановки часто дают такую же доходность, значит преимущества нет. Только стратегия, прошедшая этот тест (p-value ≤ 0.05), получает право торговать реальными деньгами.

## Простыми словами

Представьте, что вы бросаете монету 100 раз и записываете результаты. По итогам получилось 60 орлов и 40 решек — неплохо! Но можно ли сказать, что монета «нечестная»? Или это просто повезло? Задаём себе вопрос: а насколько часто случайная монета дала бы такой же или лучший результат? Если случайная монета даёт 60+ орлов в 30% случаев — это просто везение. Если лишь в 2% случаев — значит, монета, скорее всего, правда нечестная.

Бот делает ровно то же самое со сделками стратегии. (Более короткое, обзорное объяснение того же теста — на странице [[mc-permutation-test]] в разделе индикаторов; здесь — подробный технический разбор.)

**Нулевая гипотеза** (то, что мы хотим опровергнуть): знаки сделок — «+» (прибыль) и «−» (убыток) — случайны и симметричны относительно нуля. То есть у стратегии нет настоящего преимущества, просто повезло.

Тест работает так:
1. Берём реальные доходности сделок: например, `[+1%, −0.5%, +2%, −1%, +1.5%]`.
2. Вычисляем наблюдаемое среднее — это мера того, насколько хорошо стратегия.
3. 2000 раз случайно переворачиваем знаки каждой сделки (например, `+1% → −1%`, `−0.5% → +0.5%`), вычисляем среднее. Это — случайная «стратегия без преимущества».
4. Считаем: в скольких перестановках случайное среднее оказалось **не хуже** реального?

Если случайные перестановки «побеждают» редко — значит реальное преимущество есть. Если часто — значит это просто шум.

**p-value** (p-значение, вероятность случайности) — доля перестановок, где случайный результат оказался не хуже реального. Чем меньше p-value, тем убедительнее преимущество стратегии.

**Порог у нас:** p-value ≤ 0.05 — вероятность случайно получить такой результат не более 5%. Стратегия, не прошедшая этот тест, заблокирована от торговли.

### Шаг 1: функция `sign_flip_p_value` — основной тест

```python
def sign_flip_p_value(
    returns: npt.NDArray[np.float64],
    *,
    n_iterations: int = 2000,
    seed: int | None = 42,
) -> float:
```
(`src/backtest/mc_permutation.py:28–33`)

**Что принимает:** массив доходностей сделок в процентах (например, `[0.01, -0.005, 0.02]`).

**Шаг 1а — защитная проверка:** если массив пустой (нет сделок), возвращает `NaN` (не-число) вместо ошибки. Это предотвращает крах при прогоне стратегии, не совершившей ни одной сделки (`src/backtest/mc_permutation.py:51–52`).

**Шаг 1б — вычисление наблюдаемой статистики:** берём абсолютное значение среднего всех доходностей. Это мера «насколько не-нулевое» среднее у стратегии — прокси-сигнал [[sharpe-sortino-metrics|коэффициента Шарпа]]. Тест двусторонний: важно |среднее|, а не просто среднее — потому что преимущество нужно детектировать независимо от знака.

```python
observed = float(np.abs(np.mean(returns)))
rng = np.random.default_rng(seed)
```
(`src/backtest/mc_permutation.py:54–55`)

**Шаг 1в — 2000 перестановок знаков:** для каждой итерации каждой сделке случайно присваивается знак `+1` или `−1`. Это и есть «переворот знака» (sign-flip): исходная доходность `0.01` может превратиться в `−0.01`. Среднее по новому массиву — это результат «случайной стратегии». Если оно по абсолютной величине не меньше наблюдаемого, счётчик `count_extreme` увеличивается.

```python
count_extreme = 0
for _ in range(n_iterations):
    signs = rng.choice([-1.0, 1.0], size=len(returns))
    permuted = returns * signs
    if abs(float(np.mean(permuted))) >= observed:
        count_extreme += 1
```
(`src/backtest/mc_permutation.py:57–62`)

**Шаг 1г — вычисление p-value по формуле Phipson & Smyth:**

```python
return float((count_extreme + 1) / (n_iterations + 1))
```
(`src/backtest/mc_permutation.py:67`)

Подробнее о формуле — в разделе «Формулы и расчёты».

### Шаг 2: детерминизм через `seed=42`

По умолчанию seed (зерно генератора случайных чисел — начальное число, от которого разворачивается вся последовательность случайных перестановок) равен `42`. Это значит: при каждом прогоне на тех же данных бот получает ровно то же p-value. Так результат воспроизводим при аудите.

До спринта S27 seed был `None` — генератор выдавал разные результаты при каждом запуске. Это делало аудит невозможным: одни и те же данные давали разные p-value в разных сессиях. Исправлено в S27 T5.

Если нужен нестохастический (непредсказуемый) режим, вызывающий код может явно передать `seed=None` — тогда каждый запуск даст разное значение (`src/backtest/mc_permutation.py:43–46`).

Порог DSR = 0.95 задан константой `DSR_THRESHOLD` в обоих файлах (`research_wfa.py:37`, `donchian_runner.py:50`).

### Шаг 4: агрегация по нескольким символам

Когда WFA запускается на нескольких символах (например, BTC + ETH + SOL), для каждого символа вычисляется своё `sym_mc_p`. Итоговый агрегированный `mc_p` — это **максимум** из всех символов:

```python
mc_p = max(mc_p_values) if mc_p_values else 1.0
```
(`src/__main__.py:589`)

Логика: если хотя бы один символ показывает высокое p-value (случайное поведение), вся стратегия считается ненадёжной. `max` — самая консервативная агрегация. Как этот агрегированный вердикт затем показывается оператору в дэшборде — см. [[verdict-and-warnings|как читать вердикт]] и [[dsr-and-mc|DSR и Monte Carlo в дэшборде]].

### Шаг 5: `block_bootstrap_p_value` — вторичный диагностический метод

Вторая функция реализует другой подход к перемешиванию — блочный бутстрап (block bootstrap): вместо переворота знаков она ресэмплирует блоки соседних сделок с возвратом. Блок = последовательность из `MC_BLOCK_SIZE=20` сделок подряд. Это позволяет сохранить автокорреляцию (взаимозависимость соседних сделок во времени — если рынок трендовый, несколько соседних сделок могут быть похожи).

```python
def block_bootstrap_p_value(
    returns: npt.NDArray[np.float64],
    *,
    n_iterations: int = 2000,
    block_size: int = MC_BLOCK_SIZE,
    seed: int | None = 42,
) -> float:
```
(`src/backtest/mc_permutation.py:70–76`)

**Механика:** на каждой из 2000 итераций выбираются случайные начальные позиции блоков, блоки конкатенируются и обрезаются до длины исходного массива. Затем считается среднее — аналогично основной функции.

```python
n_blocks = (n + block_size - 1) // block_size  # ceil: сколько блоков нужно
starts = rng.integers(0, n - block_size + 1, size=n_blocks)
sampled = np.concatenate([returns[s : s + block_size] for s in starts])[:n]
```
(`src/backtest/mc_permutation.py:104, 110–111`)

**Критически важное ограничение.** Этот тест НЕ является тестом наличия преимущества (edge). Он измеряет вариабельность среднего по наблюдённым данным (ресэмплинг С возвратом из реальных доходностей) — но не сравнивает с нулевой гипотезой об отсутствии преимущества. Настоящий тест значимости edge требует переворота знаков целых блоков — как в `sign_flip_p_value`. Это зафиксировано в docstring функции и в тесте `test_block_bootstrap_not_used_as_gate` (`tests/unit/test_mc_block_bootstrap.py:51–81`), который через AST-анализ гарантирует, что `block_bootstrap_p_value` никогда не окажется импортированной в `research_wfa.py`.

**В `live_trade_reporter.py`** оба теста используются с разными порогами по количеству сделок n:

- n < 20: тест не запускается совсем, статус `MC_INSUFFICIENT_N`
- 20 ≤ n < 40: только `sign_flip_p_value`
- n ≥ 40: оба теста

(`src/analytics/live_trade_reporter.py:38–39, 117–133`)

## Формулы и расчёты

### Формула p-value: поправка Phipson & Smyth 2010

$$p = \frac{\text{count\_extreme} + 1}{N + 1}$$

**Что считает:** долю перестановок, где случайная стратегия показала результат не хуже реального.

**Расшифровка:**
- `count_extreme` — сколько из N=2000 случайных перестановок дали |среднее| ≥ |наблюдаемого|
- `+1` в числителе и знаменателе — поправка Phipson & Smyth

**Зачем поправка `+1`?** Без неё: если ни одна перестановка не «побила» реальный результат (count_extreme=0), формула вернёт `0/2000 = 0.0`. Но p=0 логически невозможен при конечном числе перестановок — мы никогда не проверяли все мыслимые перестановки. С поправкой минимально возможное p-value равно `1/(N+1) = 1/2001 ≈ 0.0005`.

Это не просто теоретическая элегантность. До спринта S33 T2 в коде стояло `count/N` — это давало p=0 для очень хороших стратегий. Аудиторы (quant-stats-reviewer) указали на логическую ошибку, и формула была исправлена (`src/backtest/mc_permutation.py:64–67`).

**Наша реализация:**
```python
# src/backtest/mc_permutation.py:64-67
# S33 T2 (CC-D fix): (count + 1) / (N + 1) per Phipson & Smyth 2010 / ADR 0015.
# Avoids p=0 (logically impossible с finite permutations).
# Minimum p = 1/(N+1), не 0.
return float((count_extreme + 1) / (n_iterations + 1))
```

### Тест-статистика

$$\text{stat} = |\overline{r}| = \left|\frac{1}{n}\sum_{i=1}^{n} r_i\right|$$

**Что считает:** абсолютную величину среднего по всем доходностям сделок. Выбрана как «прокси-сигнал Шарпа» — если среднее далеко от нуля, стратегия стабильно зарабатывает (или теряет).

**Двусторонний тест** (two-sided): берём `|среднее|`, а не просто `среднее`. Нам важно отклонение от нуля в любую сторону — стратегия со стабильными убытками тоже имеет преимущество, только со знаком минус.

## Примеры / сценарии

### Сценарий А: стратегия с реальным преимуществом

Стратегия совершила 100 сделок, каждая принесла ровно +1%: `returns = [0.01, 0.01, ..., 0.01]`.

Наблюдаемое среднее: `|mean| = 0.01`.

Что происходит при переворотах знаков? Случайная перестановка присвоит каждой сделке +1 или −1 с вероятностью 50/50. Если все 100 знаков стали отрицательными: `mean = -0.01`, `|mean| = 0.01 ≥ 0.01` — этот вариант засчитывается. Но в большинстве перестановок часть знаков будет положительной, часть отрицательной, и среднее окажется близко к нулю: `|mean| < 0.01`.

Например, из 2000 итераций только 7 перестановок дали `|mean| ≥ 0.01`. Тогда:

$$p = \frac{7 + 1}{2000 + 1} = \frac{8}{2001} \approx 0.004$$

`0.004 ≤ 0.05` → ворота L2 PASS. Подтверждено в тесте `test_strong_positive_returns_yield_low_p` (`tests/unit/test_mc_sign_flip.py:14–18`).

### Сценарий Б: стратегия без преимущества (шум)

Стратегия совершила 100 сделок со случайными доходностями: нормальное распределение с нулевым средним.

Наблюдаемое среднее будет около нуля (например, `|mean| = 0.001`). При перестановке знаков случайные стратегии будут давать примерно такое же среднее — нет ничего особенного для «побития». Пусть из 2000 итераций 1050 дали `|mean| ≥ 0.001`:

$$p = \frac{1050 + 1}{2000 + 1} = \frac{1051}{2001} \approx 0.525$$

`0.525 > 0.05` → ворота L2 FAIL. Подтверждено в тесте `test_zero_mean_returns_yield_high_p` (`tests/unit/test_mc_sign_flip.py:21–26`).

### Сценарий В: мульти-символьный WFA (BTC + ETH + SOL)

Предположим, прогон дал:
- BTC: `mc_p = 0.012` (PASS)
- ETH: `mc_p = 0.031` (PASS)
- SOL: `mc_p = 0.071` (FAIL — выше порога 0.05)

Агрегация: `mc_p = max(0.012, 0.031, 0.071) = 0.071`.

`0.071 > 0.05` → итоговый вердикт по MC: FAIL. Одного «слабого» символа достаточно, чтобы заблокировать всю стратегию. (`src/__main__.py:589`)

### Сценарий Г: недостаточно сделок для live-отчёта

В live-режиме функция `compute_mc_with_gating` из `live_trade_reporter.py` проверяет количество сделок перед запуском:

- n = 15 (меньше 20): оба теста не запускаются, статус `MC_INSUFFICIENT_N` — вместо ненадёжного p-value возвращается явный сигнал «недостаточно данных».
- n = 25 (между 20 и 40): только `sign_flip_p_value`, блочный бутстрап не запускается (блок 20 не вписывается в выборку надёжно).
- n = 50: оба теста. (`src/analytics/live_trade_reporter.py:116–133`)

## Подводные камни / что важно понимать

**1. Два теста — два разных вопроса.**
`sign_flip_p_value` отвечает на вопрос: «Есть ли у стратегии настоящее преимущество?» (нулевая гипотеза — нет). `block_bootstrap_p_value` отвечает на другой вопрос: «Насколько стабильно оценено среднее?» (вариабельность наблюдённого среднего). Продвигать блочный бутстрап в гейт без переключения на блочный sign-flip — ошибка, которая пропустит стратегии без реального edge. В коде есть AST-тест, блокирующий именно такой сдвиг (`tests/unit/test_mc_block_bootstrap.py:51–81`).

**2. p-value никогда не бывает точно 0 — и это правильно.**
При 2000 перестановках минимальное достижимое p-value = 1/2001 ≈ 0.0005. Если кто-то увидит в отчёте p=0 — это баг (та самая ошибка, исправленная в S33 T2). Формула `(count+1)/(N+1)` гарантирует ненулевое значение (`src/backtest/mc_permutation.py:67`).

**3. Не путать seed=42 и «нестохастичность».**
seed=42 означает «детерминированный»: одни и те же данные → одно и то же p-value при любом запуске. Это не значит, что тест «одинаковый» или «предсказуемый» без исходных данных. seed=None означает «случайный» — каждый запуск даёт разное p-value.

**4. MC-тест — только L2 из пяти ворот.**
Пройти MC недостаточно. Стратегия должна пройти **все пять** условий одновременно:

| Гейт | Что проверяет | Источник |
|------|--------------|---------|
| L1 | [[sharpe-sortino-metrics\|Sharpe]] ≥ 0.7 по каждому WFA-фолду | `walk_forward.py:196–198` |
| L2 | MC p-value ≤ 0.05 (этот тест) | `walk_forward.py:199` |
| L3 | [[tstat-oos-is-metrics\|n_eff]] ≥ 50, если применимо | `walk_forward.py:205–207` |
| L4 | n_raw ≥ 100 (T5-floor), если применимо | `walk_forward.py:210–212` |
| L5 | [[deflated-sharpe-ratio\|DSR]] ≥ 0.95 — проверяется **отдельно**, после L1-L4 | `research_wfa.py:342–348`, `donchian_runner.py:239–245` |

L5 (DSR) — полноценный блокирующий гейт: если `dsr_value < 0.95`, строка `"dsr_threshold"` дописывается в `failed_criteria`, и вердикт становится `WFA_FAIL` точно так же, как от провала любого другого гейта. MC защищает от случайности, L5 защищает от переобучения на множестве триалов. Подробнее про все ворота — в [[acceptance-gates-t1-t6]].

**5. Порог ужесточался по мере развития проекта.**
Изначально (до S34/ADR 0052) порог был 0.10 — вероятность случайности не более 10%. В S34 после консилиума трёх ревьюеров порог был ужесточён до 0.05. Это значит, что стратегии, прошедшие с p ∈ (0.05, 0.10), были бы отклонены по новым правилам. Старые callers могут передавать `p_threshold=0.10` явно для обратной совместимости — это задокументировано в `evaluate_acceptance_gate` (`src/backtest/walk_forward.py:184`).

**6. Максимум при мульти-символах — намеренно консервативен.**
При объединении нескольких символов бот берёт НАИХУДШИЙ результат (максимальный p-value), а не среднее и не минимум. Это осознанный выбор: нельзя считать стратегию значимой, если хотя бы один из рынков даёт случайные результаты (`src/__main__.py:588–589`).

**7. NaN при пустом массиве — защита, не ошибка.**
Если у стратегии нет OOS-сделок (например, слишком маленькая тестовая выборка), `sign_flip_p_value` возвращает `NaN`. В `evaluate_acceptance_gate` NaN трактуется как провал гейта — стратегия получает FAIL. Это fail-closed поведение: при неизвестном результате всегда отказываем.

# Метрики результата сделок (Sharpe, Sortino, Profit Factor и др.)

**TL;DR:** После того как бэктест прокрутил всю историю баров, две функции превращают список сделок и кривую капитала в числа: `_compute_metrics` — для простого прогона, `compute_t1_t6_metrics` — для итоговой проверки WFA. Именно эти числа решают, «пройдёт» ли стратегия ворота T1–T6 и попадёт ли в продакшн.

---

## Простыми словами

Представьте, что вы вели торговый журнал весь год: записывали каждую сделку, сколько заработали и потеряли. В конце года вы хотите понять — это была стабильная работа или вам просто повезло несколько раз?

Именно это делают метрики. Они отвечают на вопросы:

- **Сколько заработано в целом?** — Total Return, Net Profit.
- **Насколько стабильно?** — Sharpe Ratio (коэффициент Шарпа, соотношение прибыли и нервотрёпки).
- **Больно ли падать?** — Max Drawdown (максимальная просадка — самый глубокий «провал» от пика).
- **Чаще выигрываем или проигрываем?** — Win Rate (доля прибыльных сделок).
- **Перекрывают ли победы поражения?** — Profit Factor (профит-фактор).
- **Что получаем в среднем с одной сделки?** — Expectancy (матожидание).

Числа рассчитываются один раз — сразу после того, как движок завершил прокрутку исторических данных.

---

## Как это работает у нас

В нашем коде существуют **две разных функции** расчёта метрик. Они живут в разных файлах и используются в разных контекстах:

| Функция | Файл | Входные данные | Для чего |
|---|---|---|---|
| `_compute_metrics(equity_df, trades_df, initial_balance, bars_per_year)` | `src/backtest/replay_engine.py:31` | Кривая капитала + список сделок | Простой прогон (backtesting + отображение в [[trade-statistics\|дашборде]]) |
| `compute_t1_t6_metrics(trades, fold_oos_is_sharpe, ...)` | `src/backtest/strategy_metrics.py:40` | Только список [[trade-extractor-and-records\|TradeRecord]] из OOS-окон WFA | Итоговые ворота T1–T6 в WFA-пайплайне |

> **Не путать:** `_compute_metrics` считает метрики «по кривой капитала» (bar-by-bar equity). `compute_t1_t6_metrics` считает метрики «по сделкам» (per-trade pnl_pct). Числа Sharpe и Sortino у них могут немного отличаться из-за разных входных рядов. Это же различие порождает [[wfa-reporter-three-sharpe-series|три разных «коэффициента Шарпа» в итоговом отчёте]] — их нельзя путать.

### `_compute_metrics` — шаг за шагом

Вызывается в конце `run_replay` (`src/backtest/replay_engine.py:331`).

#### Шаг 1: Подготовка данных (строки 48–56)

```python
equity = equity_df["balance"].astype(float)
returns = equity.pct_change().replace([np.inf, -np.inf], np.nan).dropna()
```

Из кривой капитала вычисляются **доходности на каждый бар** — процентное изменение баланса относительно предыдущего. Бесконечные значения (если баланс упал до нуля) заменяются NaN и выбрасываются.

Затем сделки делятся на победителей и проигравших:

```python
wins   = trades_df[trades_df["net_pnl"] > 0]
losses = trades_df[trades_df["net_pnl"] < 0]
```

«Чистая прибыль» каждой сделки (`net_pnl`) уже содержит вычтенные комиссии и слиппаж, рассчитанные в `run_replay`. `(src/backtest/replay_engine.py:51–56)`

#### Шаг 2: Расчёт просадки (строки 58–60)

```python
rolling_max  = equity.cummax()
drawdown_abs = (rolling_max - equity).fillna(0.0)
drawdown_pct = drawdown_abs / rolling_max.replace(0, np.nan)
```

**Просадка** (drawdown) — это насколько текущий баланс ниже своего исторического максимума. Считается в каждый момент времени. Метрика `Max Drawdown` берёт максимальное значение из всех этих просадок.

Аналогия: вы поднялись на гору до 1 000 м, потом опустились до 700 м. Просадка = 300 м (30%). Если потом поднялись на 1 100 м и упали до 900 м — новая просадка 18%, меньше прошлой. Максимальная просадка за всё время — 30%.

`(src/backtest/replay_engine.py:58–60)`

#### Шаг 3: Фактор годовой нормировки (строка 62)

```python
annualization_factor = float(np.sqrt(bars_per_year))
```

Это ключевой параметр для Sharpe и Sortino. Без него результаты стратегий на разных таймфреймах невозможно сравнивать между собой (подробнее — в разделе «Формулы и расчёты»).

`(src/backtest/replay_engine.py:62)`

#### Шаг 4: Коэффициент Шарпа (строки 64–66)

```python
if not returns.empty and float(returns.std()) > 0:
    sharpe = float((returns.mean() / returns.std()) * annualization_factor)
```

Если стандартное отклонение доходностей равно нулю (все бары дали одинаковый результат) — Sharpe остаётся 0.0. `(src/backtest/replay_engine.py:64–66)`

#### Шаг 5: Коэффициент Сортино (строки 71–76)

```python
downside     = returns.where(returns < 0, 0.0)
downside_dev = float(np.sqrt((downside**2).mean()))
if downside_dev > 0:
    sortino = float((returns.mean() / downside_dev) * annualization_factor)
```

Вместо всей волатильности в знаменателе — только «плохая»: убыточные бары. Прибыльные бары приравниваются к нулю перед расчётом отклонения. `(src/backtest/replay_engine.py:71–76)`

#### Шаг 6: Остальные метрики (строки 78–118)

```python
win_rate   = len(wins)   / total_trades * 100.0
loss_rate  = len(losses) / total_trades * 100.0
expectancy = net_profit  / total_trades
```

Комиссии суммируются из полей `entry_fee + exit_fee` каждой сделки — только если оба столбца присутствуют в `trades_df`. `(src/backtest/replay_engine.py:83–85)`

Время удержания сделки: функция ищет сначала столбец `holding_hours`, затем — `holding_time_seconds / 3600`. Это нужно для совместимости: оба столбца присутствуют в `trades_df`, созданном `run_replay`. `(src/backtest/replay_engine.py:87–92)`

Итоговый словарь возвращается с **дублирующимися ключами** для обратной совместимости с дашбордом: `"Net Profit"` и `"Net Profit (USDT)"` — одно и то же значение, `"Total Commissions"` и `"Total Commissions (USDT)"` — тоже. `(src/backtest/replay_engine.py:97–119)`

### `compute_t1_t6_metrics` — ворота WFA

Эта функция работает иначе: на вход поступают не бары капитала, а список объектов `TradeRecord` из OOS-окон Walk-Forward анализа. Подробнее о WFA — в [[walk-forward-analysis]].

Главное отличие: **аннуализация здесь — по сделкам**, а не по барам. Каждая запись в `pnl_pcts` — доходность одной сделки в процентах. Фактор `sqrt(bars_per_year)` применяется так же, но смысл другой: он масштабирует «среднюю сделку» к годовому горизонту.

> Подробно о том, почему именно такая аннуализация и к каким значениям Sharpe это приводит, читайте в [[acceptance-gates-t1-t6]] и в [[deflated-sharpe-ratio]].

#### T1: Sharpe OOS (строки 81–86)

```python
pnl_std = float(pnl_pcts.std(ddof=1))
if pnl_std > _STD_EPS:
    sharpe_per_trade = float(pnl_pcts.mean()) / pnl_std
    t1_sharpe_oos = sharpe_per_trade * annualization_factor
```

`_STD_EPS = 1e-12` — защита от деления на ноль при «вырожденной» серии (все сделки дали одинаковый результат). В таком случае возвращается `NaN`, а не `±inf`. `(src/backtest/strategy_metrics.py:37, 81–86)`

**Ворота:** T1 проходит при `t1_sharpe_oos >= 1.0`. `(src/__main__.py:673)`

#### T2: Sortino OOS — каноническая формула (строки 93–101)

```python
downside     = np.minimum(pnl_pcts, 0.0)
downside_dev = float(np.sqrt(np.mean(downside**2)))
if downside_dev > _STD_EPS:
    sortino_per_trade = float(pnl_pcts.mean()) / downside_dev
    t2_sortino_oos = sortino_per_trade * annualization_factor
```

Это каноническая формула Sortino & Price 1994: корень из среднего квадрата отрицательных доходностей по **всем** сделкам (прибыльные дают ноль, не пропускаются). `(src/backtest/strategy_metrics.py:93–101)`

**Ворота:** T2 проходит при `t2_sortino_oos >= 1.5`. `(src/__main__.py:675)`

#### T3: Max Drawdown (строки 106–114)

```python
equity_full = np.concatenate([[initial_capital], initial_capital + np.cumsum(pnl_quotes)])
running_max = np.maximum.accumulate(equity_full)
drawdowns   = (equity_full - running_max) / running_max
t3_max_drawdown = float(abs(drawdowns.min()))
```

Кривая капитала строится из суммы `pnl_quote` всех OOS-сделок. Перед первой сделкой добавляется начальный капитал — чтобы просадка первой сделки измерялась от стартового баланса, а не от нуля. При полном сгорании капитала (`running_max = 0`) значение принудительно устанавливается в -100%. `(src/backtest/strategy_metrics.py:106–114)`

**Ворота:** T3 проходит при `t3_max_drawdown < 0.25` (то есть просадка менее 25%). `(src/__main__.py:677)`

#### T4: Win Rate + Risk/Reward (строки 117–123)

```python
t4_win_rate = len(winners) / n
t4_avg_rr   = winners.mean() / losers_abs.mean()
```

T4 — двойной профиль. Стратегия может пройти ворота двумя способами:
- Агрессивный: средний выигрыш/проигрыш ≥ 2.0, и при этом ≥ 35% сделок прибыльны.
- Умеренный: средний выигрыш/проигрыш от 1.5 до 2.0, и при этом ≥ 45% сделок прибыльны.

Если Risk/Reward < 1.5 — T4 всегда провален. `(src/__main__.py:681–688)`

#### T5: Статистическая значимость (строки 126–131)

```python
t5_mean_pnl_pct = float(pnl_pcts.mean())
t5_t_stat       = float(pnl_pcts.mean()) / (pnl_std / math.sqrt(n))
```

[[tstat-oos-is-metrics|T-статистика]] — стандартная проверка: «а не случаен ли этот результат?». Чем выше значение, тем меньше вероятность, что прибыль — просто шум. Эмпирический аналог той же проверки — [[monte-carlo-permutation|Monte-Carlo тест перестановок]]. `(src/backtest/strategy_metrics.py:126–131)`

**Ворота в коде:** T5 проходит при `mean_pnl_pct > 0`, `t_stat >= 2.0` и `n_trades >= N`, где N зависит от пути запуска. `(src/__main__.py:690–697, src/dashboard/backtest_runner.py:332, src/backtest/research_wfa.py:41, src/backtest/donchian_runner.py:49)`

> **Нюанс (важно — два разных порога):** Порог n_trades в T5 не один и тот же для всех путей запуска.
>
> | Путь запуска | Переменная | Порог T5 |
> |---|---|---|
> | CLI `python -m src wfa` | `__main__.py:695` | **100** сделок |
> | Дашборд (dashboard) | `_N_TRADES_FLOOR`, `backtest_runner.py:332` | **50** сделок |
> | Research WFA | `T5_FLOOR`, `research_wfa.py:41` | **50** сделок |
> | Donchian runner | `T5_FLOOR`, `donchian_runner.py:49` | **50** сделок |
>
> Docstring `strategy_metrics.py` со значением 50 отражает порог **трёх из четырёх** путей — он не устарел. Стратегия с 80 OOS-сделками **пройдёт** T5 на путях дашборда, research_wfa и donchian, и **провалит** только на CLI-команде `python -m src wfa`.

#### T6: OOS/IS Sharpe (строки 134–137)

```python
t6_oos_is_sharpe_ratio_mean = float(np.mean(fold_oos_is_sharpe))
```

Каждый WFA-фолд даёт пару: Sharpe на тренировочных данных (IS) и Sharpe на тестовых (OOS). T6 проверяет среднее отношение OOS/IS по всем фолдам. Если стратегия «переобучена» — на тренировочных данных она блистает, а на тестовых — сдувается, и это отношение падает ниже 0.7. `(src/backtest/strategy_metrics.py:134–137)`

**Ворота:** T6 проходит при `oos_is_sharpe_ratio_mean >= 0.7`. `(src/__main__.py:699–702)`

## Формулы и расчёты

### Коэффициент Шарпа (Sharpe Ratio)

**Суть:** сколько прибыли бот зарабатывает на каждую единицу «нервотрёпки» (волатильности). Чем выше — тем лучше. Тот же коэффициент как ворота WFA (T1/T2) разбирается в [[sharpe-sortino-metrics|Sharpe и Sortino]].

```
Sharpe = (среднее(r) / стд(r)) × sqrt(bars_per_year)
```

Расшифровка:
- `среднее(r)` — средняя доходность за один бар (или сделку в WFA-версии).
- `стд(r)` — стандартное отклонение доходностей (мера нестабильности результата).
- `sqrt(bars_per_year)` — **годовая нормировка** (см. ниже).

`(src/backtest/replay_engine.py:65–66)` / `(src/backtest/strategy_metrics.py:83–84)`

### Коэффициент Сортино (Sortino Ratio)

**Суть:** как Шарп, но штрафует только за убытки, а не за резкий рост.

```
Downside deviation = sqrt( mean( min(r, 0)² ) )
Sortino = (среднее(r) / Downside deviation) × sqrt(bars_per_year)
```

Расшифровка:
- Каждый убыточный бар/сделка участвует в знаменателе.
- Каждый прибыльный бар/сделка заменяется нулём (не штрафует).
- Итог: хорошая стратегия с редкими но большими выигрышами получит у Сортино более высокую оценку, чем у Шарпа.

`(src/backtest/replay_engine.py:73–76)` / `(src/backtest/strategy_metrics.py:93–98)`

### Годовая нормировка: зачем и какая

Без нормировки Sharpe стратегии на 1-часовых барах нельзя сравнить со стратегией на 4-часовых: за год у первой ~8 760 баров, у второй ~2 191. Нормировка приводит обе к одному масштабу — «годовой Sharpe».

| Таймфрейм | Баров в год | sqrt(баров) |
|---|---|---|
| 1H (1 час) | 8 760 | ≈ 93.6 |
| 4H (4 часа) | 2 191 | ≈ 46.8 |
| 15M (15 минут) | 35 040 | ≈ 187.2 |

Важно: неправильное значение `bars_per_year` искажает Sharpe. Для 4H вместо 1H — **в два раза** (`93.6 / 46.8 = 2.0`). Именно это был баг, исправленный в Sprint 27 (S27 T1): до него `bars_per_year` был захардкожен равным 8760 для всех таймфреймов. При 4H-баре это давало **завышение** IS Sharpe в 2× — бот применял норматив 8 760 баров/год там, где правильно 2 191. Завышенный IS Sharpe делал отношение OOS/IS меньше 0.7, что приводило к искусственному провалу T6 у хороших стратегий. `(src/backtest/replay_engine.py:39–42)`

Значение берётся из конфига (`config["bars_per_year"]`) и передаётся в `run_replay`, откуда попадает в `_compute_metrics`. `(src/backtest/replay_engine.py:137, 331)`

### Profit Factor (профит-фактор)

```
Profit Factor = Валовая прибыль / Валовый убыток
```

- > 1.0 — стратегия зарабатывает больше, чем теряет.
- = 1.0 — ноль (в нуле, без учёта комиссий).
- < 1.0 — убыточная.

Если убыточных сделок не было (`gross_loss = 0`), функция возвращает `0.0`, а не `inf`. `(src/backtest/replay_engine.py:102)`

### Win Rate и Loss Rate

```
Win Rate  (%) = (число прибыльных сделок / общее число сделок) × 100
Loss Rate (%) = (число убыточных сделок  / общее число сделок) × 100
```

Сделки с `net_pnl = 0` (точно в ноль) не попадают ни в wins, ни в losses. `(src/backtest/replay_engine.py:79–80)`

### Expectancy (матожидание сделки)

```
Expectancy (USDT) = Net Profit / Total Trades
```

Это средний ожидаемый результат с одной сделки в денежном выражении. Если отрицательный — стратегия в среднем теряет деньги. `(src/backtest/replay_engine.py:81)`

### Max Drawdown (максимальная просадка)

```
drawdown_pct[i] = (peak_equity - equity[i]) / peak_equity
Max Drawdown (%) = max(drawdown_pct) × 100
```

`peak_equity` — максимальный баланс за всё время до текущего момента. Как MaxDD (вместе с Win Rate и Risk/Reward) работает воротами T3/T4 — в [[max-drawdown-winrate-rr]]. `(src/backtest/replay_engine.py:58–60, 99)`

Параллельно считается и абсолютная просадка в USDT — `Max Drawdown (USDT)`. `(src/backtest/replay_engine.py:114)`

### Total Return (итоговая доходность)

```
Total Return (%) = (конечный_баланс / начальный_баланс − 1) × 100
```

`(src/backtest/replay_engine.py:98)`

## Примеры / сценарии

### Пример 1: Простая серия из 5 сделок

Допустим, стартовый баланс 10 000 USDT, 5 сделок:

| # | Net PnL | Баланс после |
|---|---|---|
| 1 | +150 | 10 150 |
| 2 | −80  | 10 070 |
| 3 | +200 | 10 270 |
| 4 | −350 | 9 920  |
| 5 | +100 | 10 020 |

Результат:
- **Gross Profit** = 150 + 200 + 100 = **450 USDT**
- **Gross Loss** = 80 + 350 = **430 USDT**
- **Net Profit** = 450 − 430 = **20 USDT**
- **Profit Factor** = 450 / 430 ≈ **1.047** (чуть лучше нуля)
- **Win Rate** = 3/5 × 100 = **60%**
- **Expectancy** = 20 / 5 = **4 USDT** за сделку
- **Max Drawdown** = (10 270 − 9 920) / 10 270 ≈ **3.41%** (просадка с пика 3 до бара 4)
- **Total Return** = (10 020 / 10 000 − 1) × 100 = **0.2%**

### Пример 2: Как annualization_factor влияет на Sharpe

Допустим, у стратегии средняя доходность за бар 0.1%, стандартное отклонение 0.5%:

```
Базовый Sharpe = 0.001 / 0.005 = 0.2  (безразмерный)
```

Умножаем на `sqrt(bars_per_year)`:

| Таймфрейм | bars_per_year | sqrt | Годовой Sharpe |
|---|---|---|---|
| 1H | 8 760 | 93.6 | **18.7** |
| 4H | 2 191 | 46.8 | **9.4** |
| 15M | 35 040 | 187.2 | **37.4** |

Одна и та же стратегия с теми же параметрами «выглядит» в четыре раза лучше на 15-минутных барах, чем на 4-часовых — потому что за год больше баров, больше «событий». Именно поэтому нормировку нельзя опускать и нельзя путать таймфреймы.

### Пример 3: Sortino лучше Sharpe для «хвостовых» стратегий

У стратегии несколько очень больших выигрышей и много небольших убытков:

```
pnl_pcts = [-0.01, -0.01, -0.01, -0.01, +0.15]
```

- Sharpe «штрафует» за выигрыш +15% так же, как за убыток -1% (они оба отклоняются от среднего).
- Sortino «штрафует» только за убытки: в знаменатель идут только четыре значения -1%.
- Sortino будет заметно выше Sharpe — и правильно, ведь большой выигрыш — это хорошо.

## Подводные камни / что важно понимать

### 1. Два разных Sharpe в одном пайплайне

`_compute_metrics` считает Sharpe «по барам» (изменение баланса бар за баром). `compute_t1_t6_metrics` считает Sharpe «по сделкам» (доходность каждой сделки). Это разные числа. Смотрите на правильную метрику: для ворот WFA — T1–T6, для общей картины прогона — `_compute_metrics`.

### 2. Правило годовой нормировки — строгое

Если передать неверный `bars_per_year`, Sharpe исказится пропорционально корню из ошибки. Для 4H вместо 1H — **завышение** в ровно 2 раза: `sqrt(8760) / sqrt(2191) ≈ 93.6 / 46.8 = 2.0`. Это было причиной реального бага (S27 T1) — IS Sharpe был завышен вдвое, отношение OOS/IS падало ниже 0.7, и хорошие 4H-стратегии искусственно проваливали ворота T6. `(src/backtest/replay_engine.py:39–42)`

Откуда берётся значение: из `config["bars_per_year"]`, который проставляет `__main__.py` по словарю таймфреймов (5m → 105 120, 15m → 35 040, 30m → 17 520, 1H → 8 760, 4H → 2 191, D → 365). `(src/__main__.py:518–528)`

### 3. Sortino по «старой» формуле — в 3.6× выше

До Sprint 27 Sortino считался как стандартное отклонение только убыточных сделок (`std(losers, ddof=1)`). Это не каноническая формула. Результат был завышен примерно в 3.6 раза, из-за чего порог T2 ≥ 1.5 был фактически «бесплатным». После S27 T2 исправлено на формулу Sortino & Price 1994.

### 4. Порог T5 — разный в зависимости от пути запуска

В проекте **два разных порога** T5 n_trades, и они активны одновременно на разных путях:

- **CLI [[wfa-validation-command|`python -m src wfa`]]:** порог **100** сделок (`src/__main__.py:695`).
- **Дашборд** (`_N_TRADES_FLOOR = 50`, `src/dashboard/backtest_runner.py:332`), **Research WFA** (`T5_FLOOR = 50`, `src/backtest/research_wfa.py:41`) и **[[donchian-runner-and-reference-run|Donchian runner]]** (`T5_FLOOR = 50`, `src/backtest/donchian_runner.py:49`): порог **50** сделок.

Docstring `strategy_metrics.py` со значением 50 (ADR 0052 S34) — живой, а не устаревший: он описывает поведение большинства путей. Стратегия с 80 OOS-сделками **пройдёт** T5 на трёх путях из четырёх, включая дашборд, и провалит только CLI-команду `python -m src wfa`.

### 5. Profit Factor = 0.0 при отсутствии убытков

Если стратегия не совершила ни одной убыточной сделки, `gross_loss = 0` и функция вернёт `Profit Factor = 0.0` (а не бесконечность). Это технический ноль, а не признак плохой стратегии — просто нет данных для расчёта. `(src/backtest/replay_engine.py:102)`

### 6. Equity в `_compute_metrics` — mark-to-market, не реализованная

Кривая баланса строится из mark-to-market значений: открытая позиция переоценивается по текущей цене каждый бар. Это значит, что просадки в `_compute_metrics` включают нереализованный убыток. После закрытия позиции баланс «прыгает» на реализованный PnL. Подробнее — в [[replay-engine-bar-by-bar]]. Для стратегий-пробоев кривая капитала строится иначе — последовательно-аддитивно, без mark-to-market: см. [[research-kernel-execution-model|research-ядро исполнения]].

### 7. Два дублирующихся ключа в словаре метрик

`_compute_metrics` возвращает и `"Net Profit"`, и `"Net Profit (USDT)"` с одинаковым значением. То же для `"Total Commissions"` / `"Total Commissions (USDT)"` и для времени удержания: `"Average Holding Time (hours)"` и `"Avg Holding Time (hours)"`. Это сделано для совместимости со старым дашбордом — оба ключа должны быть. `(src/backtest/replay_engine.py:107, 116–118)`

# Wilder ATR и стоп-уровни: расчёт волатильности для защитных стопов

**TL;DR:** Wilder ATR — это «термометр волатильности» рынка: одно число, которое показывает, насколько широко обычно колышется цена за одну свечу. Бот использует это число, чтобы поставить защитный стоп-лосс на «разумном» расстоянии от точки входа — достаточно далеко, чтобы не выбило случайным шумом, и достаточно близко, чтобы ограничить потери.

---

## Простыми словами

Представьте, что вы едете на автомобиле по горной дороге и хотите поставить отбойник, чтобы не улететь в пропасть. Если дорога узкая и извилистая — ставите отбойник почти вплотную к краю. Если дорога широкая и холмистая — отбойник нужно отодвинуть подальше, иначе вы будете постоянно в него врезаться на поворотах.

**[[atr-indicator|ATR]] (Average True Range — средний истинный диапазон)** — это именно «ширина дороги»: среднее расстояние, на которое цена движется вверх-вниз за одну свечу. Когда рынок спокойный — ATR маленький, цена колышется незначительно. Когда рынок бурный — ATR большой, цена скачет резко.

**Wilder ATR** — это конкретный способ считать это среднее, придуманный Дж. Уайлдером в 1978 году. Он устроен так, что недавние свечи влияют на результат чуть сильнее, чем давние (как «взвешенное» среднее с постепенным забыванием). В отличие от обычного скользящего среднего, которое просто складывает последние N чисел и делит на N, Wilder ATR «помнит» всё, что было до, через одну компактную формулу. (Это то же различие «классический против Wilder», что и у [[ema-rsi-indicators|RSI и скользящих средних]].)

**Зачем это нужно в бэктесте?** Когда бот «заходит» в сделку в симуляции, ему нужно решить: при каком минимуме цены выходить. Если поставить стоп слишком близко — случайный всплеск закроет позицию раньше времени. Если слишком далеко — потери будут большими. ATR даёт «природный» масштаб: стоп = цена входа минус N × ATR, где N — настроечный коэффициент (в проекте он называется `atr_stop_mult`).

## Как это работает у нас

### Шаг 1. Функция `_wilder_atr` — общий расчётный блок для бэктестов

Функция определена в `src/backtest/indicators.py:17–51` и является общим строительным блоком — **DRY** (Don't Repeat Yourself, «не повторяй себя»): S55 PY-3 извлёк её из дублированного кода двух раннеров в одно место.

Что она принимает: датафрейм с колонками `high` (максимум свечи), `low` (минимум), `close` (закрытие), и `period` — количество свечей для сглаживания.

Что она возвращает: массив чисел той же длины, что и входные данные. Первые `period-1` элементов — NaN (значение ещё не вычислено, данных недостаточно). Первое осмысленное значение появляется на индексе `period-1` (то есть после того, как накопилось ровно `period` свечей).

Пример: для `period=9` первые 8 элементов (индексы 0–7) — NaN, первый реальный ATR — на индексе 8.

Внутри функция делает три вещи:

**1. Извлекает массивы цен** (`src/backtest/indicators.py:33–36`):
```python
high = df["high"].to_numpy(dtype=np.float64)
low = df["low"].to_numpy(dtype=np.float64)
close = df["close"].to_numpy(dtype=np.float64)
prev_close = np.concatenate([[close[0]], close[:-1]])
```
`prev_close` — это цена закрытия предыдущей свечи. Для первой свечи предыдущего закрытия нет, поэтому используется соглашение: `prev_close[0] = close[0]`. Это значит, что для первой свечи Истинный диапазон сводится к простому `high - low` (при корректных OHLC-данных, где open ≤ max(high, prev_close)).

**2. Считает True Range для каждой свечи** (`src/backtest/indicators.py:37–43`):
```python
tr = np.maximum.reduce([
    high - low,
    np.abs(high - prev_close),
    np.abs(low - prev_close),
])
```
**True Range (истинный диапазон)** — это максимум из трёх величин:
- `high - low`: обычный диапазон свечи сверху вниз;
- `|high - prev_close|`: расстояние от вчерашнего закрытия до сегодняшнего максимума (гэп вверх);
- `|low - prev_close|`: расстояние от вчерашнего закрытия до сегодняшнего минимума (гэп вниз).

Зачем три? Потому что рынок иногда открывается с разрывом (гэпом): цена перескочила через ночь. Обычный `high - low` пропустит этот разрыв. True Range его учитывает.

**3. Сглаживает по методу Уайлдера** (`src/backtest/indicators.py:44–50`):
```python
atr_out[period - 1] = tr[:period].mean()  # seed: SMA первых period значений
for i in range(period, len(tr)):
    atr_out[i] = (atr_out[i - 1] * (period - 1) + tr[i]) / period  # рекурсия
```
- **Seed (начальное значение рекурсии)**: первый ATR = обычное среднее (SMA — простая скользящая средняя) первых `period` значений True Range. Это «стартовый разгон».
- **Рекурсия**: каждый следующий ATR = (предыдущий ATR × (period-1) + текущий TR) / period. Это сглаживание: новый день влияет на результат с весом `1/period`, а всё прошлое «затухает» постепенно.

### Шаг 3. Как ATR превращается в цену стоп-лосса

#### Бэктест ATR Breakout — стоп фиксированный

В `src/backtest/atr_breakout_runner.py:176–178` ATR вычисляется дважды — отдельно для входного сигнала и отдельно для стопа:

```python
atr_arr = _atr(df, atr_period)
atr_stop = _atr(df, atr_stop_period) if atr_stop_period != atr_period else atr_arr
```

(`_atr` здесь — импортированная `_wilder_atr` из `indicators.py`.)

При входе в позицию (`src/backtest/atr_breakout_runner.py:201–206`) запоминается ATR именно момента входа:

```python
entry_atr = atr_stop[i - 1]   # ATR на баре T-1, перед заполнением сигнала
entry_price = open_[i] * (1.0 + _SLIPPAGE)
```

Затем на каждом баре пока позиция открыта (`src/backtest/atr_breakout_runner.py:209–211`) считается стоп:

```python
stop_price = entry_price - entry_atr * atr_stop_mult
if low[i] <= stop_price:
    exit_price = stop_price * (1.0 - _SLIPPAGE)
```

Это и есть **intrabar stop (внутрибарный стоп)**: если минимум текущей свечи оказался ниже или равен `stop_price` — позиция закрывается по цене `stop_price` (с небольшим проскальзыванием, см. ниже). Бот не ждёт закрытия свечи, чтобы убедиться — достаточно того, что минимум касается стопа.

В бэктесте `entry_atr` **фиксируется один раз** в момент входа и больше не меняется: `stop_price` остаётся постоянной на всё время сделки (`src/backtest/atr_breakout_runner.py:196–209`).

#### Live-стратегия ATR Breakout — стоп плавающий

В живой стратегии стоп работает **принципиально иначе**. Объект `self._atr_stop_calc` — это инкрементальный вычислитель ATR класса `_WilderATR`, который обновляется **на каждом новом баре** (`src/signalgen/atr_breakout_strategy.py:249–250`):

```python
if self._atr_stop_calc is not None:
    self._atr_stop_calc.update(high, low, close)
```

Затем значение ATR **текущего бара** считывается как `atr_stop_curr` (`src/signalgen/atr_breakout_strategy.py:254–258`):

```python
atr_stop_curr = (
    self._atr_stop_calc.current
    if self._atr_stop_calc is not None
    else self._atr_signal.current
)
```

И именно это **текущее** значение ATR используется для проверки стопа (`src/signalgen/atr_breakout_strategy.py:297,307`):

```python
atr_val = atr_stop_curr          # ATR текущего бара T
...
float(bar.low) <= self._entry_close - self._atr_stop_mult * atr_val
```

**Что это означает на практике**: точка привязки `entry_close` фиксируется в момент входа и не меняется. Но множитель `atr_val` обновляется каждый бар вместе с реальной волатильностью рынка. Когда рынок становится более бурным после входа — ATR растёт, и стоп **опускается дальше** от цены входа. Когда рынок успокаивается — ATR падает, и стоп подтягивается ближе.

Пример симуляции (atr_period=21, atr_stop_mult=1.5, entry_close=65 000 USD):

| Бар после входа | ATR (текущий) | Уровень стопа (entry_close − 1.5×ATR) |
|---|---|---|
| +1 | 514 | 65 000 − 771 = **64 229 USD** |
| +2 | 662 | 65 000 − 993 = **64 007 USD** |
| +3 | 779 | 65 000 − 1 169 = **63 831 USD** |
| +4 | 853 | 65 000 − 1 280 = **63 720 USD** |

Стоп плывёт вместе с волатильностью. Это принципиально отличает поведение live-бота от бэктеста: если волатильность после входа вырастает, live-стоп отодвигается дальше и позиция может переживать более глубокие [[max-drawdown-winrate-rr|просадки]], чем показал бэктест. Трейдеру важно это понимать при оценке реального риска на живом счёте.

### Шаг 4. Два периода ATR — зачем разные?

Параметры LOCKED для BTCUSDT 4H (`src/signalgen/atr_breakout_strategy.py:57–63` и `src/backtest/atr_breakout_runner.py:71–77`):

| Параметр | Значение | Роль |
|---|---|---|
| `atr_period` | 9 свечей | «Быстрый» ATR для определения пробоя (сигнал входа) |
| `atr_breakout_mult` | 2.5× | Размер пробоя в ATR-единицах |
| `atr_stop_period` | 21 свеча | «Медленный» ATR для ширины стопа |
| `atr_stop_mult` | 1.5× | Расстояние стопа от точки входа в ATR-единицах |

Почему два периода? Короткий ATR (9) быстро улавливает изменения — нужен для чувствительного сигнала входа. Длинный ATR (21) медленнее меняется — даёт стопу «стабильность»: не прыгает каждый бар и не выбивает позицию случайными всплесками.

## Формулы и расчёты

### True Range

```text
TR[i] = max(
    high[i] - low[i],
    |high[i] - close[i-1]|,
    |low[i]  - close[i-1]|
)
```

Простыми словами: «насколько широко качнулась цена за этот бар с учётом того, где она была вчера». Берём максимум из трёх вариантов, потому что любой из них может быть «самым широким» в зависимости от ситуации.

Соглашение для первого бара: `close[i-1]` нет → берём `close[0]`, и тогда `TR[0] = high[0] - low[0]`.

(Реализация: `src/backtest/indicators.py:37–43`)

### Wilder ATR: seed + рекурсия

```text
ATR[period-1] = mean(TR[0], TR[1], ..., TR[period-1])   ← seed (SMA)
ATR[i]        = (ATR[i-1] × (period-1) + TR[i]) / period ← рекурсия (i ≥ period)
```

Простыми словами:
- **Seed**: первое значение ATR = обычное среднее первых `period` значений TR. Как «нулевая точка» для разгона.
- **Рекурсия**: каждый следующий ATR = смесь предыдущего (с весом `(period-1)/period`) и нового TR (с весом `1/period`). Для period=9: новый бар влияет на ATR с весом 1/9 ≈ 11%.

Математически это эквивалентно «экспоненциальному скользящему среднему» со специфическим коэффициентом сглаживания α = 1/period. Именно поэтому Wilder ATR иногда называют «RMA» (Running Moving Average).

(Реализация: `src/backtest/indicators.py:48–50`, зеркало: `src/backtest/supertrend_runner.py:93–95`)

### Формула стоп-лосса

**Бэктест** (стоп фиксированный — ATR захвачен в момент входа):
```text
stop_price = entry_price - entry_atr × atr_stop_mult
```

**Live-стратегия** (стоп плавающий — ATR пересчитывается каждый бар):
```text
stop_price = entry_close - current_atr × atr_stop_mult
```

Простыми словами: «отойди от точки привязки вниз на N стандартных шумов рынка». Если рынок обычно движется на 100 долларов за 4-часовую свечу (ATR=100), и `atr_stop_mult=1.5`, стоп поставится на 150 долларов ниже. В бэктесте это «150 долларов по ATR на дату входа»; в live — «150 долларов по ATR прямо сейчас».

(Бэктест: `src/backtest/atr_breakout_runner.py:209`; Live: `src/signalgen/atr_breakout_strategy.py:297–307`)

## Примеры / сценарии

### Сценарий А: BTCUSDT 4H, тихий рынок

Предположим, последние 9 свечей BTCUSDT имели диапазоны около 500 USD каждая. ATR≈500 USD.

- Бот покупает BTCUSDT по цене 65 000 USD (open следующего бара после сигнала).
- `entry_atr` = ATR стоп-периода (21 свечей) в момент сигнала = допустим, 480 USD.
- `stop_price` = 65 000 − 480 × 1.5 = 65 000 − 720 = **64 280 USD**.
- Если следующая свеча коснётся минимума 64 270 — стоп сработает, выход по 64 280 × (1 − 0.0005) ≈ 64 248 USD.

### Сценарий Б: тот же рынок, но волатильность выросла

Теперь ATR вырос до 1 200 USD (бурный рынок, крупные свечи).

- Бот покупает по 65 000 USD.
- `stop_price` = 65 000 − 1200 × 1.5 = 65 000 − 1800 = **63 200 USD**.
- Стоп дальше. Это разумно: когда рынок «дышит» шире, случайные откаты тоже шире, и ставить стоп близко — значит гарантировать ложные срабатывания.

### Сценарий В: прогрев (первые 24 бара, параметры BTCUSDT 4H)

Бот только запустился. Параметры для BTCUSDT 4H: `atr_period=9`, `atr_stop_period=21`. Прогрев составляет:

```text
warmup = max(atr_period, atr_stop_period) + 3 = max(9, 21) + 3 = 24 бара
```

Цикл входа в бэктесте начинается с `range(warmup, n)`, то есть с индекса 24 (`src/backtest/atr_breakout_runner.py:183,198`). Первая потенциальная сделка возможна **не раньше 25-й свечи (индекс 24)**. Даже если ATR-массив имел бы значение раньше — цикл просто до него не доходит.

Почему 24, а не 9? Потому что стоп-ATR считается по периоду 21, и NaN-guard `isnan(atr_stop[i-1])` на строках 201–203 дополнительно блокирует вход, пока стоп-ATR не готов. Граница `warmup=24` гарантирует наличие стабилизированного ATR с запасом перед первой сделкой.

## Семейства ATR в проекте — почему их несколько

В кодовой базе существует **четыре семейства** ATR. Это сделано намеренно, и каждое выполняет свою роль. Их нельзя смешивать или заменять друг другом.

### Семейство 1: TA-Lib `ATR()` (через обёртку `atr()`)

Функция `atr()` в `src/signalgen/indicators.py:67–81` вызывает `talib.ATR()` (описание обёртки — в [[technical-indicators|справочнике индикаторов]]). Её используют живые стратегии, работающие через replay-engine:

- `mean_reversion_strategy.py:31` — live Mean Reversion
- `donchian_strategy.py:29` — live Donchian
- `strategy.py:17` — live EMA Crossover
- `volume_breakout_strategy.py:46,217` — live Volume Breakout (`_compute_wilder_atr` — обёртка над той же `atr()`)

### Семейство 2: Ручная рекурсия Уайлдера (пакетная, векторная)

Тот же алгоритм (SMA-seed + рекурсия), но реализован вручную на numpy без TA-Lib. Три реализации:

| Функция | Файл | Кому служит |
|---|---|---|
| `_wilder_atr(df, period)` | `src/backtest/indicators.py:17` | ATR Breakout бэктест, Volume Breakout бэктест |
| `wilder_atr(arrays)` | `src/signalgen/indicators.py:84` | Тесты паритета |
| `_wilder_atr_vectorized` | `src/backtest/supertrend_runner.py:73` | Supertrend бэктест |

### Семейство 3: Инкрементальная рекурсия Уайлдера (потоковая, O(1) на бар)

Тот же алгоритм, но обновляется по одной свече за раз — для живых стратегий, которые получают данные в реальном времени:

| Класс / метод | Файл | Кому служит |
|---|---|---|
| `_WilderATR` (класс) | `src/signalgen/atr_breakout_strategy.py:135` | Live ATR Breakout |
| `_update_atr()` (метод) | `src/signalgen/supertrend_strategy.py:208` | Live Supertrend |

### Семейство 4: pandas EWM (без SMA-seed)

Формула `ewm(alpha=1/period, adjust=False)` — другое сглаживание, без «стартового разгона». Используется в `src/backtest/indicators.py:107` внутри `calculate_indicators()` для стратегий [[replay-engine-bar-by-bar|replay-движка]] (EMA Crossover, Mean Reversion, Donchian, Volume Breakout в бэктесте через replay).

**Почему нельзя использовать одно семейство везде?** У каждого потребителя свои требования к интерфейсу и жизненному циклу данных. Живая стратегия получает свечи по одной и не может пересчитывать весь массив заново — ей нужен инкрементальный вариант (Семейство 3). Бэктест получает сразу весь массив — ему удобнее пакетный вариант (Семейство 2). Семейство 4 обслуживает replay_engine для стратегий, у которых параметры были зафиксированы именно с таким сглаживанием ([[walk-forward-analysis|anti-snooping]]: менять нельзя).

**Расхождение в ~1.4%**: между Семейством 1 (TA-Lib `ATR()`) и Семейством 2/3 (ручная рекурсия Уайлдера) наблюдается расхождение около 1.4% для типичных периодов. Это объясняется разным способом инициализации в TA-Lib. Расхождение известно, задокументировано в `src/signalgen/indicators.py:97–99`, и принято намеренно: каждая стратегия зафиксирована на своём семействе anti-snooping. Расхождение между Семейством 4 (pandas EWM) и другими семействами существует, но не имеет задокументированной численной оценки в коде.

## Подводные камни / что важно понимать

**1. Период прогрева (warm-up) — не «9 свечей», а «24 бара» для BTCUSDT 4H.**
Для `atr_stop_period=21` прогрев в бэктесте составляет `warmup = max(9, 21) + 3 = 24 бара`. Первая сделка возможна только начиная с индекса 24 (25-я свеча). Это верно как для бэктеста (`src/backtest/atr_breakout_runner.py:183`), так и для live-стратегии (класс `ATRBreakoutStrategy`, строка `src/signalgen/atr_breakout_strategy.py:206`). Значение `period=9` сигнального ATR не определяет общий warmup — определяет `atr_stop_period`.

**2. Стоп в бэктесте — фиксированный, в live — плавающий. Это принципиальное различие.**
В бэктесте `entry_atr` запоминается в момент входа и не меняется всё время сделки (`src/backtest/atr_breakout_runner.py:196–209`). В live-стратегии стоп пересчитывается **каждый бар** по текущему ATR через `self._atr_stop_calc.current` (`src/signalgen/atr_breakout_strategy.py:254,297,307`). Если волатильность после входа растёт, live-стоп опускается дальше от цены входа и позиция переживает более глубокие просадки, чем показал бэктест. Это отличает нас от «трейлинг-стопа» (который следует за ценой вверх), но создаёт асимметрию live/backtest по компоненту ATR.

**3. Проскальзывание (slippage) при срабатывании стопа.**
Выход по стопу идёт не по `stop_price`, а по `stop_price × (1 - SLIPPAGE)`, где `SLIPPAGE = 0.0005` (0.05%) (`src/backtest/atr_breakout_runner.py:38–39,211`). Это реалистичное допущение: в реальном рынке, когда цена пробила стоп, исполнение будет чуть хуже стопа.

**4. Приоритет выходов — стоп проверяется раньше обратного пробоя.**
Если на одной свече одновременно сработали и ATR-стоп, и обратный сигнал пробоя — бэктест и live-стратегия используют ATR-стоп как более приоритетный (`src/backtest/atr_breakout_runner.py:209–220`, `if low[i] <= stop_price` идёт до `elif exit_[i]`). Это важно для точного соответствия бэктеста и production.

**5. В Supertrend ATR-стоп не используется.**
Supertrend в бэктесте выходит только по флипу тренда (BULL→BEAR), а не по ATR-стопу. Комментарий в коде (`src/backtest/supertrend_runner.py:184–185`) прямо указывает: «ATR stop: not implemented». ATR там нужен только для расчёта полос Supertrend, а не как защитный стоп.

**6. Семейство 4 (pandas EWM) не использует SMA-seed.**
Pandas `ewm(alpha=1/period, adjust=False)` начинает с первого же значения ряда (без seed). Это означает, что первый ATR появляется уже на 1-й свече, но он менее точный (нет разгона). Этот вариант обслуживает replay_engine для стратегий EMA Crossover, Mean Reversion и Donchian — их параметры были зафиксированы именно с таким ATR.

# Стратегия ATR breakout: пробой на росте волатильности

**TL;DR:** Эта страница описывает, как бот **тестирует** стратегию ATR-пробоя на исторических данных: как устроен прогон, как считается результат, как зафиксированы параметры и как проводится честная WFA-валидация по 10 комбо пар и таймфреймов. Для описания логики торговли в реальном времени (on_bar) — смотри [[02-стратегии/atr-breakout-strategy]].

## Простыми словами

Представьте, что рынок каждую свечу «дышит» — иногда спокойно, иногда резко. **[[atr-indicator|ATR]]** (Average True Range, средний истинный диапазон) — это средняя ширина этого «дыхания» за N последних свечей. Когда за одну свечу цена вырастает сильно больше обычного «дыхания» — это называется **пробоем** (breakout). Стратегия говорит: такой резкий прыжок — часто начало движения, а не случайность. Значит, стоит покупать.

Чтобы убедиться, что стратегия работает не только «на бумаге», нужно прокатить её по истории и посмотреть: зарабатывала ли она раньше? Вот для этого существует бэктест-раннер `atr_breakout_runner.py`.

Два важных момента:

1. **Параметры зафиксированы заранее** (до запуска валидации) — это так называемый **антиснупинг**-принцип (anti-snooping): мы не подбираем лучшие числа «задним числом», глядя на результаты. Именно поэтому итоговая честность результата проверяется через [[deflated-sharpe-ratio|DSR]] (поправку на «лучший из многих»). Числа выбраны автоисследованием, записаны в код и закреплены в специальных решениях (ADR 0060 и ADR 0061). Изменить их без нового ADR нельзя.

2. **Прогон — не WFA**: функция `run_atr_breakout_backtest` делает единый прогон по всей истории (без разбивки на обучающий и тестовый периоды). Это нужно для дашборда — красивого графика капитала. WFA-версия с настоящей валидацией — это отдельная функция `_run_atr_breakout_wfa`.

## Как это работает у нас

### Шаг 1. Зафиксированные параметры — «замки» для честности

Словарь `ATR_BREAKOUT_LOCKED_PARAMS_BY_COMBO` содержит **10 наборов параметров** — по одному для каждой комбинации символа и таймфрейма. Каждый набор зафиксирован независимо. Это похоже на то, что у каждого замка свой ключ: параметры для BTC 4H не применяются к ETH 1H и наоборот.

(src/backtest/atr_breakout_runner.py:71–132)

Полная таблица зафиксированных параметров:

| Пара / Таймфрейм | `atr_period` | `atr_breakout_mult` | `atr_stop_period` | `atr_stop_mult` |
|---|---|---|---|---|
| BTCUSDT / 4H | 9 | 2.5 | 21 | 1.5 |
| BTCUSDT / 1H | 9 | 2.5 | 21 | 3.0 |
| BTCUSDT / 15M | 9 | 3.0 | 14 | 3.0 |
| BTCUSDT / 1D | 9 | 1.0 | 9 | 3.0 |
| ETHUSDT / 4H | 14 | 2.5 | 14 | 1.5 |
| ETHUSDT / 1H | 14 | 2.5 | 21 | 1.5 |
| ETHUSDT / 15M | 9 | 3.0 | 14 | 2.0 |
| SOLUSDT / 4H | 21 | 1.5 | 9 | 2.0 |
| SOLUSDT / 1H | 9 | 2.0 | 21 | 3.0 |
| SOLUSDT / 15M | 21 | 2.5 | 9 | 3.0 |

Заметьте: у BTCUSDT 1D порог пробоя `atr_breakout_mult = 1.0` — то есть достаточно движения на один ATR. Дневные свечи итак крупные, поэтому порог ниже.

**Почему параметры «заблокированы»?** Это защита от «переобучения под историю» (overfitting). Параметры выбраны автоматическим исследованием (`scripts/autoresearch_endless.py`, файл `data/autoresearch_endless/best_per_combo.json`) и записаны в код один раз. Если их менять после просмотра результатов — это был бы обман: числа стали бы «знать» прошлое. ADR 0060 закрепляет параметры BTC 4H, ADR 0061 — остальные 9 комбо.

### Шаг 2. Загрузка данных — `_load_parquet_df`

Для каждого комбо (символ, таймфрейм) зарегистрирован конкретный файл parquet в словаре `PARQUET_BY_COMBO`.

(src/backtest/atr_breakout_runner.py:54–65)

Пример: для BTCUSDT 4H — `data/BTCUSDT_4h.parquet`. Функция `_load_parquet_df` читает файл, нормализует название столбца с временной меткой (поддерживает оба формата: `ts` от Binance и `time` от Bybit), сортирует по времени и фильтрует по запрошенному диапазону дат. Более полно загрузка данных и предполётная проверка качества описаны в [[single-symbol-wfa-and-data-loading|загрузке данных для WFA]].

(src/backtest/atr_breakout_runner.py:259–296)

Все данные охватывают период 2023-01-01 — 2026-04-26 (≈3.3 года), равномерно для всех символов.

### Шаг 3. Расчёт ATR по методу Уайлдера — `_wilder_atr`

Стратегия использует два ATR с разными периодами: один — для детектирования сигнала пробоя (более быстрый, `atr_period`), другой — для расчёта стоп-уровня (может быть медленнее, `atr_stop_period`). Это не ошибка и не дублирование: разные задачи требуют ATR с разной «памятью».

ATR считается через функцию `_wilder_atr` из `src/backtest/indicators.py` (строки 17–51). [[wilder-atr-and-stops|Метод Уайлдера]] — это специальная формула сглаживания: первое значение — простое среднее за `period` баров (SMA-«семя»), потом каждое следующее = предыдущее × (period−1)/period + текущий TR × 1/period. Первые `period−1` значений — NaN (прогревочный период).

(src/backtest/atr_breakout_runner.py:35, src/backtest/indicators.py:17–51)

Важно: если `atr_stop_period` совпадает с `atr_period`, массив ATR вычисляется только один раз — переиспользуется тот же объект, без повторного расчёта.

(src/backtest/atr_breakout_runner.py:178)

### Шаг 4. Главная функция прогона — `_backtest_single`

Это «сердце» бэктеста — функция, которая проходит по всем барам и принимает торговые решения. Она реализует [[research-kernel-execution-model|отдельное research-ядро исполнения]] (последовательно-аддитивный PnL), общее для всех стратегий-пробоев.

(src/backtest/atr_breakout_runner.py:144–256)

**Прогревочный период.** Перед тем как начать торговать, функция выжидает:

```python
warmup = max(atr_period, atr_stop_period) + 3
```

Это количество первых баров, которые пропускаются. Нужно, чтобы оба ATR-массива успели накопить достаточно данных (не NaN). Плюс 3 «запасных» бара.

(src/backtest/atr_breakout_runner.py:183)

**Условие входа в сделку** (формируется на баре `i-1`, исполняется по цене открытия бара `i`):

```
close[i-1] > close[i-2] + atr_breakout_mult × atr[i-2]
```

Переводя на русский: закрытие предыдущей свечи должно быть выше закрытия позапрошлой свечи минимум на `atr_breakout_mult` размеров ATR (в момент позапрошлой свечи). Если условие выполнено — ставится флаг `entry[i] = True`.

(src/backtest/atr_breakout_runner.py:185–188)

**Условие обратного пробоя** (тоже формируется на баре `i-1`, используется для выхода при исполнении на баре `i`):

```
close[i-1] < close[i-2] - atr_breakout_mult × atr[i-2]
```

Симметрично сигналу входа, но вниз. Означает: рынок так же резко упал, как до этого вырос.

(src/backtest/atr_breakout_runner.py:189–191)

**Исполнение сделок (торговый цикл).** Функция идёт по барам повторно и управляет позицией:

- **Вход:** если нет позиции и стоит флаг `entry[i]`, бот «покупает» по цене `open[i] × (1 + slippage)`. Одновременно запоминает ATR-стоп-период на момент входа: `entry_atr = atr_stop[i-1]`.
- **ATR-стоп (приоритет 1):** если есть позиция и `low[i] ≤ stop_price`, где `stop_price = entry_price − entry_atr × atr_stop_mult` — выход по цене `stop_price × (1 − slippage)`. Стоп зафиксирован в момент входа и не меняется в течение сделки.
- **Обратный пробой (приоритет 2):** только если ATR-стоп не сработал — проверяется флаг `exit_[i]`. Выход по цене `open[i] × (1 − slippage)`.

(src/backtest/atr_breakout_runner.py:199–221)

**Ключевой нюанс:** ATR-стоп всегда проверяется **раньше** обратного пробоя. Это точная копия порядка из исследовательского кода — намеренно, чтобы результаты бэктеста совпадали с оригинальным исследованием.

**Закрытие на последнем баре.** Если на момент окончания истории позиция ещё открыта — она закрывается по цене закрытия последнего бара (mark-to-market), со скидкой на slippage.

(src/backtest/atr_breakout_runner.py:223–228)

### Шаг 5. Затраты на сделку

Каждая сделка несёт два вида затрат, зафиксированных как константы:

| Затрата | Значение | Что это |
|---|---|---|
| `_COMMISSION_TAKER` | 0.001 (0.1%) | Биржевая комиссия — взимается при входе и выходе (итого 0.2% с оборота) |
| `_SLIPPAGE` | 0.0005 (0.05%) | Неблагоприятное проскальзывание — цена входа хуже на 0.05%, цена выхода тоже |

(src/backtest/atr_breakout_runner.py:38–39)

Итоговый P&L каждой сделки:

```
pnl_net = (exit_price − entry_price) / entry_price − 2 × 0.001
```

(src/backtest/atr_breakout_runner.py:213, 219, 227)

### Шаг 6. Расчёт итоговых метрик

После прогона всех сделок функция возвращает четыре числа:

- **n_trades** — количество сделок.
- **total_pnl_pct** — сумма всех `pnl_net × 100` (суммарный результат в процентах). Важно: это не компаундинг (не «проценты от нарастающего капитала»), а простая сумма.
- **win_rate** — доля прибыльных сделок.
- **sharpe** — коэффициент Шарпа по методу per-trade (подробнее — в следующем разделе о формулах).

(src/backtest/atr_breakout_runner.py:230–255)

### Шаг 7. Публичная обёртка — `run_atr_breakout_backtest`

Это основная функция, которую вызывает дашборд. Она:

1. Берёт зафиксированные параметры из `ATR_BREAKOUT_LOCKED_PARAMS_BY_COMBO` (или принимает явные параметры через аргумент `params=`).
2. Загружает данные через `_load_parquet_df`.
3. Запускает `_backtest_single`.
4. Строит `equity_curve` — список накопленного P&L по каждой сделке в процентах, с временны́ми метками, чтобы дашборд мог отрисовать график.
5. Строит `trade_markers` — словарь с метками каждой сделки: время входа/выхода, цены, P&L. Нужен для отображения значков входов и выходов на графике.
6. Упаковывает всё в стандартную обёртку `build_research_runner_envelope`.

(src/backtest/atr_breakout_runner.py:299–413)

### Шаг 8. WFA-версия — `_run_atr_breakout_wfa`

Это «честная» проверка ([[walk-forward-analysis|walk-forward анализ]]): история делится на 5 скользящих блоков, стратегия тестируется на каждом «невиданном» тестовом блоке по отдельности.

(src/backtest/atr_breakout_runner.py:416–474)

Для аtr_breakout параметры уже зафиксированы — поэтому обучающая часть каждого блока **не используется** для настройки: параметры из `ATR_BREAKOUT_LOCKED_PARAMS_BY_COMBO` берутся такими, как есть. WFA здесь нужна только для расчёта DSR и MC с правильной out-of-sample статистикой.

Параметры WFA зависят от таймфрейма:

| Таймфрейм | `train_bars` | `test_bars` | `k_folds` | `embargo_bars` | Минимум баров |
|---|---|---|---|---|---|
| 4H, 1D (низкочастотный) | 1500 | 250 | 5 | 20 | 2770 |
| 15M, 1H (высокочастотный) | 2000 | 500 | 5 | 20 | 4520 |

(src/backtest/research_wfa.py:51–77)

WFA-прогон запускается через `run_research_wfa` с параметром `n_trials=10` — семейство atr_breakout считается как 10 гипотез (10 комбо), что влияет на поправку множественного тестирования при расчёте [[deflated-sharpe-ratio|DSR]] (история Шарпов по всем прогонам хранится в [[cross-trial-log|CrossTrialLog]]).

(src/backtest/atr_breakout_runner.py:471)

Порог прохождения по [[deflated-sharpe-ratio|DSR]]: `≥ 0.95`. Порог по [[sharpe-sortino-metrics|Шарпу]]: `≥ 0.7`. Порог [[monte-carlo-permutation|MC]]: `p ≤ 0.05`. Минимум сделок: 50. Полный список порогов и логика вердикта — на странице [[acceptance-gates-t1-t6|ворот приёмки T1–T6]].

(src/backtest/research_wfa.py:37–41)

## Формулы и расчёты

### Коэффициент Шарпа по методу per-trade

Стандартный Шарп считается по дням или барам. Здесь — по сделкам, с пересчётом на год:

```
Sharpe = (mean(pnl_net) / std(pnl_net, ddof=1)) × sqrt(trades_per_year)

trades_per_year = bars_per_year / mean_holding
```

Расшифровка простыми словами:
- `mean(pnl_net)` — средний результат одной сделки.
- `std(pnl_net, ddof=1)` — разброс результатов (нестабильность).
- Делим среднее на разброс — получаем «среднюю прибыль в единицах риска».
- Умножаем на `sqrt(trades_per_year)` — чтобы привести к годовому масштабу.

`bars_per_year` — количество баров в году для данного таймфрейма (4H → 2191, 1H → 8766, 15M → 35064, 1D → 365). `mean_holding` — средняя продолжительность сделки в барах.

(src/backtest/atr_breakout_runner.py:241–246)

Если нет сделок или нулевой разброс — Sharpe = NaN. В обёртке для дашборда NaN заменяется на 0.0.

### Equity curve (кривая капитала)

Строится как нарастающая сумма pnl_pct каждой сделки, умноженная на 100 (чтобы получить проценты):

```
equity[0] = 0.0
equity[k] = equity[k-1] + trade[k].pnl_pct × 100
```

(src/backtest/atr_breakout_runner.py:371–378)

## Примеры / сценарии

### Сценарий A: одиночный прогон BTC 4H (дашборд)

Запрос: `run_atr_breakout_backtest(symbol="BTCUSDT", interval="240", start_date=date(2023,1,1), end_date=date(2026,4,26))`.

1. Параметры берутся из `ATR_BREAKOUT_LOCKED_PARAMS_BY_COMBO[("BTCUSDT","240")]`: `atr_period=9`, `mult=2.5`, `atr_stop_period=21`, `atr_stop_mult=1.5`.
2. Загружается `data/BTCUSDT_4h.parquet`, фильтруется по дате.
3. `warmup = max(9, 21) + 3 = 24` — первые 24 бара пропускаются.
4. ATR[9] быстрый и ATR[21] медленный вычисляются по всему ряду.
5. Идём по барам, ищем `close[i-1] > close[i-2] + 2.5 × atr[i-2]` для входов.
6. На каждом входе фиксируем `entry_atr = atr_stop[i-1]`, `stop_price = entry_price − 1.5 × entry_atr`.
7. Проверяем стоп (priorité 1) и обратный пробой (приоритет 2) на каждом баре.
8. Строим equity_curve и trade_markers → отдаём в дашборд.

### Сценарий B: стоп срабатывает раньше обратного пробоя

Предположим: вошли по open[50] = 30 100 USDT, `entry_atr = 500`, `stop_price = 30 100 − 1.5 × 500 = 29 350`. На баре 55 `low[55] = 29 300` — ниже стоп-цены. Выход немедленно по `29 350 × (1 − 0.0005) = 29 335` — не ждём закрытия свечи, не проверяем обратный пробой. Это «intrabar»-стоп.

На том же баре 55 мог быть и сигнал обратного пробоя — но он уже игнорируется, потому что позиция уже закрыта по стопу.

### Сценарий C: последний бар, позиция открыта

Если история заканчивается, а позиция ещё открыта — бот «вынужден» закрыться: `exit_price = close[-1] × (1 − 0.0005)`. Это mark-to-market: мы оцениваем позицию по последней известной цене, как если бы закрылись прямо сейчас. Это не реальная сделка — просто честный способ завершить расчёт.

## Подводные камни / что важно понимать

**1. Это не WFA — это одиночный прогон для дашборда.** `run_atr_breakout_backtest` прогоняет стратегию по всей истории сразу. Хороший результат здесь — **не** доказательство, что стратегия будет работать в будущем. Доказательство даёт только `_run_atr_breakout_wfa` с пятью независимыми тестовыми окнами.

**2. Параметры нельзя менять «на лету».** Если передать `params=None` для незарегистрированного комбо — функция выбросит `ValueError`. Добавить новое комбо можно только в коде через новый ADR. Это не ограничение, а защита от случайного нарушения антиснупинг-дисциплины.

**3. P&L суммируется, а не компаундируется.** Результат `total_pnl_pct` — это сумма процентов отдельных сделок, как если бы каждая торговалась с одинаковым базовым капиталом. Реальный портфельный P&L был бы другим. Это унаследованная модель из исследовательского кода (ADR 0064), сознательно сохранённая для точности сравнения.

**4. Стоп-уровень фиксируется при входе.** `entry_atr` запоминается в момент входа в сделку и **не обновляется** в течение позиции. В реальной торговле (live, `on_bar`) стоп-уровень пересчитывается каждый бар. Это намеренное расхождение: бэктест воспроизводит оригинальное исследование «дословно», а live-логика устроена иначе. Подробнее — [[02-стратегии/atr-breakout-strategy]].

**5. Обучающий слот WFA не используется для обучения.** Поскольку параметры зафиксированы заранее, в WFA-режиме обучающий срез каждого фолда просто отбрасывается — параметры не настраиваются. `train_bars` влияет только на то, где начинается тестовое окно внутри данных. Это сознательный выбор для стратегий с «замороженными» параметрами.

**6. ATR-стоп всегда проверяется первым.** Порядок проверок `low[i] ≤ stop_price` **до** `exit_[i]` — это не случайность, а точная копия порядка из исследования. Менять его нельзя: изменится разбивка сделок и, соответственно, все метрики.

**7. «Семейство 10 гипотез».** В WFA параметр `n_trials=10` означает, что при расчёте DSR применяется поправка на множественное тестирование для 10 комбо одновременно. Это делает порог более строгим: недостаточно просто хорошо работать на одном комбо — нужно доказать, что результат не случаен из 10 попыток.

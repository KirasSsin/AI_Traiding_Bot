# Векторный бэктест (vector_backtest): быстрая приблизительная оценка

**TL;DR:** Быстрый движок для предварительной оценки стратегии — без SL/TP и детального учёта сделок. Даёт грубый ответ за секунды, но не пригоден для финального вердикта. Для точного результата используется [[replay-engine-bar-by-bar|replay_engine]].

## Простыми словами

Представьте, что вы хотите быстро прикинуть, стоит ли вообще дальше изучать какую-то торговую идею. Для этого вам не нужен бухгалтерский отчёт с каждой сделкой — достаточно простого расчёта «на салфетке»: зарабатывала ли стратегия деньги на истории или нет.

Именно это делает **векторный бэктест** (`VectorBacktester`). Он берёт готовые сигналы (купить / продать / держать) и за один проход по всем данным сразу — без цикла бар за баром — считает примерную доходность. Это как быстро просмотреть трек расходов в банковском приложении, не открывая каждый чек: общая картина видна, но некоторые детали упущены.

**Главное отличие от «настоящего» бэктеста** (`replay_engine`): векторный движок не знает о стоп-лоссах, тейк-профитах и точных ценах исполнения внутри бара. Он просто смотрит на закрытие каждого бара и считает, сколько заработала или потеряла позиция. За это — скорость.

**Когда применяется:** на ранней стадии исследования, когда нужно быстро отсеять заведомо плохие идеи. Финальный вердикт выносит `replay_engine` через [[walk-forward-analysis|WFA (Walk-Forward Analysis)]].

## Как это работает у нас

Весь движок — это один класс `VectorBacktester` с методом `run()`. Разберём по шагам.

### Шаг 0. Создание объекта

```python
# src/backtest/vector_backtest.py:15–29
bt = VectorBacktester(
    df,                   # DataFrame с колонками close и signal
    initial_capital=10000.0,  # начальный капитал в USDT
    maker_fee=0.001,          # комиссия 0.1% (мейкер-комиссия)
    bars_per_year=8760,       # количество баров в году для 1H-данных
)
```

`bars_per_year` — параметр для правильного расчёта Sharpe Ratio (об этом ниже). Для разных таймфреймов (временных интервалов баров) он разный: `60` (1H) = 8760, `15` (15M) = 35040. Если передать неверное значение — Sharpe будет посчитан неправильно. `(src/backtest/vector_backtest.py:21–29)`

### Шаг 1. Проверка и форвард-филл сигнала

```python
# src/backtest/vector_backtest.py:37–42
if "signal" not in self.df.columns:
    raise ValueError("DataFrame must contain a 'signal' column.")

self.df["position"] = self.df["signal"].replace(0, np.nan).ffill().fillna(0)
```

Входной DataFrame обязан содержать колонку `signal` со значениями: `1` (купить/держать лонг), `-1` (продать/держать шорт), `0` (нет сигнала). Как из индикаторов рождается этот сигнал — см. [[indicators-and-signals]] и [[signal-architecture]].

**Форвард-филл (forward fill) — заполнение вперёд:** нулевой сигнал означает «держи предыдущую позицию». Например: сигнал пришёл на баре 5 (=1), потом на барах 6 и 7 сигнал = 0 — это значит «продолжай держать позицию». Техника: ноль заменяется на `NaN`, затем `ffill()` копирует последнее ненулевое значение вперёд. `(src/backtest/vector_backtest.py:42)`

> Примечание: pandas 3.x убрал старый способ (`replace(..., method="ffill")`). В коде используется цепочка `.replace(0, np.nan).ffill()` как совместимый способ. `(src/backtest/vector_backtest.py:41)`

### Шаг 2. Логарифмические доходности актива

```python
# src/backtest/vector_backtest.py:44–45
self.df["asset_returns"] = np.log(self.df["close"] / self.df["close"].shift(1))
```

**Логарифмическая доходность (log return)** — способ измерить, насколько изменилась цена. Вместо обычного процента (`(101 − 100) / 100 = 1%`) берётся логарифм отношения цен. Это математически удобнее для суммирования доходностей за несколько баров.

Для каждого бара T считается: `ln(close[T] / close[T-1])`. Для первого бара — `NaN` (сравнивать не с чем).

### Шаг 3. Доходность стратегии со сдвигом позиции

```python
# src/backtest/vector_backtest.py:47–48
self.df["strategy_returns"] = self.df["position"].shift(1) * self.df["asset_returns"]
```

Ключевая деталь: `position.shift(1)` — позиция сдвинута на один бар назад. Это означает, что доходность бара T рассчитывается исходя из позиции, принятой **на предыдущем баре** (T-1). Это защита от **look-ahead bias** (взгляда в будущее).

**Look-ahead bias** — это распространённая ошибка в бэктестах: если использовать сигнал бара T для расчёта его же доходности, получается, что бот «знал закрытие заранее». В реальности сигнал становится известен только после закрытия бара, и торговля возможна лишь на следующем баре. `(src/backtest/vector_backtest.py:47–48)`

### Шаг 4. Вычет комиссии при смене позиции

```python
# src/backtest/vector_backtest.py:51–52
self.df["trades"] = self.df["position"].diff().fillna(0).abs()
self.df["strategy_returns"] -= self.df["trades"] * self.maker_fee
```

Комиссия списывается только когда позиция меняется. Размер изменения считается как модуль разницы (`|position.diff()|`):

- Если позиция меняется с `+1` (лонг) на `−1` (шорт), изменение = `|−1 − 1| = 2` → вычитается `2 × 0.001 = 0.002` (0.2% от условного номинала).
- Если позиция не меняется (например, остаётся `+1`), изменение = `0` → комиссии нет.

Таким образом, каждая реальная сделка (вход + выход) стоит 0.1% в каждую сторону (`maker_fee = 0.001`). `(src/backtest/vector_backtest.py:51–52)`

### Шаг 5. Накопленные доходности и кривая капитала

```python
# src/backtest/vector_backtest.py:55–56
self.df["cumulative_returns"] = self.df["strategy_returns"].cumsum().apply(np.exp)
self.df["equity_curve"] = self.initial_capital * self.df["cumulative_returns"]
```

Поскольку доходности логарифмические, их суммируют, а затем применяют `exp()` (обратная операция к логарифму), чтобы вернуться к привычным «разам» от начального капитала. Кривая капитала = начальный капитал × накопленный множитель. `(src/backtest/vector_backtest.py:55–56)`

### Шаг 6. Просадка (Drawdown)

```python
# src/backtest/vector_backtest.py:59–62
self.df["rolling_max"] = self.df["equity_curve"].cummax()
self.df["drawdown"] = (self.df["rolling_max"] - self.df["equity_curve"]) / self.df["rolling_max"]
```

**Просадка (drawdown)** — это насколько упал капитал от своего предыдущего максимума. Например: капитал был 11 000, потом упал до 9 900 — просадка = `(11 000 − 9 900) / 11 000 ≈ 10%`. Максимальная просадка по всей истории — ключевой показатель риска (подробно — [[max-drawdown-winrate-rr|MaxDD]]). `(src/backtest/vector_backtest.py:59–62)`

### Шаг 7. Итоговые метрики

`(src/backtest/vector_backtest.py:64–81)`

```python
kpis = {
    "Total Return (%)": total_return * 100,
    "Max Drawdown (%)": max_drawdown * 100,
    "Sharpe Ratio": sharpe_ratio,
}
```

Три метрики — единственный результат `run()`. Никаких детальных таблиц сделок, никакого Win Rate, Sortino, Profit Factor — только грубые ключевые числа.

## Формулы и расчёты

### Логарифмическая доходность

```
asset_returns[T] = ln(close[T] / close[T-1])
```

Логарифм отношения закрытий двух соседних баров. Удобен тем, что суммируется: если актив вырос за 3 бара на `r1 + r2 + r3` (сумма лог-доходностей), это точно соответствует общему росту `e^(r1+r2+r3)`. `(src/backtest/vector_backtest.py:45)`

### Доходность стратегии

```
strategy_returns[T] = position[T-1] × asset_returns[T] − |position[T] − position[T-1]| × maker_fee
```

Расшифровка: доходность на баре T = «как изменился актив» × «какую позицию держали на предыдущем баре» − «комиссия за смену позиции». `(src/backtest/vector_backtest.py:48, 52)`

### Sharpe Ratio с параметризованной аннуализацией

```
Sharpe = (mean(strategy_returns) / std(strategy_returns)) × sqrt(bars_per_year)
```

**[[sharpe-sortino-metrics|Sharpe Ratio]]** — это отношение «средней доходности» к «разбросу доходностей» (риску). Чем выше, тем лучше стратегия относительно принимаемого риска.

`sqrt(bars_per_year)` — коэффициент аннуализации: приводит результат к «как будто за год». Для разных таймфреймов:

| Таймфрейм | bars_per_year | sqrt(bars_per_year) |
|---|---|---|
| 5M | 105 120 | ≈ 324.2 |
| 15M | 35 040 | ≈ 187.2 |
| 1H (по умолчанию) | 8 760 | ≈ 93.6 |
| 4H | 2 191 | ≈ 46.8 |

**Исторический баг (S10, исправлен):** раньше было захардкожено `sqrt(365 × 24 × 60)` = `sqrt(525 600)` ≈ 724.98, что соответствует 1-минутным барам. Для 1H-данных это завышало Sharpe в `724.98 / 93.6 ≈ 7.7 раза`. Исправлено на параметризованный `bars_per_year`. `(src/backtest/vector_backtest.py:68–75, комментарий строка 69)`

### Итоговая доходность

```
total_return = (equity_curve[-1] / initial_capital) − 1
```

Сколько процентов заработала стратегия от начала до конца всего периода. `(src/backtest/vector_backtest.py:65)`

### Максимальная просадка

```
drawdown[T] = (max(equity_curve[0..T]) − equity_curve[T]) / max(equity_curve[0..T])
max_drawdown = max(drawdown)
```

Максимальное падение капитала от любого исторического пика. Выражается в процентах. `(src/backtest/vector_backtest.py:59–66)`

## Примеры / сценарии

### Конкретный прогон на пяти барах

Допустим, у нас данные за 5 баров с ценами закрытия `[100, 101, 102, 100, 99]` и сигналами `[0, 1, 1, -1, 0]`:

**Шаг 1 — форвард-филл позиции:**

| Бар | signal | position (после ffill) |
|---|---|---|
| 0 | 0 | 0.0 (нет позиции, ещё нечего копировать) |
| 1 | 1 | 1.0 (вошли в лонг) |
| 2 | 1 | 1.0 (держим лонг) |
| 3 | −1 | −1.0 (переворот в шорт) |
| 4 | 0 | −1.0 (держим шорт — ffill скопировал −1) |

**Шаг 2 — логарифмические доходности актива:**

| Бар | close | asset_returns |
|---|---|---|
| 0 | 100 | NaN |
| 1 | 101 | ln(101/100) ≈ +0.00995 |
| 2 | 102 | ln(102/101) ≈ +0.00985 |
| 3 | 100 | ln(100/102) ≈ −0.01980 |
| 4 | 99 | ln(99/100) ≈ −0.01005 |

**Шаг 3 — доходность стратегии (position сдвинута на 1 бар назад):**

| Бар | position[T-1] | asset_returns | strategy_returns (до комиссии) |
|---|---|---|---|
| 0 | NaN | NaN | NaN |
| 1 | 0.0 | +0.00995 | 0.0 × 0.00995 = **0.00000** |
| 2 | 1.0 | +0.00985 | 1.0 × 0.00985 = **+0.00985** |
| 3 | 1.0 | −0.01980 | 1.0 × (−0.01980) = **−0.01980** |
| 4 | −1.0 | −0.01005 | −1.0 × (−0.01005) = **+0.01005** |

**Шаг 4 — комиссии:** смены позиции произошли на барах 1 (`0→1`, diff=1) и 3 (`1→−1`, diff=2). Maker fee = 0.001.

| Бар | |diff| | fee | strategy_returns (после fee) |
|---|---|---|---|
| 1 | 1 | 0.001 | 0.000 − 0.001 = **−0.001** |
| 2 | 0 | 0.000 | +0.00985 |
| 3 | 2 | 0.002 | −0.01980 − 0.002 = **−0.02180** |
| 4 | 0 | 0.000 | +0.01005 |

**Шаг 5 — кривая капитала** (начальный капитал 10 000 USDT):

| Бар | cumsum | exp(cumsum) | equity |
|---|---|---|---|
| 1 | −0.001 | 0.99900 | 9 990.00 |
| 2 | +0.00885 | 1.00889 | 10 088.92 |
| 3 | −0.01295 | 0.98713 | 9 871.33 |
| 4 | −0.00290 | 0.99710 | 9 971.04 |

**Итог:**
- Total Return: −0.29%
- Max Drawdown: ≈2.16% (пик 10 088.92 → низ 9 871.33)
- Sharpe: рассчитывается по `mean / std × sqrt(8760)` из четырёх значений strategy_returns

## Подводные камни / что важно понимать

**1. Это грубая оценка, не финальный вердикт**

`VectorBacktester` не моделирует:
- **Стоп-лосс (SL) и тейк-профит (TP):** в реальности сделка может закрыться в середине бара по SL-цене, а не по закрытию. Векторный бэктест этого не видит и может показать «выживших» — позиции, которые на самом деле срабатывали бы по стопу внутри бара.
- **Внутрибарное движение цены:** учитывается только `close`, тогда как реальное исполнение зависит от `high`/`low`.
- **Детальный учёт по сделкам:** нет Win Rate, Profit Factor, среднего удержания — ничего кроме трёх чисел.

Для финального вердикта всегда используется `replay_engine` (bar-by-bar движок с SL/TP). `[[replay-engine-bar-by-bar]]`

**2. Анти-look-ahead реализован через shift(1) — не убирай его**

Если убрать `.shift(1)` из `position.shift(1) * asset_returns`, стратегия будет «знать» закрытие бара в момент входа — результаты окажутся нереально хорошими. Этот сдвиг — обязательная защита от смотрения в будущее. `(src/backtest/vector_backtest.py:48)`

**3. Комиссия — приблизительная**

`trades × maker_fee` — упрощённая модель. В реальности:
- при перевороте позиции (`+1 → −1`) происходят две сделки: закрытие лонга и открытие шорта, и `|diff| = 2` корректно отражает двойную комиссию;
- но `maker_fee` применяется к 1.0 (нормированной единице позиции), а не к реальному размеру в USDT — это приближение.

**4. bars_per_year нужно задавать правильно**

По умолчанию `bars_per_year=8760` (для 1H-данных). Если передать 1H-данные с параметром для 15M (`35040`), Sharpe будет завышен в `sqrt(35040/8760) = 2.0` раза. Вызывающий код (`__main__.py`) берёт `bars_per_year` из таблицы по таймфрейму. `(src/__main__.py:518–529)`

**5. В src/ `VectorBacktester` не вызывается автоматически**

Поиск по кодовой базе показывает: класс `VectorBacktester` используется только в тестах (`tests/unit/test_vector_backtest_annualization.py`). В production-потоке бот использует `replay_engine`. Векторный бэктест — инструмент для быстрого ручного исследования или написания тестов, не часть автоматического pipeline WFA.

**6. Логарифмические доходности суммируются, а не перемножаются**

`strategy_returns.cumsum().apply(np.exp)` — это математически корректный способ перевести лог-доходности в накопленный множитель. Это **не то же самое**, что просто сложить проценты. Путаница здесь может привести к неверной интерпретации кривой капитала.

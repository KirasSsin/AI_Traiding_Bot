# Стратегия Supertrend: следование за трендом с рекурсивной линией

**TL;DR:** Бот рисует «плавающий отбойник» рядом с ценой биткоина. Когда цена пробивает его снизу вверх — бот покупает; когда падает ниже — продаёт. Этот раздел описывает, как бэктест-раннер проверяет стратегию на исторических данных. Про live-логику (работу «прямо сейчас») — см. [[02-стратегии/supertrend-strategy]].

## Простыми словами

Представьте светофор на горной дороге: пока машины едут вверх — горит зелёный, как только поток разворачивается вниз — красный. Supertrend работает похожим образом: он следит за ценой BTC и определяет, «тренд сейчас вверх или вниз».

Конкретно: индикатор рисует линию рядом с ценой. Пока цена держится **выше** линии — говорим, что тренд бычий (**BULL**, «зелёный»). Как только цена **проваливается ниже** линии — тренд становится медвежьим (**BEAR**, «красный»). Момент переключения называется **флипом тренда** (trend flip).

Стратегия проста: купить при первом «зелёном» сигнале (BEAR→BULL флип), продать при первом «красном» (BULL→BEAR флип). Никаких коротких продаж — только покупка и ожидание.

Линия строится по алгоритму **Lazybear** (псевдоним разработчика из торгового сообщества). Подробный разбор самого индикатора — на странице [[supertrend-indicator]]. У неё есть важная черта — **«храповик»** (clamp/ratchet): в бычьем тренде нижняя полоса может только подниматься, никогда не опускаясь. Это защищает от ложных разворотов при коротких «откатах» цены.

> Параметры стратегии **зафиксированы до начала проверки** решением ADR 0067 (спринт S50): `atr_period=10`, `multiplier=3.0`. Это правило anti-snooping: параметры нельзя менять по результатам проверки — иначе мы бы «подогнали» под историю. Менять их можно только через новый ADR.

## Как это работает у нас

Бэктест-раннер работает в три крупных этапа: (1) рассчитать ATR и построить Supertrend-линию для всех баров сразу, (2) пробежать по сигналам и посчитать сделки, (3) запустить WFA-валидацию и вернуть вердикт.

### Шаг 1. Расчёт Wilder ATR — `_wilder_atr_vectorized`

`(src/backtest/supertrend_runner.py:73–96)`

Прежде чем строить Supertrend, нужно знать, насколько «шумен» рынок в каждый момент. Для этого считается [[atr-indicator|ATR]] (Average True Range — средний истинный диапазон) по методу **Уайлдера** (Wilder). Каноническую формулу Wilder ATR и её варианты в проекте разбирает [[wilder-atr-and-stops]].

Истинный диапазон (True Range, TR) каждого бара — это максимум из трёх чисел:

```text
TR = max(
    high − low,                    # обычный диапазон свечи
    |high − close_предыдущего|,    # разрыв вверх от предыдущего закрытия
    |low  − close_предыдущего|     # разрыв вниз от предыдущего закрытия
)
```

Затем ATR считается рекурсивно. Первые `atr_period=10` баров накапливаются как простое среднее (seed). Начиная с 11-го бара:

```text
ATR[i] = (ATR[i-1] × (period − 1) + TR[i]) / period
```

Это так называемое «сглаживание Уайлдера» — новые значения добавляются понемногу, старые медленно «забываются». Такой ATR всегда использует **всю историю** данных (полная рекурсия), а не только последние N баров — это принципиально отличается от простого скользящего среднего.

Первые 9 баров возвращают `NaN` (нет данных для расчёта) — это прогрев. Первый реальный ATR появляется на 10-м баре (seed бар, индекс 9 в нулевой нумерации). `(src/backtest/supertrend_runner.py:93–95)`

### Шаг 2. Построение Supertrend-линии — `_supertrend_vectorized`

`(src/backtest/supertrend_runner.py:99–168)`

Имея ATR, строятся две «базовые» полосы:

```text
hl2 = (high + low) / 2          # середина свечи

basic_ub = hl2 + multiplier × ATR   # верхняя полоса (upper band)
basic_lb = hl2 − multiplier × ATR   # нижняя полоса (lower band)
```

При `multiplier=3.0` полосы отступают от середины свечи на три ATR в каждую сторону. Чем волатильнее рынок (больше ATR), тем шире полосы.

Затем к ним применяется **храповик Lazybear** (clamp/ratchet). Он «зажимает» полосы так, чтобы они не двигались в «неправильную» сторону:

```python
# Верхняя полоса: берём новое значение ТОЛЬКО если оно ниже предыдущего
# ИЛИ если цена закрытия пробила предыдущую верхнюю полосу
final_ub[i] = (
    basic_ub[i]
    if (basic_ub[i] < prev_final_ub or prev_close > prev_final_ub)
    else prev_final_ub
)

# Нижняя полоса: берём новое значение ТОЛЬКО если оно выше предыдущего
# ИЛИ если цена закрытия упала ниже предыдущей нижней полосы
final_lb[i] = (
    basic_lb[i]
    if (basic_lb[i] > prev_final_lb or prev_close < prev_final_lb)
    else prev_final_lb
)
```

`(src/backtest/supertrend_runner.py:149–158)`

После этого определяется, какая из полос сейчас «активна» как Supertrend-линия — и соответственно, каков тренд:

```python
if prev_supertrend == prev_final_ub:  # линия шла по верхней полосе (BEAR-режим)
    supertrend[i] = final_ub[i] if close[i] <= final_ub[i] else final_lb[i]
else:                                  # линия шла по нижней полосе (BULL-режим)
    supertrend[i] = final_lb[i] if close[i] >= final_lb[i] else final_ub[i]

trend[i] = 1 if supertrend[i] == final_lb[i] else -1
# trend = +1 (BULL), -1 (BEAR), 0 (прогрев)
```

`(src/backtest/supertrend_runner.py:161–166)`

**Ключевая тонкость — почему алгоритм рекурсивный:** значение `trend[i]` зависит от `close[i]` (сравнение `close[i] <= final_ub[i]`). Это означает, что флип тренда на баре `i` **становится известен только ПОСЛЕ закрытия бара `i`**. Поэтому самая ранняя цена, по которой можно исполнить ордер — это `open[i+1]` (открытие следующего бара). Войти по `open[i]` означало бы «знать будущее» (same-bar look-ahead — заглядывание в пределах бара) — это дисквалифицирует результаты бэктеста.

### Шаг 3. Подсчёт сделок — `_backtest_single`

`(src/backtest/supertrend_runner.py:171–269)`

Пробегаем по всем барам и ищем флипы тренда:

**Вход в позицию** — BEAR → BULL флип:
- На баре `i` закрылся BULL, на баре `i-1` был BEAR → флип зафиксирован на баре `i` (по `close[i]`).
- Если есть следующий бар (`i+1 < n`): покупаем по `open[i+1] × (1 + 0.05%)`.
- Запоминаем `entry_price` и индекс `entry_idx = i+1`.

```python
if prev_trend == -1 and curr_trend == 1 and i + 1 < n:
    entry_price = open_[i + 1] * (1.0 + _SLIPPAGE)
    entry_idx = i + 1
    in_pos = True
```

`(src/backtest/supertrend_runner.py:223–225)`

> Важно: в коде переменная `curr_trend` — это `trend[i]` (проверяем флип завершившийся на баре `i`), а fill происходит по `open_[i+1]`. То есть: флип решается на баре `i` (по `close[i]`), исполняем на `i+1` (следующий `open`). Это соответствует контракту `close(T)→open(T+1)`.

**Выход из позиции** — BULL → BEAR флип:
- Аналогично: флип завершился на баре `i` → продаём по `open[i+1] × (1 − 0.05%)`.
- PnL рассчитывается как разность цен минус две комиссии (вход + выход):

```python
pnl_gross = (exit_price - entry_price) / entry_price
pnl_net = pnl_gross - 2.0 * _COMMISSION_TAKER  # 2 × 0.1% = 0.2%
```

`(src/backtest/supertrend_runner.py:231–232)`

**Флип на последнем баре** — если флип происходит на последнем баре данных, следующего `open` нет:
- Вход пропускается (нет бара для исполнения).
- Открытая позиция закрывается «по рынку» (mark-to-market) по `close[-1] × (1 − 0.05%)` — это цена последней свечи, уменьшенная на slippage.

`(src/backtest/supertrend_runner.py:237–241)`

**АТR-стоп в бэктесте отсутствует.** Стратегия полагается исключительно на выход по флипу тренда. В live-торговле ATR-стоп-брекет добавляется downstream FSM-слоем (конечным автоматом управления позицией), но в исследовательском бэктесте этот слой не реализован — OOS-оценка считается только по flip-выходам. `(src/backtest/supertrend_runner.py:183–185)`

### Шаг 4. Расчёт метрик фолда

После сбора сделок:

```text
mean_holding = среднее число баров между entry_idx и exit_idx
trades_per_year = bars_per_year / mean_holding  (8766 баров в году для 1H)
Sharpe фолда = (mean(PnL) / std(PnL, ddof=1)) × √(trades_per_year)
```

`(src/backtest/supertrend_runner.py:253–261)`

Эта формула аннуализирует [[sharpe-sortino-metrics|Sharpe]] через **реальный средний срок удержания позиции** — честный подход для тренд-следующих стратегий, где сделки длятся по-разному.

### Шаг 5. WFA-прогон — `run_supertrend_wfa`

`(src/backtest/supertrend_runner.py:303–372)`

Главная функция, которую вызывает дашборд или CLI:

1. **Тир-параметры WFA**: вызывается `get_wfa_tier_params("60")` (1H = high-freq тир). `(src/backtest/supertrend_runner.py:341)`. Возвращает: `train_bars=2000, test_bars=500, k_folds=5, embargo_bars=20`. Минимально нужно 4520 баров: `2000 + 20 + 5×500 = 4520`. `(src/backtest/research_wfa.py:88–89)`

2. **Загрузка данных**: `_load_ohlcv_df("data/BTCUSDT_1h.parquet", start_date, end_date)` — BTCUSDT 1H данные, зафиксировано в ADR 0067. `(src/backtest/supertrend_runner.py:354)`

3. **Вызов `run_research_wfa`** с параметрами:
   - `n_trials=10` — стратегия числится как 10-я гипотеза в семействе (ADR 0067, CC3).
   - `strategy_class="supertrend"` — для изоляции sigma_SR внутри класса стратегий (S51 D5).
   - `backtest_fn=_backtest_single` — ядро бэктеста.
   - `bars_per_year=8766` (`int(365.25 × 24)`). `(src/backtest/supertrend_runner.py:51)`

4. **Внутри `run_research_wfa`**: [[walk-forward-analysis|WFA]] разбивает данные на 5 фолдов, для каждого фолда запускает `_backtest_single` на тест-слайсе (train-слайс при LOCKED-параметрах не используется — нечего подбирать), собирает OOS-сделки и считает итоговые метрики. Ту же research-модель исполнения сделок описывает [[research-kernel-execution-model]], а полный референс-прогон WFA через `replay_engine` — [[donchian-runner-and-reference-run]].

5. **[[acceptance-gates-t1-t6|Ворота валидации]]**: пороги из `research_wfa.py:37–41` (ADR 0052):

| Критерий | Порог | Константа в коде |
|---|---|---|
| Sharpe каждого фолда | ≥ 0.7 | `SHARPE_THRESHOLD = 0.7` |
| MC sign-flip p-value | ≤ 0.05 | `P_THRESHOLD = 0.05` |
| Число OOS сделок (N_eff) | ≥ 50 | `N_EFF_THRESHOLD = 50` |
| T5 минимум сделок | ≥ 50 | `T5_FLOOR = 50` |
| DSR (дефлированный Sharpe) | ≥ 0.95 | `DSR_THRESHOLD = 0.95` |

Если хотя бы один критерий не выполнен — вердикт `WFA_FAIL`. Все выполнены — `WFA_PASS`. `(src/backtest/research_wfa.py:330–350)`

## Формулы и расчёты

### Полосы Supertrend

```text
hl2       = (high + low) / 2

basic_ub  = hl2 + 3.0 × ATR       (верхняя сырая полоса)
basic_lb  = hl2 − 3.0 × ATR       (нижняя сырая полоса)

final_ub  = min(basic_ub, prev_final_ub)  — но сбрасывается, если prev_close > prev_final_ub
final_lb  = max(basic_lb, prev_final_lb)  — но сбрасывается, если prev_close < prev_final_lb

supertrend = final_lb  (BULL)   |   final_ub  (BEAR)
trend      = +1 (BULL)          |   -1 (BEAR)
```

Простыми словами: верхняя полоса может только опускаться (или сброситься при прорыве), нижняя — только подниматься. Это «храповик»: как гайка с трещоткой, которая крутится только в одну сторону.

`(src/backtest/supertrend_runner.py:114–166)`

### ATR по Уайлдеру

```text
TR[0]  = high[0] − low[0]
TR[i]  = max(high[i]−low[i], |high[i]−close[i-1]|, |low[i]−close[i-1]|)

Seed (ATR[9])    = mean(TR[0..9])
ATR[i] (i ≥ 10) = (ATR[i-1] × 9 + TR[i]) / 10
```

Расшифровка: за 10 баров мы берём среднее как «начальный разгон». Затем каждый новый бар добавляет своё значение, а старые потихоньку снижают вес. Коэффициент `(period−1)/period = 9/10 = 0.9` означает: предыдущий ATR имеет вес 90%, новый TR — 10%.

`(src/backtest/supertrend_runner.py:73–96)`

### PnL одной сделки

```text
entry_price = open[i+1] × 1.0005   (0.05% slippage на покупку)
exit_price  = open[j+1] × 0.9995   (0.05% slippage на продажу)

pnl_gross = (exit_price − entry_price) / entry_price
pnl_net   = pnl_gross − 2 × 0.001  (две комиссии по 0.1% — вход и выход)
```

`(src/backtest/supertrend_runner.py:47–48, 231–232)`

## Примеры / сценарии

### Нормальный цикл сделки

Представьте, что у нас 3 бара (часовые свечи BTC):

| Бар | Ситуация | Trend | Действие |
|---|---|---|---|
| Бар 100 | close ушла ниже линии | BEAR (-1) | Ничего |
| Бар 101 | close вернулась выше линии | BULL (+1) | **Флип BEAR→BULL** |
| Бар 102 | — | — | **Вход**: open[102] × 1.0005 |
| ... | ... | BULL | Держим позицию |
| Бар 150 | close упала ниже линии | BEAR (-1) | **Флип BULL→BEAR** |
| Бар 151 | — | — | **Выход**: open[151] × 0.9995 |

PnL = (open[151] × 0.9995 − open[102] × 1.0005) / (open[102] × 1.0005) − 0.002

### Флип на последнем баре данных

Если на последнем баре (бар `n-1`) происходит BULL→BEAR флип — следующего открытия нет. Открытая позиция принудительно закрывается по `close[-1] × 0.9995` (последняя известная цена минус slippage). Нового входа после флипа на последнем баре тоже не будет — его пропускают. `(src/backtest/supertrend_runner.py:237–241)`

### DSR-штраф и n_trials=10

Стратегия зарегистрирована под n_trials=10: это значит, что [[deflated-sharpe-ratio|DSR]]-формула «знает» — мы перепробовали 10 гипотез в семействе, и конкретная Supertrend — одна из них. Штраф за множественность тестов активируется только при наличии ≥ 3 записей в `data/cross_trial_sharpes.json` (см. [[cross-trial-log]]) класса `"supertrend"`. Если истории ещё мало — DSR честно считается без штрафа (n_trials=1 fallback). Это **не баг, а ожидаемое поведение**. `(src/backtest/supertrend_runner.py:24–28, src/backtest/research_wfa.py:295–309)`

## Подводные камни / что важно понимать

### 1. Рекурсия = невозможность заполнить по текущему open

Supertrend РЕКУРСИВЕН: `trend[i]` зависит от `close[i]`. Это означает, что флип на баре `i` неизвестен до конца этого бара. Заполнить ордер по `open[i]` (открытие того же бара) было бы «подсматриванием в будущее» (same-bar look-ahead). Поэтому заполнение всегда на `open[i+1]`. Если бы мы нарушили это правило — результаты бэктеста были бы нереалистично хорошими. `(src/backtest/supertrend_runner.py:207–214)`

### 2. ATR-стоп отсутствует в бэктесте

В live-системе FSM добавляет ATR-стоп-брекет (защитный стоп) на каждую позицию. В бэктест-раннере этот слой отсутствует намеренно: бэктест оценивает только OOS-прибыльность flip-логики. Реальная live-торговля будет защищена стопом, который бэктест не учитывает — это значит, что реальные результаты могут немного отличаться от бэктестных. `(src/backtest/supertrend_runner.py:183–185)`

### 3. Параметры LOCKED и anti-snooping

`atr_period=10`, `multiplier=3.0`, `signal_side_mode="long_only"` — зафиксированы до проведения WFA-проверки (ADR 0067). Их нельзя менять по результатам проверки, иначе мы «подгоняем» стратегию под историю. Такое «подгонять после просмотра» называется snooping (снупинг). Менять параметры — только через новый ADR. `(src/backtest/supertrend_runner.py:53–57)`

### 4. n_trials=10 и DSR-штраф — двухуровневый пул

`n_trials=10` — это глобальная «ширина поиска» (сколько гипотез тестировалось всего в семействе). Но sigma_SR (разброс Sharpe между испытаниями) считается **внутри класса** `"supertrend"`, а не по всему пулу. Это S51 D5 fix: Sharpe других стратегий (например, [[06-бэктест-и-валидация/atr-breakout-strategy|ATR Breakout]] ETH с −89) не должен загрязнять расчёт для Supertrend. `(src/backtest/research_wfa.py:284–293)`

### 5. Seed бар — нет сигнала

Первый бар с действительным ATR (10-й бар, индекс 9) — это seed бар. На нём заполняются начальные значения полос, но сигнала нет: нет предыдущей линии, с которой сравнивать. Первый возможный флип — только начиная с 11-го бара. `(src/backtest/supertrend_runner.py:123–136)`

### 6. Точность аннуализации Sharpe

В `_backtest_single` аннуализация Sharpe использует реальный средний срок удержания из `entry_idx`/`exit_idx`. В `run_research_wfa` (для trial-level Sharpe) используется заглушка `_MEAN_HOLDING_BARS_PLACEHOLDER=100` — потому что research-трейды не несут bar-индексов. Этот trial-level Sharpe информационный и не является воротами (gates). `(src/backtest/research_wfa.py:43–48)`

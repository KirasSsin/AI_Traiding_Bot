# Сколько денег ставить на сделку: формула Келли по фазам

**TL;DR:** Бот решает, сколько денег поставить на каждую сделку, через формулу Келли — математически обоснованный метод определения «оптимальной ставки». Но он никогда не доверяет формуле сразу: пока статистики мало (менее 200 сделок), бот ограничивает себя маленькими долями капитала — **1-3%** (фазы 1-3); только накопив 200+ сделок (фаза 4, зрелая статистика), потолок поднимается до **5%** — независимо от того, что говорит формула.

---

## Простыми словами

Представьте игрока в покер, который только пришёл за стол. У него есть стратегия, но он ещё не знает, насколько она хороша именно здесь, с этими соперниками, в этих условиях. Умный игрок не ставит всё сразу — он начинает с маленьких ставок, постепенно собирает статистику своих побед и проигрышей, и лишь накопив достаточно данных, начинает ставить больше.

Именно так работает наш бот с **критерием Келли** — математической формулой, придуманной в 1956 году для расчёта оптимального размера ставки. Формула говорит: «Если ты выигрываешь X% сделок и в среднем выигрываешь в Y раз больше, чем проигрываешь — вот какую долю капитала оптимально ставить за раз».

**Проблема чистой формулы Келли:** она агрессивна. При хорошей статистике она может советовать ставить 20-30% капитала за раз. Это математически «оптимально» на бесконечном горизонте, но на практике приводит к огромным просадкам и психологическому стрессу. Поэтому опытные трейдеры и наш бот используют **дробные версии Келли** — ставят не всю «оптимальную» долю, а её четверть или половину.

**Главная идея нашей системы:** чем больше закрытых сделок накопил бот, тем больше он доверяет своей статистике — и тем больше позволяет себе ставить. Это называется **системой фаз**.

---

## Как это работает у нас

### Шаг 1. Определяем фазу по числу сделок

Функция `phase_from_trade_count(n)` смотрит, сколько сделок бот закрыл к данному моменту, и присваивает фазу (`src/risk/kelly.py:20-40`):

| Фаза | Число закрытых сделок | Смысл |
|------|----------------------|-------|
| 1 | меньше 30 | Новичок за столом — статистики почти нет |
| 2 | от 30 до 99 | Первые наблюдения — начинаем видеть тенденцию |
| 3 | от 100 до 199 | Достаточно данных, чтобы применить формулу осторожно |
| 4 | 200 и больше | Зрелая статистика — большее доверие формуле |

```python
# src/risk/kelly.py:34-40
if n < 30:
    return 1
if n < 100:
    return 2
if n < 200:
    return 3
return 4
```

Граничные значения: 29 сделок → Фаза 1; 30 сделок → Фаза 2; 199 → Фаза 3; 200 → Фаза 4.

---

### Шаг 2. Вычисляем сырую долю по формуле Келли

Функция `kelly_fraction(p, b)` считает теоретически оптимальную долю капитала (`src/risk/kelly.py:73-92`).

Формула: **f\* = (p · b − q) / b**, где q = 1 − p.

Переменные:
- **p** — вероятность выигрыша (например, 0.55 = «55% сделок заканчиваются в плюс»)
- **q** — вероятность проигрыша (1 − p)
- **b** — соотношение среднего выигрыша к среднему проигрышу (payoff ratio): если в среднем выигрываем 150 USDT, а проигрываем 100 USDT — то b = 1.5
- **f\*** — рекомендуемая доля капитала

Что означает формула простыми словами: числитель `p · b − q` — это математическое «преимущество» стратегии (ожидаемый доход на единицу риска). Делим на b, чтобы выразить это как долю от всего капитала.

```python
# src/risk/kelly.py:90-92
q = 1.0 - p
f_star = (p * b - q) / b
return max(0.0, f_star)
```

**Когда формула возвращает 0:**
- если `b <= 0` (некорректный payoff ratio) — (`src/risk/kelly.py:88-89`)
- если вычисленная доля отрицательна — то есть математического преимущества нет, и лучше вообще не торговать (`src/risk/kelly.py:92`: `max(0.0, f_star)`)

Пример расчёта: при p=0.60 (60% выигрышных сделок) и b=2.0 (выигрыш вдвое больше проигрыша):
f\* = (0.60 · 2.0 − 0.40) / 2.0 = (1.20 − 0.40) / 2.0 = **0.40** (то есть 40% капитала).
Это и есть причина, почему чистый Келли агрессивен — 40% за одну сделку это огромный риск.

### Шаг 3. Откуда берутся p и b — функция `_compute_p_b`

Функция `_compute_p_b(phase)` в `src/risk/manager.py:325-341` ([[risk-overview-decision-pipeline|риск-менеджера]]) определяет, откуда взять вероятность выигрыша и payoff ratio:

**Фазы 1 и 2 (меньше 100 сделок):** данных недостаточно. Возвращается заглушка `(0.5, 1.0)` — «монетка» без преимущества. Эти значения всё равно игнорируются, так как в Фазах 1 и 2 формула не применяется (см. Шаг 4).

**Фазы 3 и 4 (100+ сделок):** берётся реальная [[trade-fill-history|история закрытых сделок]] за последние 90 дней (`window_days=90`). При этом нужно выполнение трёх условий:
1. Не менее 30 закрытых сделок в этом окне
2. Хотя бы одна выигрышная сделка (PnL > 0)
3. Хотя бы одна проигрышная сделка (PnL < 0)

Если любое условие не выполнено — откат к заглушке `(0.5, 1.0)`.

```python
# src/risk/manager.py:329-341
recent = self._trades.load_recent(window_days=90, now=self._clock(), symbol=self._symbol)
if len(recent) < 30:
    return (0.5, 1.0)
wins = [t for t in recent if t.pnl_quote > 0]
losses = [t for t in recent if t.pnl_quote < 0]
if not wins or not losses:
    return (0.5, 1.0)
```

**Консервативная оценка p — интервал Вилсона.** Даже если у бота за последние 90 дней win rate (доля выигрышных сделок) составил 60%, это не значит, что он на самом деле выигрывает 60% сделок — это может быть просто удача на небольшой выборке. Поэтому бот берёт не само значение 0.60, а **нижнюю границу 95% доверительного интервала Вилсона** — то есть самую пессимистичную оценку, которая всё ещё «вписывается» в статистику с 95% вероятностью:

```python
# src/risk/manager.py:337
p_lower, _ = wilson_95_ci(len(wins), len(recent))
```

Для payoff ratio b (это [[max-drawdown-winrate-rr|Risk-Reward]] — отношение среднего выигрыша к среднему проигрышу) берётся среднее фактических выигрышей делённое на среднее проигрышей:

```python
# src/risk/manager.py:338-340
avg_win = sum((t.pnl_quote for t in wins), start=Decimal(0)) / len(wins)
avg_loss = abs(sum((t.pnl_quote for t in losses), start=Decimal(0)) / len(losses))
b = float(avg_win / avg_loss) if avg_loss > 0 else 1.0
```

### Шаг 4. Применяем фазовое правило — `phase_adjusted_fraction`

Функция `phase_adjusted_fraction(phase, p, b, caps)` применяет осторожность в зависимости от фазы (`src/risk/kelly.py:95-128`):

**Фазы 1 и 2 — фиксированная маленькая доля, формула не применяется:**

```python
# src/risk/kelly.py:114-117
if phase == 1:
    return caps.phase1   # = 0.01 (1% капитала)
if phase == 2:
    return caps.phase2   # = 0.02 (2% капитала)
```

Статистики мало — игнорируем p и b полностью, берём безопасный минимум.

**Фаза 3 — Quarter-Kelly (четверть-Келли):**

Берём только 25% от того, что советует формула, и сверху ограничиваем жёстким потолком 3%:

```python
# src/risk/kelly.py:124-125
return min((f_dec * Decimal("0.25")).quantize(quant), caps.phase3)
```

**Фаза 4 — Half-Kelly (половина-Келли):**

Берём 50% от рекомендации формулы, потолок 5%:

```python
# src/risk/kelly.py:126-127
return min((f_dec * Decimal("0.5")).quantize(quant), caps.phase4)
```

Аналогия: Quarter-Kelly — это как строитель, который нашёл перспективный участок земли, но не покупает всё — берёт только четверть, пока не убедится, что перспективы реальные. Half-Kelly — когда уверенности больше, но всё равно не «ва-банк».

### Шаг 6. Итоговый размер позиции — `compute_qty`

Функция `compute_qty(equity, fraction, atr, price, k)` переводит долю капитала в конкретное количество монет (`src/risk/sizing.py:6-29`):

**Формула: qty = (fraction · equity) / (k · atr)**

- **fraction** — доля из шага 4 (например, 0.02 = 2%)
- **equity** — [[equity-tracking|текущий капитал бота]] в USDT
- **atr** — средний дневной диапазон цены ([[atr-indicator|ATR]] 14 баров) — мера того, насколько сильно цена обычно двигается
- **k** — множитель стоп-лосса (по умолчанию 1.5 из настроек: `risk_sl_atr_multiplier = Decimal("1.5")`, `src/platform/config.py:113`)

```python
# src/risk/sizing.py:29
return (fraction * equity) / (k * atr)
```

**Зачем делить на k·ATR?** Знаменатель — это расстояние от цены входа до стоп-лосса в деньгах. Чем сильнее рынок «болтает» (большой ATR), тем дальше стоп-лосс, а значит — тем меньше монет нужно купить, чтобы потерять не больше `fraction·equity`. Это называется «риск-параметрическая позиция» — размер подстраивается под текущую волатильность.

Упрощённая аналогия: вы решили, что готовы рискнуть 1000 руб. на одну ставку. Если ваш «стоп» (выход из позиции при плохом сценарии) стоит 500 руб. за единицу — берите 2 единицы. Если стоп стоит 1000 руб. — берите только 1. Логика одна: риск фиксирован, размер подстраивается.

**Защитные случаи:**
- если `fraction = 0` или `atr = 0` → возвращает 0 (`src/risk/sizing.py:26-27`)
- если любой вход отрицательный → `ValueError` (`src/risk/sizing.py:19-24`)

**После вычисления qty** менеджер рисков округляет результат вниз до 8 знаков после запятой (требование Bybit Spot):

```python
# src/risk/manager.py:276
qty = qty.quantize(Decimal("0.00000001"), rounding=ROUND_DOWN)
```

Если после округления qty = 0 → отказ с [[reason-codes-assessment-output|кодом причины]] `REJECT_MIN_NOTIONAL` (`src/risk/manager.py:279-286`).

## Формулы и расчёты

### Формула 1. Критерий Келли

```text
f* = (p · b − q) / b,  где q = 1 − p
```

| Символ | Что это | Где берётся |
|--------|---------|-------------|
| p | Вероятность выигрыша (нижняя граница Вилсона) | `_compute_p_b` → `wilson_95_ci` (manager.py:337) |
| q | Вероятность проигрыша (= 1 − p) | Вычисляется внутри kelly.py:90 |
| b | Payoff ratio: средний выигрыш / средний проигрыш | `_compute_p_b` (manager.py:338-340) |
| f\* | «Оптимальная» доля капитала (не применяется напрямую!) | `kelly_fraction` (kelly.py:73-92) |

Реализация: `src/risk/kelly.py:73-92`.

### Формула 2. Интервал Вилсона (95% CI)

Формула позволяет оценить «настоящий» win rate с учётом размера выборки (`src/risk/kelly.py:43-70`):

```text
p_hat = wins / total
z = 1.96  (квантиль нормального распределения для 95%)
center = p_hat + z² / (2·total)
spread = z · √(p_hat·(1−p_hat)/total + z²/(4·total²))
denom  = 1 + z²/total
lower  = (center − spread) / denom
upper  = (center + spread) / denom
```

Бот использует только `lower` — самую пессимистичную оценку.

Проверка: при 55 победах из 100 сделок: lower ≈ **0.452**, upper ≈ **0.644** — то есть бот будет считать win rate равным 45.2%, а не 55%. Это намеренная консервативность.

### Формула 3. Размер позиции

```text
qty = (fraction · equity) / (k · atr)
```

| Параметр | Дефолтное значение | Где задан |
|----------|--------------------|-----------|
| k (множитель ATR) | 1.5 | `risk_sl_atr_multiplier` (config.py:113) |

Реализация: `src/risk/sizing.py:6-29`.

## Примеры / сценарии

### Сценарий А: Фаза 1 — только начали

Бот совершил 15 сделок. Статистики мало.

- Фаза: 1 (15 < 30)
- Формула Келли: **не применяется**
- Доля капитала: фиксированная 1% (caps.phase1)
- Капитал бота: 10 000 USDT, ATR текущей монеты: 800 USDT

```text
qty = (0.01 × 10 000) / (1.5 × 800) = 100 / 1200 ≈ 0.0833 BTC
```

При цене BTC = 40 000 USDT это 0.0833 × 40 000 = ~3 333 USDT позиция. Потенциальные потери при срабатывании стоп-лосса: 0.01 × 10 000 = **100 USDT** (1% капитала).

### Сценарий Б: Фаза 3 — накопили достаточно

Бот совершил 120 сделок. За последние 90 дней: 55 побед из 100 сделок (win rate 55%), средний выигрыш 150 USDT, средний проигрыш 100 USDT.

**Шаг 1 — Wilson lower bound:**
wilson_95_ci(55, 100) → lower ≈ **0.452** (используем вместо 0.55)

**Шаг 2 — f\*:**
b = 150/100 = 1.5
f\* = (0.452 × 1.5 − 0.548) / 1.5 = (0.678 − 0.548) / 1.5 ≈ **0.087**

**Шаг 3 — Quarter-Kelly:**
0.25 × 0.087 = 0.022 (2.2%) < caps.phase3 = 3% → **fraction = 0.022**

**Шаг 4 — qty:**
Капитал 20 000 USDT, ATR = 1200 USDT:
qty = (0.022 × 20 000) / (1.5 × 1200) = 440 / 1800 ≈ **0.244 BTC**

Риск в деньгах: 0.022 × 20 000 = 440 USDT = 2.2% капитала.

### Сценарий В: Неблагоприятная статистика — бот не ставит

За последние 90 дней: 30 побед из 100 сделок (win rate 30%), payoff ratio = 1.0 (выигрыши равны проигрышам).

**Шаг 1 — Wilson lower bound:**
wilson_95_ci(30, 100) → lower ≈ **0.219** (используем вместо 0.30; `src/risk/manager.py:337`)

**Шаг 2 — f\*:**
b = 1.0
f\* = (0.219 × 1.0 − 0.781) / 1.0 = −0.562 → max(0, −0.562) = **0**

**Шаг 3 — Quarter-Kelly:**
0.25 × 0 = **0**. Бот возвращает qty=0 и отклоняет сделку с кодом `REJECT_MIN_NOTIONAL`.

Заметьте: бот не берёт 0.30 напрямую — он подставляет в формулу нижнюю границу Вилсона (0.219), которая ещё ниже наблюдаемого win rate. Результат (f*=0, отказ) тот же, но по более строгой причине.

### Сценарий Г: Фаза 2 — переход к 2%

При 50 сделках (Фаза 2) — бот всегда берёт ровно 2% капитала, независимо от любой статистики. Формула Келли в этой фазе вообще не вычисляется.

## Подводные камни / что важно понимать

**1. Фазы 1 и 2 игнорируют формулу полностью.** В `phase_adjusted_fraction` при phase=1 или phase=2 функция немедленно возвращает фиксированный cap, не вызывая `kelly_fraction` вообще (`src/risk/kelly.py:114-117`). Переданные p и b в этих фазах не влияют ни на что.

**2. Формула никогда не даёт больше потолка.** Даже при идеальной статистике (p=0.99, b=100) в Фазе 4 результат будет не больше 5% капитала. Потолок жёсткий: `min(0.5 * f*, caps.phase4)`. Это сознательный выбор — защита от «слишком хорошей» короткой статистики.

**3. Wilson занижает win rate намеренно.** Если бот выиграл 60 из 100 сделок — реальная вероятность, которую он использует в формуле, около **50.2%** (нижняя граница 95% CI), а не 60%. То есть формула Вилсона уже почти на 10 процентных пунктов занижает наблюдаемый win rate на такой выборке. На малых выборках это занижение существенно. При 1000 сделках нижняя граница почти совпадёт с реальным win rate. (Проверка: `wilson_95_ci(60, 100)` → lower ≈ 0.502, `src/risk/kelly.py:43-70`.)

**4. История только за 90 дней, только от 30 сделок.** Если за последние 90 дней было меньше 30 сделок — даже в Фазе 3/4 бот откатывается к заглушке (0.5, 1.0). Стратегия с редкими сделками получает более консервативный расчёт (`src/risk/manager.py:330-331`).

**5. История изолирована по символу (торговой паре).** Параметр `symbol` в `_compute_p_b` позволяет отдельно считать Kelly для BTC и ETH, чтобы успехи на одном активе не «раздули» ставки на другом (`src/risk/manager.py:56-59`, `src/risk/trade_history.py:87`). В текущей версии v0.1 торгуется один символ.

**6. Decimal vs float — дисциплина типов (ADR 0007).** Вероятности (p, b) хранятся как `float` — это нормально для статистических расчётов. Но при переводе доли в `Decimal` для денежных операций используется промежуточный `Decimal(str(f))` и `quantize(Decimal("1e-10"))` для отсечения шума IEEE-754 (`src/risk/kelly.py:122-123`). Это предотвращает накопление ошибок округления при умножении float на Decimal.

**7. `price` в compute_qty — неиспользуемый параметр.** Аргумент `price` принимается функцией для симметрии API (`src/risk/sizing.py:10`, комментарий `# noqa: ARG001`), но в расчёт не входит. Размер позиции в монетах считается только через ATR и fraction, цена нигде не используется внутри этой функции.

**8. Множитель k из настроек, не из кода.** В `compute_qty` нет никакого дефолтного `k=1.5` внутри функции. Значение берётся из `settings.risk_sl_atr_multiplier` (`src/risk/manager.py:272`) — и передаётся явно. Это же k используется при расчёте [[wilder-atr-and-stops|стоп-лосса]]: SL = цена − k × ATR (`src/risk/manager.py:288`). Тем самым qty и SL математически согласованы: если стоп сработает, потеря составит ровно `fraction × equity`.

### Индикаторы и метрики (входы формул)

- [[atr-indicator]] — ATR стоит в знаменателе `qty = fraction·equity / (k·ATR)`: чем выше волатильность, тем меньше монет
- [[wilder-atr-and-stops]] — тот же множитель k и ATR задают стоп-лосс `SL = цена − k·ATR`, математически согласованный с размером позиции
- [[max-drawdown-winrate-rr]] — win rate и Risk-Reward это и есть p и b, которые подставляются в формулу Келли
- [[sharpe-sortino-metrics]] — Kelly оптимизирует рост капитала, но дробные версии (Quarter/Half) снижают волатильность доходности, которую измеряет Sharpe

### Где размер позиции применяется (контекст выше по потоку)

- [[end-to-end-overview]] — место позиционирования в полном пути «свеча → сигнал → риск → ордер»
- [[configuration-and-settings]] — там задаются потолки `risk_kelly_phase{1..4}_cap` и множитель `risk_sl_atr_multiplier` (k), которые использует эта страница

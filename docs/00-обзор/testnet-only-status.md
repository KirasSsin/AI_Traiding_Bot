# Текущий статус и почему бот работает только на TESTNET (без реальных денег)

**TL;DR:** Бот находится на стадии исследования — он умеет торговать, но делает это только с виртуальными деньгами на тренировочной бирже. Ни одной стратегии, которая стабильно зарабатывала бы деньги, пока не найдено. Реальный капитал не рискуется и не может рисковаться — это заблокировано в самом коде.

---

## Простыми словами

Представьте, что вы хотите научиться водить автомобиль. Сначала вы ездите на симуляторе — он выглядит как настоящая машина, имитирует физику, но авария на симуляторе не ломает реальный автомобиль. Это и есть TESTNET.

- **TESTNET** (тестовая сеть, тренировочная биржа) — это копия настоящей биржи Bybit, где всё работает по-настоящему, но деньги на ней ненастоящие. Вы можете открывать ордера, видеть их исполнение, получать «прибыль» или «убыток» — но всё это виртуально. Как учебные патроны вместо боевых.

- **MAINNET** (основная сеть, реальная биржа) — настоящая биржа Bybit, где торгуются реальные деньги. Если бот совершает ошибку там — деньги теряются по-настоящему.

За всё время существования проекта (55 спринтов разработки) **ни один реальный доллар не был подвергнут риску** — бот работал исключительно с виртуальным капиталом на TESTNET.

## Как это работает у нас

### Шаг 1. Главный барьер — валидаторы в коде

Переход на реальную биржу невозможен не «на честном слове», а на уровне самого кода. В файле `src/platform/config.py` есть два специальных проверяющих — функции-валидаторы, которые запускаются при каждом старте бота (и даже при каждом изменении настроек во время работы).

**Первый валидатор — `_live_trading_guards`** (строки 253–258):

```python
def _live_trading_guards(self) -> "Settings":
    if self.live_trading and not self.trading_enabled:
        raise ValueError("live_trading requires trading_enabled=True")
    if self.live_trading and self.testnet:
        raise ValueError("live_trading requires testnet=False (mainnet-only)")
    return self
```

Смысл: если кто-то попытается включить «живую торговлю» (`live_trading=True`) вместе с тестовым режимом (`testnet=True`) — бот немедленно выдаёт ошибку и отказывается запускаться. Это невозможная комбинация по условию.

**Второй валидатор — `_validate_s35_demo_mainnet_exclusion`** (строки 261–291) — дополнительная страховка для «живого тестового режима» (δ TESTNET, подробнее ниже):

```python
def _validate_s35_demo_mainnet_exclusion(self) -> "Settings":
    if self.s35_demo_active and self.live_trading:
        raise ValueError(
            "S35 δ TESTNET demo cannot run на MAINNET (live_trading=True). ..."
        )
    if self.s35_demo_active and not self.testnet:
        raise ValueError(
            "S35 δ TESTNET demo requires testnet=True (Bybit endpoint flag). ..."
        )
    return self
```

Два случая, которые этот валидатор блокирует:
1. Попытка запустить демо-режим с флагом «живой торговли» — запрещено.
2. Попытка запустить демо-режим с отключённым тестнетом (`testnet=False`) — тоже запрещено, потому что даже без флага `live_trading` сам флаг `testnet=False` уже направляет запросы к реальной бирже Bybit.

Ключевой нюанс нашей реализации: поле `validate_assignment=True` в конфигурации (строка 57) означает, что валидаторы перезапускаются при каждом изменении настройки, даже если кто-то попробует подменить значение в памяти после запуска бота. Это закрывает попытку «обойти» защиту через пост-инициализацию.

(src/platform/config.py:57, 253–291)

### Шаг 2. Что такое δ TESTNET live mode

Кроме обычного режима «запустить бэктест через браузер», у бота есть продвинутый режим — **δ TESTNET live mode** (delta-TESTNET). Это режим, в котором бот реально отправляет ордера на тренировочную биржу: подключается к Bybit через API, следит за рыночными данными в реальном времени и торгует — но виртуальными деньгами.

Запускается командой `./scripts/start-bot.sh --live`, активируется переменной `S35_DEMO_ACTIVE=true` в файле `.env`. По умолчанию выключен (`S35_DEMO_ACTIVE=false`). (README.md, секция .env template)

### Шаг 3. Защитные выключатели (HaltGate)

В δ TESTNET режиме бот не торгует бесконтрольно. Встроенный блок `HaltGate` (файл `src/risk/halt_gate.py`) при каждом тике (каждой итерации работы) проверяет четыре критерия. Если хоть один сработал — бот немедленно останавливается и требует ручного перезапуска оператором:

| Критерий | Порог | Что означает |
|---|---|---|
| Просадка за сутки | ≥ 20% (`s35_halt_dd_intraday`) | Виртуальный баланс упал за 24 часа более чем на 20% |
| Просадка от пика | ≥ 15% (`s35_halt_dd_multiday`) | Баланс упал более чем на 15% от максимальной точки с момента запуска |
| Убыточные сделки подряд | ≥ 5 | Пять убыточных сделок одна за другой |
| Отсутствие сделок | ≥ 6 месяцев без 30 закрытых позиций | Стратегия слишком редко даёт сигналы |
| Неизвестный символ | Не в белом списке | Попытка торговать парой, не разрешённой заранее (по умолчанию разрешён только BTCUSDT) |
| Подделка метки запуска | HMAC-подпись не совпадает | Кто-то изменил внутренние данные о времени активации |

(src/risk/halt_gate.py:1–73, src/platform/config.py:132–165, README.md секция Halt criteria)

Приоритет срабатывания: сначала проверяется суточная просадка (самая срочная), потом многодневная, потом убыточная серия, потом пауза в торговле. Первый сработавший критерий останавливает бот. (src/risk/halt_gate.py:65–72)

### Шаг 4. Условие для перехода на реальные деньги

Переход на MAINNET намеренно сделан сложным. Согласно ADR 0055 (архитектурное решение о разрешении δ TESTNET), для разрешения реальной торговли потребуется:

- **12 месяцев доказательств работы на TESTNET** — показать статистически значимые результаты
- **Новый ADR** — формальная предварительная регистрация архитектурного решения о переходе

Ни одно из этих условий на момент написания не выполнено. (README.md: «MAINNET activation forbidden by code-level invariants (ADR 0055 SD-1) до 12mo TESTNET evidence + new ADR pre-registration»)

## Текущий статус проекта

**Тег версии** — v0.1.0-alpha.55 (спринт S55, полный аудит проекта).

Что это означает: приставка `alpha` говорит, что проект находится на ранней стадии. Число `.55` — это номер последнего завершённого спринта (цикла разработки). README показывает `alpha.54` — это незначительное расхождение; актуальный тег `alpha.55` выпущен по итогам спринта S55.

**Стратегии: все проверенные гипотезы провалились.** За 55 спринтов было протестировано 8 различных торговых идей. Ни одна не прошла все критерии качества (T1–T6 + DSR + Monte Carlo). (README.md, таблица Strategy presets)

**Инфраструктура готова.** Бот умеет торговать, подключаться к бирже, управлять рисками, строить отчёты. Просто выгодной стратегии пока не найдено.

## S55 — аудит как маркер зрелости кода

Спринт S55 (июнь 2026) — не добавление новых функций, а полный аудит качества. 120 проверяющих агентов прошли по всей кодовой базе и нашли **43 подтверждённых дефекта** (включая 2 критических — BLOCKER).

Примеры найденного и исправленного:

- **BLOCKER TL-01**: live-режим никогда не вооружал стоп-ордера после входа в позицию — убыток мог быть неограниченным. Исправлено.
- **BLOCKER BYBIT-01**: REST-запросы и WebSocket-соединение шли в разные аккаунты Bybit, из-за чего бот никогда не видел исполнения своих ордеров. Исправлено.

После исправлений: 1694 юнит-теста проходят, 103 интеграционных теста проходят, строгая проверка типов (mypy) — 0 ошибок в 101 файле.

Это показывает подход проекта: код доводится до production-качества, даже пока прибыльной стратегии не найдено. (llm-wiki/wiki/log.md, запись [2026-06-26] sprint-end S55; current-state-part-2.md, строка S55)

## Примеры / сценарии

### Сценарий 1: попытка включить реальную торговлю

Пользователь правит `.env`:

```text
TESTNET=false
LIVE_TRADING=true
S35_DEMO_ACTIVE=true
```

При попытке запустить бот:

```text
ValueError: S35 δ TESTNET demo cannot run на MAINNET (live_trading=True).
Set live_trading=False (testnet=True) OR disable s35_demo_active.
```

Бот не запускается. Причина — валидатор `_validate_s35_demo_mainnet_exclusion` поймал запрещённую комбинацию. (src/platform/config.py:279–284)

### Сценарий 2: срабатывание защитного выключателя

Бот запущен в δ TESTNET режиме. Виртуальный баланс за сутки упал на 22%. На следующем тике (каждые ~5 секунд) выполняется проверка:

```python
if intraday_dd >= self.dd_intraday_threshold:  # 0.22 >= 0.20 → True
    return HaltTrigger.DD_INTRADAY
```

Бот фиксирует причину остановки `S35_DD_INTRADAY`, записывает её в базу данных, выходит чисто. Для возобновления работы нужен ручной перезапуск оператора. (src/risk/halt_gate.py:65–66)

### Сценарий 3: нормальный запуск (бэктест через браузер)

Пользователь запускает `./scripts/start-bot.sh`. В `.env`: `TESTNET=true`, `LIVE_TRADING=false`, `S35_DEMO_ACTIVE=false`. Оба валидатора проверяют настройки и пропускают запуск. Бот открывает браузер на `http://127.0.0.1:8000/`. В браузере можно выбрать стратегию и запустить исторический прогон — реальных ордеров не отправляется.

## Подводные камни / что важно понимать

**Флаг `testnet=False` опаснее, чем кажется.** Интуитивно кажется, что для реальных денег нужен только `live_trading=True`. Но в нашей реализации одного флага `testnet=False` достаточно, чтобы запросы ушли на реальную биржу — даже если `live_trading=False`. Именно поэтому второй валидатор проверяет оба флага. (src/platform/config.py:269–271, комментарий)

**Исследование Kronos (ML-стратегия) — не доказательство прибыльности.** Стратегия на базе языковой модели Kronos помечена как `RAW_PRETRAIN_LEAKAGE_SUSPECTED`: модель обучена на данных, которые, вероятно, перекрываются с данными бэктеста. Это значит, что результаты бэктеста статистически невалидны. Реальный прогон (без утечки данных) показал убыток: −5.61% на часовых барах, −10.24% на пятиминутных. (README.md, секция Kronos ML)

**Дисклеймер:** этот проект — исследовательский, не торговый советник. Протестированные стратегии не прошли критерии качества. Ничто на этих страницах не является финансовой рекомендацией.

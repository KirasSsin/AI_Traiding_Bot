# Дашборд — общий обзор и запуск

**TL;DR:** Дашборд — это локальный веб-интерфейс, который открывается в браузере и позволяет запускать проверку торговых стратегий на исторических данных, не трогая реальные деньги. Четыре вкладки: проверить стратегию, посмотреть результаты, изучить справку, открыть глоссарий.

## Простыми словами

Представьте, что у вас есть торговый план и вы хотите проверить: «а что, если бы я торговал по этому плану два года назад — заработал или потерял?». Дашборд делает именно это: берёт записи прошлых цен (это и есть **исторические данные** — котировки, которые уже случились) и «прокручивает» по ним стратегию, как будто торговля шла вживую.

Такая проверка называется **[[what-is-backtest-overview|бэктест]]** (от английского backtest — «тест на истории»). Это не гарантия будущего дохода, но позволяет выловить очевидно плохие стратегии до того, как они потратят реальные деньги.

Дашборд — это сугубо **инструмент разработчика**: он работает только у вас на компьютере (на адресе `localhost`, то есть «на этом самом устройстве»), логинов нет намеренно, данные никуда не отправляются (кроме запросов к Bybit API для получения баланса счёта). Это не торговая платформа — только исследовательский стенд.

Аналогия из жизни: дашборд похож на Excel-таблицу с кнопкой «посчитать», куда вы вводите условия сделки и получаете итоговый отчёт. Только красивее и быстрее.

## Как это работает у нас

### Запуск

Дашборд запускается одной командой:

```bash
./scripts/dashboard.sh
```

Скрипт проверяет наличие виртуального окружения `.venv` и зависимостей, затем запускает Python-модуль `src.dashboard.app` (src/dashboard/app.py:349–374). Адрес автоматически открывается в браузере спустя 1,5 секунды.

Альтернативный способ через Python напрямую:

```bash
.venv/bin/python -m src.dashboard.app
```

Сервер слушает только адрес `127.0.0.1:8000` — это означает «только этот компьютер». Снаружи (из интернета или соседней машины) он недоступен. (src/dashboard/app.py:353–370)

### Архитектура: FastAPI + React

Сервер написан на **FastAPI** — это Python-библиотека для построения веб-API (программного интерфейса, через который браузер запрашивает данные у сервера). Браузерный интерфейс написан на **React** — это JavaScript-фреймворк для построения интерактивных веб-страниц.

Схема взаимодействия:

```text
Браузер (React SPA)
      │
      │  HTTP запросы к /api/*
      ▼
FastAPI-сервер (src/dashboard/app.py)
      │
      │  вызывает backtest pipeline
      ▼
data/runs/<run_id>.json  ← кеш результатов
```

**SPA (Single-Page Application)** — это веб-приложение, которое загружается один раз как единый файл, а потом все переходы между вкладками происходят внутри браузера без перезагрузки страницы. Файлы React-сборки находятся в `src/dashboard_react/dist/` и раздаются FastAPI-сервером как статические файлы. (src/dashboard/app.py:54–55, 144–161)

Точка входа создаётся через `create_app()` — **фабрика приложения** (паттерн, при котором приложение не создаётся автоматически при импорте, а собирается функцией — это упрощает тестирование). (src/dashboard/app.py:135)

### Структура вкладок

Дашборд состоит из четырёх вкладок (src/dashboard_react/src/App.tsx:21–26):

| № | Название | Назначение |
|---|----------|------------|
| 01 | BACKTEST | Настроить и запустить бэктест, посмотреть результаты |
| 02 | DOCUMENTATION | Справочник: индикаторы, мультипликаторы, стратегии, методология ([[documentation-tab]]) |
| 03 | HISTORY | Таблица всех ранее запущенных бэктестов ([[history-tab]]) |
| 04 | GLOSSARY | Словарь терминов с поиском и фильтрацией по стратегии ([[glossary-tab]]) |

Вкладки переключаются без перезагрузки страницы — это типичное поведение SPA (src/dashboard_react/src/App.tsx:28–99).

### Кеширование результатов бэктеста

Запуск бэктеста — тяжёлая операция (30–60 секунд). Чтобы не пересчитывать одно и то же дважды, результат сохраняется в файл `data/runs/<run_id>.json`.

**run_id** — это уникальный идентификатор запроса: первые 16 символов SHA-256 хеша от комбинации (стратегия + символ + таймфрейм + дата начала + дата конца). Если вы запускаете те же параметры повторно — сервер отдаёт файл с диска, не запуская pipeline заново. Технические детали кеша и защиты запросов — в [[caching-and-security]]. (src/dashboard/backtest_runner.py:857–921)

Галочка **FORCE_RECOMPUTE** в форме обходит кеш и запускает pipeline заново (src/dashboard/backtest_runner.py:919).

### CacheControlMiddleware — почему браузер не «застревает» на старых данных

После React-сборки (команды `npm run build`) файлы вида `/assets/main-abc123.js` содержат в имени хеш содержимого — значит, при изменении кода имя файла меняется. Эти файлы можно кешировать в браузере навечно.

Но `index.html` и все адреса `/api/*` — динамические. Их нельзя кешировать, иначе браузер будет показывать устаревший HTML или старые данные.

Middleware выставляет правильные заголовки автоматически (src/dashboard/app.py:318–330):

```python
if path.startswith("/assets/"):
    response.headers["Cache-Control"] = "public, immutable, max-age=31536000"
else:
    response.headers["Cache-Control"] = "no-cache, no-store, must-revalidate"
```

`max-age=31536000` = один год в секундах. `no-store` = браузер не сохраняет вообще.

### Безопасность: нет авторизации — намеренно

Дашборд работает только на `127.0.0.1` (loopback — петлевой адрес, недоступный снаружи). Авторизация не нужна, потому что никто кроме вас и не может подключиться. Это осознанное архитектурное решение «dev tool только локально» (src/dashboard/app.py:2–4).

При этом есть защита от атак на файловую систему: поле `symbol` в запросе бэктеста проверяется регулярным выражением `\A[A-Z0-9]{1,20}\Z` — только заглавные буквы и цифры, от 1 до 20 символов, никаких слешей, точек или других специальных символов, которые могли бы позволить «вылезти» из папки с данными (path traversal). Проверка происходит до того, как строка попадает в путь к файлу. (src/dashboard/app.py:57–109)

### Баланс Bybit: TTL-кеш и graceful fallback

Если на компьютере есть API-ключи Bybit (переменные окружения `BYBIT_API_KEY` и `BYBIT_API_SECRET`), дашборд запрашивает текущий баланс счёта и показывает его в форме. Если ключей нет или запрос не удался — показывается заглушка `10 000 USDT` с пометкой `fallback`. Подробнее об источниках баланса — в [[account-balance]]. (src/dashboard/account_service.py:110–172)

Чтобы не ходить на Bybit при каждом обращении к форме, результат кешируется на **5 секунд** (`_BALANCE_TTL_SECONDS = 5.0`). Только успешные ответы от Bybit попадают в кеш; ошибки не кешируются, чтобы повторный запрос мог получить реальные данные. (src/dashboard/account_service.py:37–38, 159–162)

### Стратегии и таймфреймы

Список доступных стратегий задан в `STRATEGY_PRESETS` в `backtest_runner.py`. Карта всех стратегий с их логикой — в [[strategies-overview]]. На момент написания документации это 8 пресетов в 5 категориях:

| Категория | Стратегии |
|-----------|-----------|
| Тренд-следование | EMA 12/26 + ADX |
| Тренд | Supertrend (ATR) |
| Возврат к среднему | RSI/Bollinger классика, RSI/Bollinger мягкий |
| Прорывы | Канал Дончиана, Volume breakout, ATR-адаптивный пробой |
| ML / Прогноз | Kronos ML (Transformer) |

(src/dashboard/backtest_runner.py:47–286)

Поддерживаемые таймфреймы: 5 минут, 15 минут, 1 час, 4 часа, 1 день. 30-минутный и 2-часовой таймфреймы намеренно исключены — модель данных [[bar-model|Bar]] их не поддерживает. (src/dashboard/backtest_runner.py:291–296)

## Примеры / сценарии

### Сценарий 1 — первый запуск дашборда

1. Открываем терминал в папке проекта.
2. Запускаем `./scripts/dashboard.sh` — скрипт проверяет `.venv`, запускает uvicorn.
3. Через 1,5 секунды браузер автоматически открывает `http://127.0.0.1:8000/`.
4. Перед нами вкладка **01 BACKTEST** с формой.
5. Выбираем стратегию «Supertrend», символ `BTCUSDT`, таймфрейм `1 hour`, период с 2023-01-01 по 2026-01-01.
6. Нажимаем **▶ EXECUTE**. Кнопка показывает «⏵ EXECUTING», ждём 30–60 секунд.
7. Появляется [[verdict-and-warnings|вердикт]], [[equity-chart-and-drawdown|график доходности]], [[metrics-table-tiers|таблица метрик]].
8. При повторном запуске тех же параметров — результат возвращается мгновенно (из файла кеша).

### Сценарий 2 — React-сборка отсутствует

Если папка `src/dashboard_react/dist/` не существует (например, после свежего клонирования репозитория без фронтенд-сборки), сервер отвечает на корневой адрес сообщением:

```text
React build missing
Run npm run build в src/dashboard_react/
```

Код: 503 Service Unavailable. (src/dashboard/app.py:153–161)

### Сценарий 3 — вкладка HISTORY

Переходим на вкладку **03 HISTORY** ([[history-tab]]). Появляется таблица всех запусков из папки `data/runs/`. Каждая строка кликабельна — раскрывается аккордеон с деталями: начальный баланс, итоговый баланс, win rate, краткое резюме вердикта на русском языке. Закрыть аккордеон можно кнопкой «✕ закрыть» или клавишей Escape.

## Подводные камни / что важно понимать

**Дашборд — это симуляция, не реальная торговля.** Все операции с деньгами в бэктесте — условные. Кнопка «▶ EXECUTE» не отправляет никаких ордеров на биржу.

**Кеш не протухает автоматически.** Если вы обновили данные или параметры стратегии, а потом запустили те же параметры — дашборд отдаст старый результат из `data/runs/`. Включите **FORCE_RECOMPUTE**, чтобы пересчитать.

**Один бэктест за раз.** Внутри `run_backtest()` стоит `threading.Lock` — одновременно выполняется только один расчёт. Если запустить два бэктеста параллельно, второй подождёт завершения первого. (src/dashboard/backtest_runner.py:10)

**Без сборки React — ничего не работает.** Если вы меняете TypeScript-код интерфейса, нужно заново собрать его командой `npm run build` в папке `src/dashboard_react/`. Иначе браузер покажет старую версию (или сообщение «React build missing»).

**Бэктест на истории ≠ результат в будущем.** Бэктест сообщает, «как было бы», а не «как будет». Хорошие результаты на исторических данных не гарантируют прибыль в реальной торговле — рынок меняется. Именно для этого в проекте используется строгая процедура WFA (проверка за пределами обучающего периода): подробнее в [[wfa-methodology]].

**«Заблокирована» комбинация символа и таймфрейма.** Часть стратегий имеет фиксированные пары (например, ATR-пробой только для конкретных комбинаций). Если выбрать запрещённую комбинацию, поле в выпадающем меню покажется неактивным, а сервер вернёт ошибку 422. Это защита от запуска стратегии с параметрами, для которых нет подобранных констант. (src/dashboard/app.py:221–254)

**Баланс Bybit — только для справки.** Значение в поле «INITIAL BALANCE» подтягивается с вашего реального счёта, чтобы бэктест считался на реалистичной сумме. Но само поле редактируемое — вы можете поставить любое число.

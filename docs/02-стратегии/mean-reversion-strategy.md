# Стратегия возврата к среднему (RSI + полосы Боллинджера)

**TL;DR:** Бот ждёт, когда цена одновременно упадёт ниже «нижней границы нормы» (полосы Боллинджера) и RSI уйдёт в зону перепроданности — тогда открывает длинную позицию. Закрывает её, как только цена восстанавливается (RSI или верхняя граница). Параметры «залочены» по результатам статистического тестирования: стандартные числа из учебников давали шум, а не сигнал.

## Простыми словами

Представьте, что вы покупаете акции на распродаже. Но вам нужна двойная гарантия того, что это именно распродажа, а не начало краха:

1. **Цена слишком низко** — она ушла за нижний край «нормального коридора» (как если бы цена хлеба упала ниже себестоимости — явная аномалия).
2. **Покупатели явно устали продавать** — специальный индикатор перепроданности (RSI) говорит «достаточно, все уже продали всё что хотели».

Только когда оба признака совпадают одновременно — бот входит в позицию. Это называется **AND-гейт** (от английского «И» — обе двери должны открыться вместе).

Выйти из сделки бот готов при первом же признаке восстановления — либо RSI сигнализирует о перекупленности, либо цена поднялась выше верхнего края нормального коридора (OR-логика, то есть достаточно любого одного).

Название стратегии — **возврат к среднему** (mean reversion) — отражает идею: рынок рано или поздно возвращается к «нормальному» уровню после экстремального отклонения. Как резинка: чем сильнее растянули — тем сильнее отскок.

> Аналогия из жизни: стратегия работает как охотник за скидками, который идёт в магазин только когда цена упала ниже исторического минимума И на улице стоит очередь недовольных продавцов. Если выполняется только одно из двух — проходит мимо.

## Как это работает у нас

### Шаг 1. Поступает новая закрытая свеча

Метод `on_bar(bar)` вызывается один раз на каждую закрытую свечу (бар). Свечи с флагом `is_closed=False` отфильтровываются и не обрабатываются. Также не принимаются свечи не по нашему символу или пришедшие вне хронологического порядка (дедупликация по `close_time`).

```python
# src/signalgen/mean_reversion_strategy.py:133-136
def on_bar(self, bar: Bar) -> Signal | None:
    if not self._append_bar(bar):
        return None
```

(src/signalgen/mean_reversion_strategy.py:116–127)

### Шаг 2. Прогрев буфера — нужно накопить историю

Бот не может посчитать RSI или полосы Боллинджера по одной свече — нужна история. Минимальное количество свечей для работы:

```
min_required = max(rsi_period, bb_period) + 1
```

При залоченных параметрах (RSI 14, BB 20): `max(14, 20) + 1 = 21 свеча`. Пока их меньше — `on_bar` возвращает `None`, сигналов нет.

Буфер хранит последние `max(rsi_period, bb_period, atr_period) + 5` свечей (с запасом +5 для безопасности). При залоченных параметрах: `max(14, 20, 14) + 5 = 25 свечей`.

(src/signalgen/mean_reversion_strategy.py:91–93, 138–140)

### Шаг 3. Расчёт трёх индикаторов

На каждый новый бар бот считает три числа:

**[[ema-rsi-indicators|RSI]] (Индекс относительной силы)** — показывает, перепродан или перекуплен рынок по шкале от 0 до 100. Значение ниже порога (35 в залоченных параметрах) означает «слишком много продавали, рынок перепродан».

Наша реализация использует библиотеку TA-Lib с методом сглаживания Уайлдера (α = 1/period), а не классическое экспоненциальное сглаживание. Первые `period` (14) значений — NaN (прогрев).

(src/signalgen/indicators.py:47–64)

**[[bollinger-bands-indicator|Полосы Боллинджера]]** — три линии вокруг скользящего среднего цены:
- Средняя полоса = SMA за 20 свечей (простое среднее).
- Верхняя полоса = среднее + k × σ (стандартное отклонение).
- Нижняя полоса = среднее − k × σ.

Подробнее о расчёте — в секции «Формулы и расчёты» ниже.

(src/signalgen/bollinger_bands.py:15–55)

**[[atr-indicator|ATR]] (средний истинный диапазон)** — мера волатильности, показывает насколько «прыгает» цена. Бот считает его и записывает в сигнал, но для принятия решений о входе/выходе не использует — это поле заполняется для журнала сделок.

(src/signalgen/indicators.py:67–81, mean_reversion_strategy.py:150–151)

### Шаг 4. Проверка условий входа (AND-гейт)

Бот проверяет вход только если сейчас не в позиции (`SignalSide.FLAT`). Оба условия должны выполняться одновременно:

```python
# src/signalgen/mean_reversion_strategy.py:167-175
if (
    self._current_side == SignalSide.FLAT
    and rsi_val < self._rsi_oversold          # RSI < 35
    and close_val < snapshot["bb_lower"]      # цена < нижняя полоса BB
):
    self._current_side = SignalSide.LONG
    return self._build_signal(..., reason=ReasonCode.ENTRY_LONG_MEANREV_RSI_BB.value)
```

[[reason-codes-assessment-output|Reason code]] `ENTRY_LONG_MEANREV_RSI_BB` — метка в журнале, по которой можно найти все сделки именно этой стратегии.

(src/signalgen/mean_reversion_strategy.py:167–175, src/risk/reason_codes.py:140)

### Шаг 5. Проверка условий выхода (OR-логика)

Если бот уже в длинной позиции (`SignalSide.LONG`), он проверяет два условия для выхода — достаточно любого одного:

```python
# src/signalgen/mean_reversion_strategy.py:178-184
if self._current_side == SignalSide.LONG and (
    rsi_val > self._rsi_overbought             # RSI > 65
    or close_val > snapshot["bb_upper"]        # цена > верхняя полоса BB
):
    self._current_side = SignalSide.FLAT
    return self._build_signal(..., reason=ReasonCode.EXIT_FLAT_MEANREV_REVERT.value)
```

Reason code `EXIT_FLAT_MEANREV_REVERT` — метка выхода.

(src/signalgen/mean_reversion_strategy.py:178–184, src/risk/reason_codes.py:141)

### Шаг 6. Формирование сигнала

Сигнал ([[signal-architecture|`Signal`]]) — это сообщение, которое стратегия передаёт дальше исполнителю. В нём: идентификатор, символ, сторона (LONG или FLAT), время свечи, значения RSI и ATR на момент сигнала.

Важная деталь: у стратегии возврата к среднему нет EMA и ADX (они используются другой стратегией — [[ema-crossover-strategy|EMA Crossover]]). Тем не менее поля в Signal есть — они заполняются нулями-заглушками. Это сделано намеренно: чтобы стратегии были взаимозаменяемы в одной системе (drop-in replacement).

```python
# src/signalgen/mean_reversion_strategy.py:197-210
ema_fast=Decimal("0"),
ema_slow=Decimal("0"),
adx_14=Decimal("0"),
plus_di_14=Decimal("0"),
minus_di_14=Decimal("0"),
rsi_14=Decimal(str(snapshot["rsi"])),
atr_14=Decimal(str(snapshot["atr"])),
```

(src/signalgen/mean_reversion_strategy.py:197–211)

### Шаг 7. Исполнение — на открытии следующей свечи

Сигнал на основе закрытия свечи T исполняется на открытии свечи T+1 (подробнее о пути сигнала к ордеру — [[order-lifecycle-overview|жизненный цикл ордера]]). Это строгое правило (anti-look-ahead), записанное в заголовке файла:

> «Invariant: signal on close(T) → execution at open(T+1) — no look-ahead»

(src/signalgen/mean_reversion_strategy.py:11–12)

## Формулы и расчёты

### Полосы Боллинджера

**Формула:**
```text
Средняя полоса  = SMA(цена_закрытия, N)
Верхняя полоса  = SMA + k × σ_pop
Нижняя полоса   = SMA − k × σ_pop
```

**Простыми словами:** Берём среднюю цену за N свечей. Затем считаем, насколько цена «гуляла» вокруг этой средней (стандартное отклонение σ). Добавляем k раз это отклонение вверх — получаем «верхний потолок нормы», вычитаем вниз — «нижний пол нормы».

**Наша реализация:** Используется σ с `ddof=0` (популяционное стандартное отклонение, то есть делим на N, а не N−1). Это оригинальная формула Боллинджера. Первые `period − 1` значений — NaN.

```python
# src/signalgen/bollinger_bands.py:50-53
s = float(np.std(window, ddof=0))   # population stdev per Bollinger
middle[i] = m
upper[i] = m + k * s
lower[i] = m - k * s
```

(src/signalgen/bollinger_bands.py:47–53)

### RSI (Индекс относительной силы)

Подробная математика RSI описана в [[technical-indicators]] (страница индикаторов). Здесь — только то, что важно для нашей стратегии:

- RSI возвращает число от 0 до 100.
- Реализован через TA-Lib с методом сглаживания Уайлдера (α = 1/period, а не α = 2/(period+1) как у классической EMA). Это важно для воспроизводимости в бэктесте.
- Первые `period` (14) значений — NaN.

(src/signalgen/indicators.py:47–64)

### Залоченные параметры (MEAN_REVERSION_S17_RELAXED_PARAMS)

Бот использует не «учебные» значения параметров, а проверенные исторически:

| Параметр | Залоченное значение | Стандартное («учебное») | Почему не стандарт |
|----------|--------------------|--------------------------|--------------------|
| `rsi_oversold` | **35** | 30 | При пороге 30 — MC p=0.998 (шум) |
| `rsi_overbought` | **65** | 70 | При пороге 70 — MC p=0.998 (шум) |
| `bb_std_mult` (k) | **1.5σ** | 2.0σ | При 2σ — MC p=0.998 (шум) |
| `rsi_period` | 14 | 14 | Совпадает |
| `bb_period` | 20 | 20 | Совпадает |
| `and_gate_required` | `True` | — | AND, не OR |

**MC p-value** ([[mc-permutation-test|Monte Carlo p-value]]) — это статистический тест: он запускает стратегию тысячи раз на перемешанных (случайных) данных и проверяет, могли ли такие результаты получиться случайно. p=0.998 означает «99.8% вероятность, что результат — случайность». p=0.018 (из docstring, line 102) или p=0.01 (из комментария, line 35) означает «вряд ли случайность».

(src/signalgen/mean_reversion_strategy.py:35–36, 43–52, 102)

Словарь параметров защищён от изменений через `MappingProxyType` — любая попытка изменить значение во время работы вызовет `TypeError`. Это сделано намеренно: бот работает с реальными деньгами на TESTNET, и случайная мутация параметров в тесте или монкипатчинге могла бы незаметно сломать «залоченный» договор.

(src/signalgen/mean_reversion_strategy.py:39–52)

## Примеры / сценарии

### Сценарий 1 — Вход в позицию (AND-гейт сработал)

Допустим, торгуется BTCUSDT на 1-часовых свечах:

- Последние 20 часов: BTC падал, цена снизилась с 70 000 до 66 000 USDT.
- Текущая свеча закрылась: цена = 65 800 USDT.

Бот считает:
- SMA(20) = 68 200 USDT; σ = 1 200 USDT; k = 1.5.
- Нижняя полоса BB = 68 200 − 1.5 × 1 200 = **66 400 USDT**.
- Цена закрытия (65 800) < нижней полосы (66 400) → **условие BB выполнено**.
- RSI(14) = 32 < 35 → **условие RSI выполнено**.

Оба условия выполнены одновременно → бот генерирует сигнал `ENTRY_LONG_MEANREV_RSI_BB`. На открытии следующей свечи (T+1) исполнитель покупает.

### Сценарий 2 — Выход (RSI восстановился первым)

Через 8 часов BTC вырос до 67 500 USDT:
- RSI(14) = 68 > 65 (порог `rsi_overbought`) → **условие выхода по RSI выполнено**.
- Верхняя полоса BB = 68 200 + 1.5 × 800 = 69 400 USDT. Цена (67 500) < 69 400 → **условие BB не выполнено**.

Но достаточно одного (OR-логика) → бот генерирует сигнал `EXIT_FLAT_MEANREV_REVERT`. На открытии следующей свечи закрывает позицию.

### Сценарий 3 — Сигнал не выдан (AND не выполнен)

Та же ситуация, но RSI = 38 (выше порога 35):
- Цена < нижней BB — **да**.
- RSI = 38 < 35 — **нет**.

AND-гейт заблокирован → `on_bar` возвращает `None`, позиция не открывается.

### Сценарий 4 — Прогрев, первые 20 свечей

Стратегия только создана, буфер пустой. Первые 20 свечей накапливаются через `warmup(bar)` — сигналов нет. На 21-й свече `on_bar` начинает вычислять индикаторы. К этому моменту все три значения снимка (RSI[-1], полосы Боллинджера, ATR) уже не NaN: talib RSI с периодом 14 становится non-NaN начиная с 15-й свечи (первые `period` значений — NaN, согласно docstring `indicators.py:57`), BB готов с 20-й, ATR — с 14-й. NaN-гейт на строке 160 не срабатывает, и первый сигнал возможен ровно на 21-й свече.

(src/signalgen/mean_reversion_strategy.py:138–161, src/signalgen/indicators.py:47–64)

## Подводные камни / что важно понимать

**1. AND-гейт строже — меньше сделок, выше качество.**
Требование двух одновременных условий (RSI < 35 И цена < нижней BB) резко сокращает число сигналов по сравнению с OR-логикой. Это намеренно: меньше ложных срабатываний.

**2. Параметры нельзя просто «поменять на стандартные».**
Стандартные RSI 30/70 и BB 2σ давали MC p=0.998 — результат неотличим от случайного шума. Залоченные параметры (RSI 35/65, BB 1.5σ) дали p≈0.01–0.018 по результатам тестирования в Sprint 17 и 22. Смена параметров без повторного тестирования обесценивает всю проверку.

(src/signalgen/mean_reversion_strategy.py:35–36)

**3. Мутация залоченных параметров вызовет ошибку.**
`MEAN_REVERSION_S17_RELAXED_PARAMS` — это `MappingProxyType`. Попытка `MEAN_REVERSION_S17_RELAXED_PARAMS["rsi_oversold"] = 30` бросит `TypeError`. Это защита: если кто-то случайно попробует «переключить» бота на старые параметры через тест или конфиг — сразу получит ошибку, а не молчаливое изменение поведения.

(src/signalgen/mean_reversion_strategy.py:39–52)

**4. Фабричный метод `from_locked_s17_params()` — единственная «правильная» точка подключения в production.**
Когда `s35_demo_active=True` (демо-режим на TESTNET), бот **обязан** создаваться через `from_locked_s17_params(symbol=...)`, а не вручную. Это гарантирует точное соответствие проверенным параметрам.

(src/signalgen/mean_reversion_strategy.py:97–114, src/__main__.py:147–154)

**5. Поля EMA/ADX в сигнале всегда равны нулю.**
Это не ошибка. Стратегия не считает EMA и ADX — они нужны другой стратегии (EMA Crossover). Нули-заглушки позволяют обеим стратегиям возвращать один и тот же тип `Signal` и работать в одной системе без изменений кода.

(src/signalgen/mean_reversion_strategy.py:197–210)

**6. Стратегия не потокобезопасна — один экземпляр на один поток.**
Если несколько потоков будут одновременно вызывать `on_bar` у одного экземпляра — данные буфера могут исказиться. Для нескольких символов создаётся отдельный экземпляр на каждый.

(src/signalgen/mean_reversion_strategy.py:14–15)

**7. Разница p=0.01 и p=0.018 в коде.**
В двух местах кода приводятся немного разные значения: комментарий к константе (строка 35) называет `MC p=0.01`, а docstring `from_locked_s17_params` (строка 102) — `MC p=0.018`. Оба относятся к S17/S22 тестированию relaxed-параметров и означают «статистически значимо». Точное значение зависит от версии теста и количества перестановок.

# Как Kronos принимает решения о входе и выходе

**TL;DR:** Kronos смотрит на прогноз цены следующей свечи: если предсказанный рост больше 0.6% (порог покрытия торговых расходов) — покупает; если прогноз ниже текущей цены — выходит. Никаких шортов, никаких сложных условий.

## Простыми словами

Представьте, что у вас есть помощник-предсказатель. Перед закрытием каждой свечи он говорит вам: «По моей оценке, через один период цена будет вот такой». Дальше вы принимаете простое решение:

- Прогнозируемая цена **заметно выше** текущей — значит, есть смысл **купить** сейчас.
- Прогнозируемая цена **ниже** текущей — значит, держать позицию невыгодно, **выходим**.
- Прогнозируемая цена выросла, но **совсем чуть-чуть** — торговать не стоит: комиссии и проскальзывание съедят весь заработок.

Это и есть V3-правило сигнала Kronos — простой фильтр «стоит ли вообще торговать на этом прогнозе».

Важная деталь: стратегия **только покупает** (long-only). Открыть короткую позицию («поставить на падение») она не может — это сознательное ограничение для spot-торговли на Bybit.

**Аналогия из жизни.** Вы смотрите на прогноз погоды: «завтра +2°C». Сегодня +18°C. Вы надеваете куртку? Нет. Но если прогноз говорит «завтра −10°C» — вы точно что-то предпримете. Kronos работает по тому же принципу: реагирует только на прогнозы, достаточно сильно отличающиеся от текущего положения дел.

## Как это работает у нас

Вся логика принятия решений сосредоточена в одной функции — `on_bar(bar)` — класса `KronosStrategy` (`src/signalgen/kronos_strategy.py:112`). Функция вызывается ботом каждый раз, когда **закрывается** очередная [[bar-model|свеча (бар)]].

### Шаг 1 — Защитные проверки (гейты)

Прежде чем что-то решать, функция выполняет два обязательных условия:

```python
if not bar.is_closed:
    return None
if bar.symbol != self._symbol:
    return None
```
(src/signalgen/kronos_strategy.py:120–123)

- Незакрытая свеча — сигнал не выдаётся. Это принципиально: если бы бот реагировал на данные незакрытой свечи, он «заглядывал бы в будущее» (read-ahead). Ещё раз: закрытая свеча — это исторический факт; незакрытая — неизвестно, чем она закончится.
- Чужой символ (например, пришли данные по ETHUSDT, а стратегия настроена на BTCUSDT) — игнорируется.

### Шаг 2 — Обновление ATR

[[atr-indicator|ATR]] (Average True Range) — это мера «размаха» движения цены за последние N свечей. Простыми словами: насколько сильно цена «прыгала» в последнее время. ATR нужен стратегии не для принятия решения о входе, а для расчёта стоп-лосса и тейк-профита — уровней «выхода с убытком / выходом с прибылью» — которые передаются дальше в [[risk-overview-decision-pipeline|риск-менеджер]].

```python
self._atr.update(float(bar.high), float(bar.low), float(bar.close))
if self._atr.current is not None:
    self._last_atr = Decimal(str(self._atr.current))
```
(src/signalgen/kronos_strategy.py:128–130)

ATR рассчитывается инкрементально по [[wilder-atr-and-stops|методу Уайлдера]] (класс `_WilderATR`, позаимствованный из стратегии [[atr-breakout-strategy|ATR Breakout]]) — с каждой новой свечой добавляется одно новое значение, а не пересчитывается с нуля. Это быстро и не требует хранить всю историю. По умолчанию период равен 14 свечам (`atr_period=14`, src/signalgen/kronos_strategy.py:77).

### Шаг 3 — Получение прогноза из кэша

Kronos — ML-модель, которая заранее (до торговли) обработала исторические данные и сохранила предсказания в специальное хранилище — **кэш прогнозов**. Стратегия не запускает модель в реальном времени: она просто берёт уже готовый прогноз.

Ключ поиска строится из семи полей: идентификатор модели, хеш весов, символ, таймфрейм, временная метка закрытия текущей свечи, хеш параметров выборки и устройство вычисления (`src/signalgen/kronos_strategy.py:133–141`).

```python
key = CacheKey(
    model_id=self._model_id,
    weights_hash=self._weights_hash,
    symbol=self._symbol,
    timeframe=self._timeframe,
    bar_close_ts=int(bar.close_time.timestamp()),
    params_hash=self._params_hash,
    device=self._device,
)
prediction = self._cache.get(key)
```

Ключевой момент безопасности: `bar_close_ts = int(bar.close_time.timestamp())` — временна́я метка **текущей** закрытой свечи, не следующей. Таким образом, стратегия никогда не может случайно прочитать прогноз, относящийся к будущему бару.

Подробнее об устройстве кэша — в [[kronos-offline-predict-cache]].

### Шаг 4 — Обработка промаха кэша (cache miss)

Если для данного бара прогноз в кэше отсутствует — функция возвращает `None`, торговля не происходит, ошибки нет:

```python
if not prediction:
    return None
```
(src/signalgen/kronos_strategy.py:144–145)

Это называется **cache miss** (промах кэша) — ситуация, когда нужный элемент в хранилище отсутствует. Стратегия деградирует корректно: просто пропускает этот бар, не блокируя весь бот.

### Шаг 5 — Применение V3-правила сигнала

После получения прогноза стратегия применяет главное правило (V3, LOCKED — зафиксированное как окончательное в ADR 0068):

```python
pred_close = prediction[0]   # горизонт = 1 → один прогнозируемый close
current_close = bar.close
```
(src/signalgen/kronos_strategy.py:147–148)

**Правило входа (LONG):** применяется только если бот сейчас вне рынка (состояние FLAT):

```python
if self._current_side == SignalSide.FLAT and pred_close > current_close * (
    Decimal(1) + self._threshold
):
```
(src/signalgen/kronos_strategy.py:151–153)

Дополнительная защита перед входом: если ATR ещё не прогрелся (накопилось меньше 14 свечей), вход запрещён:

```python
if self._last_atr is None or self._last_atr <= 0:
    return None
```
(src/signalgen/kronos_strategy.py:156–157)

Без прогретого ATR нельзя рассчитать стоп-лосс — войти без стоп-лосса значит торговать без страховки.

**Правило выхода (FLAT):** применяется только если бот сейчас держит позицию (состояние LONG):

```python
if self._current_side == SignalSide.LONG and pred_close < current_close:
```
(src/signalgen/kronos_strategy.py:161)

Выход не требует прогретого ATR — закрыть позицию можно в любой момент.

### Шаг 6 — FSM: конечный автомат состояний

Стратегия отслеживает, находится ли бот в позиции или нет, через переменную `_current_side`. Это называется **конечный автомат** (FSM, Finite State Machine) — система, у которой есть чётко ограниченный набор состояний и правила переходов между ними. Это внутренний мини-автомат самой стратегии, не путать с [[execution-state-machine|конечным автоматом исполнения ордера]] на стороне зоны исполнения.

У Kronos всего два состояния:

```
FLAT (вне рынка)  →[прогноз +0.6%]→  LONG (в позиции)
LONG (в позиции)  →[прогноз < цены]→  FLAT (вне рынка)
```

Начальное состояние — FLAT (`src/signalgen/kronos_strategy.py:110`).

Что это даёт:
- **Двойной вход невозможен** (TL-06): бот, уже находясь в позиции LONG, не выдаст ещё один сигнал LONG — условие `self._current_side == SignalSide.FLAT` заблокирует его.
- **Призрачный выход невозможен**: бот не попытается закрыть позицию, которой нет — условие `self._current_side == SignalSide.LONG` заблокирует ложный выход.
- **SHORT никогда не возникнет**: в коде нет состояния SHORT, нет перехода в него и нет сигнала с `SignalSide.SHORT`.

### Шаг 7 — Формирование объекта Signal

При срабатывании правила (вход или выход) создаётся объект [[signal-architecture|`Signal`]]:

```python
return self._build_signal(bar, SignalSide.LONG, ReasonCode.ENTRY_LONG_KRONOS)
# или
return self._build_signal(bar, SignalSide.FLAT, ReasonCode.EXIT_FLAT_KRONOS)
```
(src/signalgen/kronos_strategy.py:159, 165)

Signal содержит метку причины (`reason`): `ENTRY_LONG_KRONOS` или `EXIT_FLAT_KRONOS` — [[reason-codes-assessment-output|коды из канонического реестра]] `ReasonCode` (`src/risk/reason_codes.py:151–152`). Они попадают в журнал аудита и позволяют однозначно установить, какая стратегия и по какому правилу вызвала действие.

Индикаторы EMA, RSI, ADX, которые используются другими стратегиями, Kronos не вычисляет — их поля в Signal заполняются нулём (`_ZERO`, src/signalgen/kronos_strategy.py:48). В поле `atr_14` ставится текущее значение Wilder ATR — оно нужно риск-менеджеру для расчёта стоп-лосса.

## Формулы и расчёты

### V3-правило входа

```
Условие входа:  pred_close > current_close × (1 + threshold)
```

Расшифровка простыми словами: прогнозируемая цена закрытия следующей свечи должна быть **строго больше** текущей цены закрытия, умноженной на коэффициент `(1 + threshold)`.

При `threshold = 0.006`:

```
current_close = 100 000 USDT (гипотетически)
порог входа   = 100 000 × 1.006 = 100 600 USDT
```

Если `pred_close > 100 600` — вход. Если `pred_close = 100 500` — нет сигнала (прогноз в «мёртвой зоне»).

### V3-правило выхода

```
Условие выхода:  pred_close < current_close
```

Если прогноз ниже текущей цены хотя бы на 0.01 USDT — выходим. Порог здесь не применяется: достаточно любого предсказания снижения.

### Откуда взялось значение 0.6%

Порог — это не «красивое» число, а прямой расчёт торговых расходов (ADR 0068, PHASE 6 FIX 1):

| Статья расходов | За одну сторону | Туда-обратно |
|---|---|---|
| Комиссия биржи | 0.10% | 0.20% |
| Проскальзывание (slippage) | 0.05% | 0.10% |
| **Итого round-trip cost** | **0.15%** | **0.30%** |

Порог = **2 × round-trip cost = 2 × 0.30% = 0.60%**.

Почему двойной? Потому что один round-trip cost — это лишь точка безубыточности. При ожидаемом росте ровно на 0.30% сделка не принесёт ни прибыли, ни убытка. Чтобы оставался запас на реальную прибыль и статистические погрешности прогноза, порог удвоен.

Важная история: исходно (до PHASE 6 review) порог был установлен в 0.25% — **ниже** break-even уровня (0.30%). Это была арифметическая ошибка, которую обнаружил рецензент-квант и исправил до 0.60% (ADR 0068, Поправка PHASE 6, FIX 1).

Реализация в коде:

```python
DEFAULT_THRESHOLD = Decimal("0.006")
```
(src/signalgen/kronos_strategy.py:46)

Threshold настраивается при создании объекта стратегии — это параметр `__init__`, который по умолчанию равен `DEFAULT_THRESHOLD`.

### Wilder ATR (прогрев индикатора)

ATR по методу Уайлдера требует «прогрева»: первые 13 свечей (при периоде 14) накапливаются для вычисления начального среднего значения. Начиная с 14-й свечи применяется рекуррентная формула:

```
ATR[i] = (ATR[i-1] × (period − 1) + TR[i]) / period
```

где `TR[i]` — True Range i-й свечи (максимальный из трёх значений: `high − low`, `|high − prev_close|`, `|low − prev_close|`).

До прогрева (`_last_atr is None or _last_atr <= 0`) вход в позицию невозможен — стратегия вернёт `None` даже при идеальном прогнозе (`src/signalgen/kronos_strategy.py:156–157`).

## Примеры / сценарии

### Сценарий 1 — Нормальный вход

Допустим, бот торгует BTCUSDT на часовых свечах. Прошло 14 свечей, ATR прогрет до 450 USDT. Текущий бар закрылся по цене 98 000 USDT.

Стратегия строит ключ кэша с временной меткой этого бара и получает прогноз: `pred_close = 99 200 USDT`.

Проверяем условие входа:
```
99 200 > 98 000 × 1.006 = 98 588  →  TRUE
```

Состояние FLAT, ATR прогрет (450 > 0) → выдаётся сигнал `ENTRY_LONG_KRONOS`. Состояние меняется на LONG.

### Сценарий 2 — Прогноз в «мёртвой зоне»

Тот же бар, но прогноз: `pred_close = 98 500 USDT`.

```
98 500 > 98 000 × 1.006 = 98 588  →  FALSE (98 500 < 98 588)
```

Выход в FLAT: `pred_close = 98 500 > current_close = 98 000` → условие выхода `pred_close < current_close` не выполнено.

Итог: `return None`. Ни входа, ни выхода. Прогнозируемый рост 0.51% недостаточен для покрытия расходов.

### Сценарий 3 — Выход при медвежьем прогнозе

Бот находится в состоянии LONG. Следующий бар закрывается по 99 400 USDT. Прогноз: `pred_close = 99 100 USDT`.

```
99 100 < 99 400  →  TRUE
```

Выдаётся сигнал `EXIT_FLAT_KRONOS`. Состояние меняется на FLAT.

### Сценарий 4 — Cache miss на одном баре

В кэше нет прогноза для этого конкретного бара (например, бар появился позже, чем строился кэш). Функция получает `None` от `cache.get(key)` и возвращает `None`. Бот переходит к следующей свече без каких-либо действий.

### Сценарий 5 — ATR не прогрет (первые 13 свечей)

На 10-й свече прогноз великолепный: `pred_close = 110 000` при `current_close = 100 000`. Порог пройден — но `_last_atr is None`. Вход запрещён. Без ATR нельзя рассчитать стоп-лосс, а без стоп-лосса торговать — значит не иметь страховки.

## Подводные камни / что важно понимать

**1. Прогноз — это не гарантия, это вероятностная оценка.**
Kronos — ML-модель. Она не знает будущего. Она выдаёт статистически вероятное значение на основе паттернов в исторических данных. Порог 0.6% — это фильтр «достаточно ли модель уверена», но не «модель права».

**2. Прогноз хранится в кэше — он рассчитан заранее, не в реальном времени.**
Kronos не «думает» во время торговли. До начала торговой сессии запускается скрипт кэш-билда, который прогоняет модель по историческим барам и сохраняет прогнозы. Стратегия на каждом баре просто берёт готовый ответ. Подробнее — [[kronos-cache-build-script]].

**3. Данные, на которых обучался Kronos, пересекаются с нашими историческими данными.**
Это называется утечка предобучения (pretrain leakage): модель «видела» наши BTC/USDT данные во время обучения. Это делает бэктест-результаты методологически невалидными — они выглядят как внешняя проверка, но фактически являются тестом на известных данных. Подробнее — [[kronos-data-leakage]].

**4. Порог 0.6% — минимум, не оптимум.**
Это порог безубыточности (с запасом). Он не оптимизирован под максимальную прибыль — это намеренное решение: оптимизация порога на исторических данных привела бы к подгонке (overfitting). Оператор может менять threshold через конфиг, но ниже 0.6% опускаться нельзя — сделки уйдут в минус даже без учёта прогнозных ошибок.

**5. ATR-прогрев на первых свечах — намеренная блокировка.**
Бот не войдёт в позицию в первые 13 свечей (при периоде 14), даже если прогноз отличный. Это правило безопасности: без прогретого ATR риск-менеджер не сможет выставить корректный стоп-лосс, и вход был бы «голым» — без защитного ограничения убытка.

**6. Стратегия никогда не видит незакрытые свечи.**
Гейт `if not bar.is_closed: return None` (src/signalgen/kronos_strategy.py:120–121) — это защита от look-ahead (тот же принцип, что и [[bar-source-live|защита от look-ahead в live-источнике свечей]]). В [[what-is-backtest-overview|бэктесте]] особенно важно: некорректный бэктест мог бы «заглядывать» в незакрытую свечу и получать нереалистично хорошие результаты.

**7. Временна́я метка кэш-ключа — всегда текущий бар, не следующий.**
`bar_close_ts = int(bar.close_time.timestamp())` (src/signalgen/kronos_strategy.py:138) — метка берётся у закрытого бара, по которому принимается решение. Прогноз, хранящийся под этим ключом, описывает СЛЕДУЮЩИЙ бар — но ключ указывает на ТЕКУЩИЙ. Это дисциплина «добавляй в кэш перед вычислением» (append-before-compute): гарантирует, что мы никогда не прочтём прогноз для бара, которого ещё не было.

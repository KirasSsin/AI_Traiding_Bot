# Стратегия прорыва канала Дончиана (Turtle Trading)

**TL;DR:** Бот покупает биткоин, когда цена пробивает исторический максимум последних 20 свечей, и продаёт — когда цена падает ниже минимума последних 10 свечей или теряет больше 2×ATR от цены входа. Параметры жёстко зафиксированы до проведения бэктеста, чтобы исключить подгонку под данные.

## Простыми словами

Представьте, что вы наблюдаете за ценой акции на протяжении двадцати дней. Если сегодня цена закрытия превысила максимум любого из этих двадцати дней — это сигнал: рынок вышел за пределы «привычного коридора». Это и называется **прорывом** (breakout): цена пробила «потолок» недавней истории.

**[[donchian-channel-indicator|Канал Дончиана]]** — это тот самый коридор: верхняя граница — наивысшая цена за последние N баров, нижняя — наименьшая за последние M баров. Назван по имени Ричарда Дончиана, который разработал этот метод в 1970-х.

**Turtle Trading** — знаменитая система 1983 года: трейдеры-«черепахи» входили на пробой 20-барного максимума, а выходили по 10-барному минимуму. Наш бот реализует именно этот классический вариант.

Главная идея: когда цена выходит за пределы недавнего диапазона — это признак начала тренда. Бот «садится в поезд» при пробое максимума и едет до тех пор, пока поезд не начнёт разворачиваться.

Страховка — **[[atr-indicator|ATR-стоп]]** (от Average True Range — «средний истинный диапазон», мера того, насколько цена обычно колеблется за один бар). Если цена упала ниже уровня «цена входа минус 2 × ATR», бот не ждёт канального сигнала — выходит немедленно, ограничивая потерю.

Стратегия работает только **в одну сторону** — только покупки (long-only), продавать в короткую бот не умеет.

## Как это работает у нас

### Зафиксированные параметры

Все параметры зафиксированы в константе `DONCHIAN_LONG_ONLY_PARAMS` **до** запуска бэктеста согласно ADR 0054 — это называется «anti-snooping lock»: нельзя подобрать параметры, сначала посмотрев на результаты. (src/signalgen/donchian_strategy.py:33–39)

```python
DONCHIAN_LONG_ONLY_PARAMS: dict[str, object] = {
    "lookback_n": 20,        # окно входа: ширина канала для сигнала покупки
    "exit_lookback_n": 10,   # окно выхода: ширина канала для сигнала продажи
    "atr_period": 14,        # период ATR (стандартный Уайлдер 1978)
    "atr_stop_mult": Decimal("2.0"),  # множитель ATR-стопа
    "signal_side_mode": "long_only",  # инвариант: SHORT никогда не эмитируется
}
```

| Параметр | Значение | Смысл |
|---|---|---|
| `lookback_n` | 20 | Смотрим назад на 20 закрытых баров при входе |
| `exit_lookback_n` | 10 | Смотрим назад на 10 закрытых баров при выходе |
| `atr_period` | 14 | ATR считается по 14 барам (Wilder 1978) |
| `atr_stop_mult` | 2.0 | Стоп-лосс = цена входа − 2.0 × ATR |

**Инвариант:** `exit_lookback_n < lookback_n` — жёсткое требование кода. Если передать exit_lookback_n ≥ lookback_n — класс бросает исключение. (src/signalgen/donchian_strategy.py:60–61)

### Класс `DonchianBreakoutStrategy`

Стратегия — **объект с памятью** (stateful): внутри хранится скользящий буфер баров, текущая позиция (FLAT или LONG) и цена входа.

**Конструктор и размер буфера** (src/signalgen/donchian_strategy.py:49–71):

```python
self._buffer_size = max(lookback_n, atr_period) + 5
```

Буфер хранит `max(20, 14) + 5 = 25` последних баров. Этого достаточно, чтобы одновременно вычислить и 20-барный максимум, и 14-барный ATR.

Поля состояния:

- `_current_side: SignalSide` — текущая позиция: FLAT (нет позиции) или LONG (куплено).
- `_entry_close: Decimal | None` — цена закрытия бара, на котором был вход. Нужна для расчёта ATR-стопа.

### `_append_bar` — добавление бара в буфер (src/signalgen/donchian_strategy.py:75–85)

Перед добавлением проверяется три условия:

1. Бар должен быть **закрытым** (`bar.is_closed = True`) — незакрытая свеча не несёт финального значения.
2. Символ бара должен совпадать с символом стратегии.
3. `close_time` нового бара должен быть **строго позже** последнего бара в буфере — дубликаты не принимаются.

Если буфер переполнился — обрезается с хвоста: `self._bars = self._bars[-self._buffer_size:]`.

### `warmup` — прогрев без сигнала (src/signalgen/donchian_strategy.py:87–89)

При старте нужно «накормить» стратегию историческими барами, не получая сигналов. Метод `warmup` просто добавляет бар в буфер и не проверяет правила входа/выхода. Это нужно, чтобы к моменту первого «живого» бара в буфере уже было достаточно истории.

### `on_bar` — основной метод обработки бара (src/signalgen/donchian_strategy.py:91–142)

Вызывается на каждой новой закрытой свече в реальном времени. Возвращает `Signal` или `None`.

**Шаг 1. Проверка минимального количества баров.** (src/signalgen/donchian_strategy.py:94)

```python
if len(self._bars) < self._lookback_n + 1:
    return None
```

Нужно минимум `lookback_n + 1 = 21` бар: 20 исторических для канала плюс текущий.

**Шаг 2. Вычисление канальных уровней.** (src/signalgen/donchian_strategy.py:97–105)

```python
highs = np.array([float(b.high) for b in self._bars], dtype=np.float64)
lows  = np.array([float(b.low)  for b in self._bars], dtype=np.float64)
closes= np.array([float(b.close) for b in self._bars], dtype=np.float64)

donchian_high     = float(np.max(highs[-(self._lookback_n + 1) : -1]))
donchian_low_exit = float(np.min(lows[-(self._exit_lookback_n + 1) : -1]))
```

Срез `[-(N+1):-1]` означает «последние N баров, **не включая текущий**». Это принципиально важно: если бы текущий бар был включён, пробой канала текущей же свечой не имел бы смысла (look-ahead). Подробнее о принципе no look-ahead — в документе [[03-индикаторы-и-расчёты/donchian-channel-indicator]].

**Шаг 3. Вычисление ATR.** (src/signalgen/donchian_strategy.py:104–107)

```python
atr_arr = atr(highs, lows, closes, self._atr_n)
atr_now = float(atr_arr[-1])
if np.isnan(atr_now):
    return None
```

Функция `atr()` из `src/signalgen/indicators.py` (строка 67) использует TA-Lib со [[wilder-atr-and-stops|сглаживанием Уайлдера]] (α = 1/14). Если ATR ещё не прогрелся (NaN на первых `atr_period` барах) — сигнал не выдаётся.

**Шаг 4. Правило входа LONG.** (src/signalgen/donchian_strategy.py:112–120)

```python
if self._current_side == SignalSide.FLAT and close_now > donchian_high:
    self._current_side = SignalSide.LONG
    self._entry_close = bar.close
    return self._build_signal(bar, SignalSide.LONG, ...)
```

Два условия одновременно:

1. Текущая позиция — FLAT (нет открытой позиции).
2. Цена закрытия текущего бара **строго больше** максимума предыдущих 20 баров.

При входе сохраняется `entry_close` — цена закрытия. Именно от неё будет считаться ATR-стоп.

**Шаг 5. Правило выхода FLAT — два механизма с приоритетом.** (src/signalgen/donchian_strategy.py:123–140)

```python
atr_stop_price = float(self._entry_close) - float(self._atr_stop_mult) * atr_now
channel_exit  = close_now < donchian_low_exit
atr_stop_exit = close_now < atr_stop_price

if channel_exit or atr_stop_exit:
    reason = EXIT_FLAT_ATR_STOP if atr_stop_exit else EXIT_FLAT_CHANNEL
```

Условия проверяются одновременно (`or`), но при совпадении обоих — **приоритет ATR-стопа** (он указывается как `reason` первым). Логика: ATR-стоп — более жёсткий критерий (острый обвал), канальный выход — плановый выход при нормальном развороте.

После выхода: `_current_side = FLAT`, `_entry_close = None` — стратегия снова готова к следующему пробою.

### `_build_signal` — формирование сигнала (src/signalgen/donchian_strategy.py:144–169)

Создаёт объект `Signal`. Donchian-стратегия не вычисляет EMA, ADX, RSI — эти поля Signal-протокола заполняются нулями (Decimal("0")). Это не ошибка: [[signal-architecture|протокол сигнала]] общий для всех стратегий, незаполненные поля — явный нуль, не None. (src/signalgen/donchian_strategy.py:154)

### Коды причин (reason codes)

Каждый сигнал несёт строковый [[reason-codes-assessment-output|код причины]] для аудита и риск-журнала (src/risk/reason_codes.py:142–144):

| Код | Когда возникает |
|---|---|
| `ENTRY_LONG_DONCHIAN_BREAKOUT` | Вход: close > 20-барный максимум |
| `EXIT_FLAT_ATR_STOP` | Выход: close < entry_close − 2.0 × ATR |
| `EXIT_FLAT_CHANNEL` | Выход: close < 10-барный минимум |

## Формулы и расчёты

### Верхняя граница канала (сигнал входа)

```text
donchian_high = max( high[T-20], high[T-19], ..., high[T-1] )
```

**Простыми словами:** берём свечи с T−20 по T−1 (20 штук), находим наибольший максимум (high). Текущая свеча T не включается.

В коде — срез `highs[-(lookback_n + 1):-1]`, то есть `highs[-21:-1]` при `lookback_n=20`. (src/signalgen/donchian_strategy.py:102)

### Нижняя граница канала (сигнал выхода)

```text
donchian_low_exit = min( low[T-10], low[T-9], ..., low[T-1] )
```

**Простыми словами:** берём последние 10 свечей (не включая текущую), находим наименьший минимум (low). Если текущая цена упала ниже — выход.

В коде — срез `lows[-(exit_lookback_n + 1):-1]`, то есть `lows[-11:-1]`. (src/signalgen/donchian_strategy.py:103)

### ATR-стоп

```text
atr_stop_price = entry_close - 2.0 × ATR(14)
```

**Простыми словами:** от цены, по которой вошли, вычитаем удвоенную «обычную волатильность» рынка. Это наш нижний предел: если цена упала настолько — выходим, не дожидаясь канального сигнала.

ATR (Average True Range) — среднее значение «истинного диапазона» за 14 баров, сглаженное методом Уайлдера (α = 1/14). Истинный диапазон бара — это наибольшее из трёх: (high − low), |high − prev_close|, |low − prev_close|. Функция `atr()` вызывает TA-Lib под капотом. (src/signalgen/indicators.py:67–81)

**Расчёт в коде:** (src/signalgen/donchian_strategy.py:124)

```python
atr_stop_price = float(self._entry_close) - float(self._atr_stop_mult) * atr_now
```

### Инвариант окон

```text
exit_lookback_n < lookback_n   →   10 < 20   ✓
```

Окно выхода должно быть уже окна входа. Логика Turtle Trading: широкое окно нужно для подтверждения сильного пробоя, узкое окно для выхода позволяет быстрее реагировать на разворот. (src/signalgen/donchian_strategy.py:60–61)

## Примеры / сценарии

### Сценарий 1: успешный пробой с канальным выходом

Допустим, BTCUSDT торгуется в диапазоне 100–105 USDT в течение 25 четырёхчасовых баров. Максимальный high за последние 20 баров (не включая текущий) = 105.

**Бар №26:** `close = 109 > donchian_high = 105` → сигнал `ENTRY_LONG_DONCHIAN_BREAKOUT`, позиция LONG, `entry_close = 109`.

После входа рынок продолжает расти, потом разворачивается. Через несколько баров минимум последних 10 свечей опускается до 108, а очередная свеча закрывается на 107.8.

**close = 107.8 < donchian_low_exit = 108** → сигнал `EXIT_FLAT_CHANNEL`.

Этот пример подтверждён тестом `test_breakout_above_donchian_high_emits_long_signal` (tests/unit/test_donchian_strategy.py:51–67).

### Сценарий 2: резкое падение — срабатывает ATR-стоп

Вошли по `entry_close = 109`, ATR = 3.5.

```text
atr_stop_price = 109 − 2.0 × 3.5 = 102.0
```

Следующий бар: резкое падение, `close = 82 < 102.0` → сигнал `EXIT_FLAT_ATR_STOP` — стоп срабатывает раньше, чем 10-барный минимум успел опуститься до этого уровня.

Тест `test_atr_stop_exit_when_in_long`: crash_bar с close=82 при entry_close=109 при ATR ~3–4 от предыдущих плоских баров (100–105) даёт ATR-стоп, подтверждая приоритет ATR-выхода. (tests/unit/test_donchian_strategy.py:90–103)

### Сценарий 3: пробой вниз не даёт SHORT

Если цена пробивает нижнюю границу в состоянии FLAT (нет позиции) — ничего не происходит. Стратегия `long_only`: SHORT не существует. Тест `test_long_only_invariant_no_short_signals` это подтверждает. (tests/unit/test_donchian_strategy.py:70–87)

### Сценарий 4: прогрев — нет сигнала до накопления 21 бара

Если передать менее 21 бара (`lookback_n + 1`), `on_bar` всегда возвращает `None`. Проверяется тестом `test_warmup_no_signal_until_buffer_full` (15 баров → все None). (tests/unit/test_donchian_strategy.py:43–48)

## Подводные камни / что важно понимать

**1. Сигнал — не сделка, а заявка на следующий бар.**
Принцип no look-ahead (указан в docstring стратегии строка 15): сигнал на баре T исполняется по цене open[T+1]. Как сигнал превращается в реальный ордер — см. [[order-lifecycle-overview|жизненный цикл ордера]]. Это честная симуляция реального рынка — нельзя купить по цене, которую только что «увидел» на закрытии. (src/signalgen/donchian_strategy.py:15)

**2. ATR-стоп — от цены входа, а не трейлинг.**
`entry_close` сохраняется однажды — в момент входа. ATR-стоп не движется вверх по мере роста цены. Это не классический trailing stop (скользящий стоп, который ползёт за ценой) — уровень стопа фиксирован от начала позиции. Если нужна защита растущей прибыли — канальный выход (10-барный минимум) выполняет роль нестрогого трейлинга.

**3. Параметры нельзя менять без нового ADR.**
Константа `DONCHIAN_LONG_ONLY_PARAMS` помечена `# ADR 0054 LOCKED — DO NOT modify без new ADR`. Изменение параметров после просмотра бэктест-данных аннулирует статистическую значимость результатов (data snooping). (src/signalgen/donchian_strategy.py:32)

**4. Только одна позиция одновременно.**
Стратегия — FLAT или LONG, третьего нет. Пока позиция открыта, новые пробои вверх не порождают дополнительных входов.

**5. ATR может быть NaN на прогреве.**
Если в буфере ещё недостаточно баров для расчёта ATR-14 (TA-Lib требует `atr_period` баров для первого не-NaN значения), `on_bar` вернёт None. Это защита: без ATR невозможно проверить ATR-стоп. (src/signalgen/donchian_strategy.py:106–107)

**6. Стратегия не потокобезопасна.**
Docstring явно указывает: `NOT thread-safe — single-producer per symbol pattern`. Один экземпляр — один поток. (src/signalgen/donchian_strategy.py:17)

**7. Отсутствие фиксированного тейк-профита.**
В [[donchian-runner-and-reference-run|backtest-конфигурации раннера]] `tp_atr_mult = 1e9` (фактически отключён). Стратегия не имеет верхней цели — только два вида выхода: канальный или стоп-лосс. (src/backtest/donchian_runner.py:78)

**8. Бэктест-гейты — шесть строгих критериев одновременно.**
Стратегия считается подтверждённой только при одновременном прохождении всех [[acceptance-gates-t1-t6|шести ворот приёмки T1–T6]]. Пороги зафиксированы в `donchian_runner.py` (строки 46–51): [[sharpe-sortino-metrics|Sharpe]] ≥ 0.7 (per-fold), [[monte-carlo-permutation|MC]] p-value ≤ 0.05, минимум [[tstat-oos-is-metrics|50 сделок]], [[deflated-sharpe-ratio|DSR]] ≥ 0.95. Подробнее о честной проверке на невиданных данных — в [[walk-forward-analysis|walk-forward анализе (WFA)]].

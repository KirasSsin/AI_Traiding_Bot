# Стратегия Kronos (ML-прогнозирование цены)

**TL;DR:** Бот спрашивает у нейросети Kronos — «каким будет следующий бар?» — и открывает сделку только если прогноз даёт рост больше 0.6% (ровно покрывает комиссию плюс проскальзывание в обе стороны). Сам нейросетевой расчёт происходит заранее и офлайн; в момент торговли бот лишь читает уже готовый ответ из файла-кэша.

## Простыми словами

Представьте, что у вас есть умный советник, который каждый час смотрит на историю рынка и говорит: «Через час цена будет вот такой». Вы заранее — пока биржа ещё закрыта — спрашиваете его о каждом баре и записываете его ответы в блокнот. Когда биржа открывается и приходит очередной закрытый бар, бот открывает блокнот, находит нужный прогноз и принимает решение по простому правилу:

- Прогнозируемая цена **больше текущей на 0.6% и выше** → открываем длинную позицию (покупаем).
- Прогнозируемая цена **ниже текущей** → выходим из позиции (продаём).
- Прогноз в «нейтральной полосе» (от 0% до 0.6%) → ничего не делаем.

Почему именно 0.6%? Потому что любая сделка стоит денег. Комиссия биржи — 0.10% при покупке и 0.10% при продаже. Плюс проскальзывание (разница между ценой в заявке и фактической ценой исполнения) — ещё 0.05% туда и 0.05% обратно. Итого одна сторона стоит **0.15%** (0.10% + 0.05%), а полный «круг» (вход + выход) — **0.15% при входе + 0.15% при выходе = 0.30%**. Порог 0.60% — это два таких «круга»: сознательный запас, чтобы сделка была выгодна даже с учётом погрешности прогноза. `(src/signalgen/kronos_strategy.py:15-16)`

Советник-нейросеть — это модель **Kronos** (см. [[kronos-what-is-it]] о том, что это за модель). Ключевое отличие от обычных стратегий бота: вместо [[technical-indicators|технических индикаторов]] (скользящих средних, RSI, ATR) бот использует машинное обучение (ML, machine learning) — нейросеть, обученную распознавать паттерны в огромных массивах ценовых данных.

## Как это работает у нас

### Шаг 0. Два мира: офлайн и онлайн

Kronos — тяжёлая нейросеть. Запускать её в реальном времени на каждый входящий бар было бы и медленно, и рискованно. Поэтому система разделена на два независимых мира:

- **Офлайн (кэш-билд):** отдельный скрипт (`scripts/run_kronos_s53.py`) заранее прогоняет Kronos через историю, собирает предсказания и сохраняет их на диск. Файлы стратегии в `src/signalgen/` **никогда** не импортируют `torch` (библиотеку нейросетей) — это гарантирует тест `tests/unit/test_ml_optional_dep.py` тест B. `(src/signalgen/kronos_strategy.py:1-8)`
- **Онлайн (стратегия):** класс `KronosStrategy` в `src/signalgen/kronos_strategy.py` только читает уже готовые предсказания из кэша через `PredictionCache.get()`. Никакой нейросети в момент торговли — только чтение файла и сравнение двух чисел.

### Шаг 1. Инициализация стратегии — параметры и конфигурация

`KronosStrategy.__init__()` принимает несколько обязательных параметров — они нужны не для торговли напрямую, а чтобы строить **правильный ключ кэша** при каждом баре: `(src/signalgen/kronos_strategy.py:66-106)`

| Параметр | Назначение |
|---|---|
| `symbol` | Торговый инструмент, например `"BTCUSDT"` |
| `cache` | Объект `PredictionCache` — «блокнот» с предсказаниями на диске |
| `model_id` | Название модели, например `"NeoQuasar/Kronos-mini"` |
| `weights_hash` | Криптографический отпечаток весов модели (SHA-256) — защита от подмены |
| `timeframe` | Таймфрейм бара, например `"1h"` |
| `params_hash` | Отпечаток параметров сэмплирования модели |
| `device` | Устройство, на котором строился кэш (`"cpu"`, `"mps"`, `"cuda"`) |
| `threshold` | Порог входа, по умолчанию `Decimal("0.006")` (0.6%) |
| `atr_period` | Период ATR для расчёта стоп-лосса, по умолчанию `14` |

Помимо параметров конструктор создаёт два внутренних объекта состояния:

- `self._atr = _WilderATR(period=14)` — **инкрементальный [[atr-indicator|ATR]]** (Average True Range, средний истинный диапазон) по методу Уайлдера. Это мера «волатильности» бара — насколько широко цена ходила от минимума до максимума с учётом предыдущего закрытия. Нужен для расчёта стоп-лосса при входе. `(src/signalgen/kronos_strategy.py:105)`
- `self._current_side = SignalSide.FLAT` — **конечный автомат** (FSM) состояний [[signal-architecture|SignalSide]]: `FLAT` (нет позиции) или `LONG` (куплено). Это гарантирует, что бот не войдёт дважды и не выйдет из несуществующей позиции. `(src/signalgen/kronos_strategy.py:110)`

### Шаг 2. on_bar() — главная функция, которая вызывается на каждом баре

`KronosStrategy.on_bar(bar: Bar) -> Signal | None` — единственная публичная точка входа стратегии. Она вызывается каждый раз, когда приходит новый [[bar-model|бар (свеча)]]. Вот что она делает по порядку: `(src/signalgen/kronos_strategy.py:112-166)`

**Проверка 1 — бар закрыт?** `(src/signalgen/kronos_strategy.py:120-121)`

```python
if not bar.is_closed:
    return None
```

Живой (ещё не закрытый) бар игнорируется. Торговать по незакрытому бару — это смотреть в будущее: цена ещё не устоялась. Это одна из ключевых защит от **look-ahead bias** (заглядывания в будущее).

**Проверка 2 — правильный инструмент?** `(src/signalgen/kronos_strategy.py:122-123)`

```python
if bar.symbol != self._symbol:
    return None
```

Если бар пришёл от другого торгового инструмента — пропускаем.

**ATR обновляется всегда — независимо от сигнала** `(src/signalgen/kronos_strategy.py:127-130)`

```python
self._atr.update(float(bar.high), float(bar.low), float(bar.close))
if self._atr.current is not None:
    self._last_atr = Decimal(str(self._atr.current))
```

Инкрементальный ATR обновляется на каждом закрытом баре — даже если нет предсказания в кэше и сигнал не появится. Это важно: когда войти наконец можно будет, ATR уже будет «прогрет» (посчитан по достаточному количеству баров).

**Построение ключа кэша** `(src/signalgen/kronos_strategy.py:133-141)`

```python
key = CacheKey(
    model_id=self._model_id,
    weights_hash=self._weights_hash,
    symbol=self._symbol,
    timeframe=self._timeframe,
    bar_close_ts=int(bar.close_time.timestamp()),
    params_hash=self._params_hash,
    device=self._device,
)
```

Ключ строится из **семи полей**. Критически важное поле — `bar_close_ts = int(bar.close_time.timestamp())`. Это временная метка **текущего** (не следующего!) бара. Если кто-то записал предсказание для бара в 14:00, а сейчас бар 13:00 — ключи не совпадут, кэш ответит «не найдено». Защита от look-ahead работает на уровне самого ключа.

**Чтение из кэша** `(src/signalgen/kronos_strategy.py:142-145)`

```python
prediction = self._cache.get(key)
if not prediction:
    return None
```

**Cache miss (промах кэша)** — предсказание не найдено — это штатная ситуация. Нет предсказания = нет сигнала = нет сделки. Ни ошибки, ни аварийного останова. Если предсказание найдено, `prediction` — это список `Decimal` значений. При горизонте 1 (следующий бар) это список из одного числа.

**Получение предсказанной цены** `(src/signalgen/kronos_strategy.py:147-148)`

```python
pred_close = prediction[0]  # horizon = 1 -> single predicted close
current_close = bar.close
```

`prediction[0]` — предсказанная цена закрытия следующего бара. В текущей конфигурации горизонт (`horizon`) равен 1, поэтому всегда берётся первый (и единственный) элемент.

**Правило входа (LONG)** `(src/signalgen/kronos_strategy.py:151-159)`

```python
if self._current_side == SignalSide.FLAT and pred_close > current_close * (
    Decimal(1) + self._threshold
):
    if self._last_atr is None or self._last_atr <= 0:
        return None
    self._current_side = SignalSide.LONG
    return self._build_signal(bar, SignalSide.LONG, ReasonCode.ENTRY_LONG_KRONOS)
```

Условие входа проверяется **только когда нет открытой позиции** (`SignalSide.FLAT`). Это предотвращает двойной вход (TL-06). Дополнительная проверка: ATR должен быть прогрет и положителен. Без ATR нельзя рассчитать стоп-лосс — размер допустимого убытка. Входить без стопа запрещено.

**Правило выхода (FLAT)** `(src/signalgen/kronos_strategy.py:161-165)`

```python
if self._current_side == SignalSide.LONG and pred_close < current_close:
    self._current_side = SignalSide.FLAT
    return self._build_signal(bar, SignalSide.FLAT, ReasonCode.EXIT_FLAT_KRONOS)
```

Условие выхода проверяется **только когда есть открытая позиция** (`SignalSide.LONG`). Выходим, как только нейросеть предсказывает снижение — даже на 1 копейку ниже текущей цены. При выходе ATR не требуется.

### Шаг 3. Построение сигнала

`_build_signal()` создаёт объект `Signal` со стандартными полями: `(src/signalgen/kronos_strategy.py:168-184)`

```python
Signal(
    signal_id=uuid4(),
    symbol=self._symbol,
    side=side,
    bar_close_time=bar.close_time,
    generated_at=datetime.now(UTC),
    ema_fast=_ZERO, ema_slow=_ZERO, adx_14=_ZERO,
    plus_di_14=_ZERO, minus_di_14=_ZERO, rsi_14=_ZERO,
    atr_14=self._last_atr if self._last_atr is not None else _ZERO,
    reason=reason.value,
)
```

Kronos не вычисляет EMA, RSI, ADX — эти поля равны нулю. Единственный «живой» индикатор в сигнале — `atr_14` для размера стоп-лосса. [[reason-codes-assessment-output|Коды причины]]: `ENTRY_LONG_KRONOS` (код 66) и `EXIT_FLAT_KRONOS` (код 67). `(src/risk/reason_codes.py:151-152)`

## Кэш предсказаний: как устроен «блокнот»

### Ключ кэша (CacheKey)

Каждая запись в кэше идентифицируется структурой `CacheKey` из **7 полей**: `(src/ml/prediction_cache.py:33-47)`

```python
@dataclass(frozen=True)
class CacheKey:
    model_id: str        # какая модель
    weights_hash: str    # какие именно веса модели (отпечаток файла)
    symbol: str          # какой торговый инструмент
    timeframe: str       # какой таймфрейм
    bar_close_ts: int    # какой конкретно бар (UNIX-timestamp закрытия)
    params_hash: str     # с какими параметрами сэмплирования запускалась модель
    device: str          # на каком устройстве (cpu/mps/cuda)
```

**Несовпадение хотя бы одного поля = промах кэша.** Если вы переобучили модель, обновили весовые файлы, переключились с CPU на MPS — все старые записи автоматически стали недействительными. Нет риска случайно использовать устаревшее предсказание.

Ключ превращается в имя файла через SHA-256 хэш всех семи полей: `key.digest()` возвращает 64-символьную строку вида `a3f7c1...`, файл называется `a3f7c1....json`. `(src/ml/prediction_cache.py:44-47)`

### Запись (put) и целостность SHA-256

Каждый файл предсказания сопровождается файлом-спутником `.sha256`: `(src/ml/prediction_cache.py:118-150)`

```
cache/
  a3f7c1....json        ← само предсказание в формате JSON
  a3f7c1....json.sha256 ← SHA-256 контрольная сумма содержимого
```

**SHA-256** — это криптографический хэш (отпечаток): любое изменение даже одного байта в файле предсказания даёт совершенно другой отпечаток. Запись происходит атомарно (через временный файл + `os.replace`): либо оба файла записаны корректно, либо ни одного. Нет ситуации «файл есть, а спутника нет».

### Чтение (get) и проверка целостности

При чтении кэш проверяет: `(src/ml/prediction_cache.py:152-175)`

1. Существуют ли оба файла (JSON и его .sha256)?
2. Совпадает ли текущий SHA-256 содержимого JSON с сохранённым в .sha256?

Если хэши не совпадают (файл повреждён или подделан) — `warnings.warn(...)` + возвращает `None` (промах). **Никогда не бросает исключение.** Стратегия получает `None` и молча пропускает бар, как будто предсказания нет. Данные хранятся как строки Decimal (`"100.500000"`), при загрузке преобразуются обратно в `Decimal` без потери точности.

## Формулы и расчёты

### Правило входа V3

```
ВХОД (LONG) если:
  pred_close > current_close × (1 + threshold)
  то есть:
  pred_close > current_close × 1.006
```

**Расшифровка простыми словами:** прогнозируемая цена следующего закрытия должна быть **строго больше** текущей цены, умноженной на 1.006. При текущей цене 100 000 ₽ — нужен прогноз выше 100 600 ₽. Если прогноз 100 500 ₽ — сигнала нет. Граничное значение не засчитывается (строгое неравенство).

**Откуда взялось 0.006 (0.6%)?**

```
Комиссия при входе:   0.10% от суммы сделки
Проскальзывание вход: 0.05% от суммы сделки
                      ─────
Стоимость входа:      0.15%

Комиссия при выходе:  0.10%
Проскальзывание вых.: 0.05%
                      ─────
Стоимость выхода:     0.15%

Итого «круг»:         0.30% → threshold = 0.30% × 2 = 0.60%
```

Порог = **двойная** стоимость круга. Это сознательный запас: даже если модель слегка ошибётся, сделка всё равно должна покрывать затраты. `(src/signalgen/kronos_strategy.py:14-17, 44-46)`

### Правило выхода V3

```
ВЫХОД (FLAT) если:
  pred_close < current_close
```

Любое снижение прогноза ниже текущей цены — сигнал к выходу. Нет «обратного порога»: стратегия не ждёт падения на 0.6%, она консервативно выходит при любом прогнозируемом снижении.

### ATR по методу Уайлдера (прогрев)

ATR (Average True Range) — мера волатильности. Истинный диапазон (True Range, TR) каждого бара:

```
TR[0] = high[0] - low[0]                           (первый бар)
TR[i] = max(
    high[i] - low[i],
    |high[i] - close[i-1]|,
    |low[i]  - close[i-1]|
)                                                   (последующие)
```

Инициализация (бар с индексом `period-1`, то есть 14-й бар):

```
ATR_seed = среднее(TR[0..13])
```

Рекурсия Уайлдера после инициализации:

```
ATR[i] = (ATR[i-1] × 13 + TR[i]) / 14
```

Метод Уайлдера «медленнее» стандартного EMA — он лениво реагирует на резкие выбросы. Это специально: стоп-лосс должен отражать **устойчивую** волатильность, а не панические всплески. Каноническая формула Wilder ATR (SMA-seed + рекурсия) и её роль в защитных стопах разобрана отдельно — см. [[wilder-atr-and-stops]]. `(src/signalgen/atr_breakout_strategy.py:135-180)`

**Важно:** ATR считается полностью в инкрементальном режиме (O(1) на каждый бар, без хранения полной истории). До 14-го закрытого бара `self._last_atr` равен `None` — вход запрещён.

### Медианный ансамбль (median_ensemble)

При **офлайн-построении** кэша модель запускается несколько раз (sample_count > 1) с разными случайными семенами. Функция `median_ensemble()` сводит несколько прогнозов к одному: `(src/ml/prediction_cache.py:61-90)`

```
Для каждого шага горизонта:
  column = [sample_1[шаг], sample_2[шаг], ..., sample_N[шаг]]
  column.sort()
  result[шаг] = column[(N-1)//2]  # нижний средний при чётном N
```

**Почему медиана, а не среднее?** Среднее чувствительно к выбросам: один аномальный прогноз `+50%` сильно сдвинет среднее вверх. Медиана устойчива — один выброс среди 10 значений не меняет результат. Для чётного числа образцов берётся нижний средний элемент (не усреднение двух средних) — чтобы результат оставался точным `Decimal`-значением, без потери точности при делении. `(src/ml/prediction_cache.py:83-89)`

## Два варианта модели Kronos

`KronosVariant` — неизменяемая «конфигурационная карточка» модели. В системе два пресета: `(src/ml/kronos_variant.py:14-49)`

| Вариант | model_id | max_context | Токенизатор |
|---|---|---|---|
| `KRONOS_BASE` | `NeoQuasar/Kronos-base` | 512 баров | `NeoQuasar/Kronos-Tokenizer-base` |
| `KRONOS_MINI` | `NeoQuasar/Kronos-mini` | 2048 баров | `NeoQuasar/Kronos-Tokenizer-2k` |

**max_context** — сколько последних баров подаётся модели как «история» при прогнозировании. `base` смотрит на 512 баров назад, `mini` — на 2048. Для часового таймфрейма 512 баров = примерно 3 недели истории, 2048 баров = примерно 3 месяца.

**Почему токенизатор и модель — это два разных компонента?** Токенизатор переводит числовые данные (цены) в формат, понятный нейросети (примерно как «словарь» языка). Модель — сама нейросеть. У `mini` другой токенизатор именно потому, что 2048-контекстная версия требует другого «словаря» (во время Sprint 52 `mini` ошибочно получала токенизатор от `base` — ADR 0069 C10 исправил это). `(src/ml/kronos_variant.py:1-7)`

## Примеры / сценарии

### Сценарий А — успешный вход и выход

**Контекст:** стратегия инициализирована, кэш прогрет, ATR посчитан по 14 барам. Цена BTC = 100 000 USDT. Нейросеть предсказывает следующее закрытие = 101 200 USDT.

1. Приходит закрытый бар 14:00, `bar.close = 100 000`.
2. Строится ключ с `bar_close_ts = 1704384000` (UNIX-время 14:00).
3. Кэш находит предсказание: `[Decimal("101200")]`.
4. Проверяем порог: `101 200 > 100 000 × 1.006 = 100 600` → **да**.
5. ATR прогрет (например, 850 USDT) и положителен → ATR-guard пройден.
6. Текущее состояние `FLAT` → входим. Возвращается `Signal(side=LONG, reason="ENTRY_LONG_KRONOS", atr_14=850)`.

Следующий бар 15:00, `bar.close = 101 000`. Нейросеть предсказывает 16:00 = 100 500 USDT.

1. Ключ обновляется с новым `bar_close_ts` (15:00).
2. Кэш: `[Decimal("100500")]`.
3. `100 500 < 101 000` → прогноз ниже текущей цены.
4. Текущее состояние `LONG` → выходим. Возвращается `Signal(side=FLAT, reason="EXIT_FLAT_KRONOS")`.

### Сценарий Б — промах кэша

Пришёл новый бар, но для него нет записи в кэше (офлайн-скрипт не добрался до этого временного интервала).

1. `self._cache.get(key)` возвращает `None`.
2. `if not prediction: return None`.
3. Бот ничего не делает, ждёт следующего бара. Никаких ошибок, никаких аварий.

### Сценарий В — «нейтральная полоса»

Текущая цена 100 000, предсказание 100 300 (рост 0.3% — меньше порога 0.6%).

1. `100 300 > 100 000 × 1.006 = 100 600` → **нет** (100 300 < 100 600).
2. Первое условие не выполнено.
3. `100 300 < 100 000` → тоже **нет**.
4. Возвращается `None`. Торговли нет — прогнозируемый рост не покрывает затраты.

### Сценарий Г — ATR не прогрет (первые 13 баров)

Стратегия только что создана. Приходят первые 13 баров. Для одного из них есть предсказание с хорошим ростом (предположим 2%).

1. ATR ещё не посчитан (`self._last_atr is None`).
2. Условие входа формально выполнено, но: `if self._last_atr is None: return None`.
3. Вход заблокирован. Без ATR нельзя рассчитать стоп-лосс — рискованная сделка запрещена.

### Сценарий Д — повреждённый кэш (checksum mismatch)

Файл предсказания был случайно изменён (побитовое повреждение диска или ручное редактирование).

1. `PredictionCache.get()` читает `.sha256` файл → сравнивает с реальным SHA-256 содержимого.
2. Хэши не совпадают → `warnings.warn("Prediction cache checksum mismatch ...")` в лог.
3. Возвращается `None` (промах кэша). Торговля не происходит. Система продолжает работу.

## Подводные камни / что важно понимать

**1. Кэш должен быть актуальным.** Если офлайн-скрипт не запускался несколько часов, в кэше не будет предсказаний для новых баров → стратегия будет непрерывно получать промахи и молча пропускать торговлю. Мониторить наполненность кэша — задача оператора.

**2. Смена модели = пересборка кэша.** Если обновили веса Kronos или параметры сэмплирования (temperature, top_p и т.д.) — `weights_hash` и `params_hash` изменятся. Все старые записи кэша станут недостижимыми (ключи не совпадут). Торговля возобновится только после полного пересчёта кэша на новых весах.

**3. Device должен совпадать.** Если кэш строился на `"mps"` (Apple Silicon), а стратегия инициализирована с `device="cpu"` — промах кэша для каждого бара. Параметр `device` — часть ключа.

**4. Long-only.** Стратегия **никогда** не открывает короткую позицию (SHORT). Поле `SignalSide.SHORT` в системе вообще не используется в v0.1 (spot-торговля на Bybit не поддерживает шортование в боте). `(src/signalgen/models.py:14)`

**5. Выход по «любому снижению» — это агрессивно.** Правило выхода очень чувствительное: даже прогноз на 0.01% ниже текущей цены закроет позицию. Это не баг, а сознательное решение (V3, ADR 0068): при горизонте 1 бар нейросеть даёт один прогноз, и любое предсказание снижения трактуется как сигнал выхода.

**6. Пустой список из кэша = промах.** Если кто-то записал в кэш пустое предсказание `put(key, [])`, стратегия обработает это как промах через `if not prediction: return None` (пустой список falsy в Python), без IndexError. `(tests/unit/test_kronos_strategy.py:237-267)`

**7. Параллельное использование не безопасно.** Класс не является потокобезопасным — одна стратегия обслуживает один инструмент, один поток. Это соответствует архитектуре ADR 0023 (single-writer invariant).

**8. Безопасность: пины SHA коммитов.** `KronosModelAdapter` (в тестах его заменяет заглушка — см. [[kronos-mock-adapter]]) при загрузке модели через HuggingFace использует `variant.model_revision` и `variant.tokenizer_revision` — SHA конкретного коммита в репозитории. Это защита от ACE (arbitrary code execution, выполнение произвольного кода): функция `from_pretrained` в PyTorch/HuggingFace десериализует файлы модели, что технически позволяет встроить вредоносный код в обновление весов. Пин SHA гарантирует, что загружается строго проверенная версия. `(src/ml/kronos_variant.py:21-23, src/ml/kronos_adapter.py:57-60)`

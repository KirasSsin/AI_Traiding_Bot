# Проверка стратегии на честность: команда wfa (Walk-Forward Analysis)

**TL;DR:** Команда `wfa` прогоняет торговую стратегию по историческим данным способом, который исключает «подгонку под прошлое», и выносит честный [[verdict-and-warnings|вердикт PASS/FAIL]] по [[acceptance-gates-t1-t6|шести критериям]] плюс статистической поправке [[deflated-sharpe-ratio|DSR]]. Если вердикт PASS — стратегия продемонстрировала, что умеет зарабатывать на данных, которые никогда не «видела» в процессе обучения.

---

## Простыми словами

Представьте, что вы хотите нанять трейдера. Он показывает вам его сделки за 2021–2024 год — все прибыльные, красивая кривая. Но вы не знаете: он действительно умеет торговать, или просто задним числом подобрал стратегию, которая работала именно на тех данных? Если дать ему новый рынок, покажет ли он тот же результат?

[[walk-forward-analysis|Walk-Forward Analysis]] (WFA) — это процедура честной проверки. Мы не проверяем стратегию на тех же данных, на которых её «обучали». Вместо этого мы делаем следующее:

1. Берём длинную историю цен и нарезаем её на несколько кусков — **окон** (по-английски _folds_, то есть «складки»).
2. На первом куске истории — «тренируем» стратегию (ищем параметры). Это **in-sample** (IS) — данные, которые стратегия видела.
3. Запускаем ту же стратегию с теми же параметрами на следующем куске, который она ещё **не видела** — это **out-of-sample** (OOS).
4. Смотрим, насколько хорошо она сработала на незнакомых данных. Хорошо — переходим к следующему окну.
5. После нескольких таких «складок» агрегируем результат и выносим вердикт.

Между обучающим и проверочным кусками мы оставляем небольшой **зазор (embargo)** — это буфер времени, чтобы данные с конца обучающего периода «не протекли» в проверочный и не исказили оценку.

Аналогия из жизни: студент учит билеты (IS), сдаёт экзамен по другим билетам (OOS), между списком вопросов на репетиции и реальным экзаменом — разрыв в неделю (embargo), чтобы никто не успел «слить» реальные вопросы. Если студент сдал — значит, знания настоящие.

После WFA бот считает **[[acceptance-gates-t1-t6|шесть проверочных критериев (T1–T6)]]** и дополнительно применяет статистическую поправку на то, что мы уже перепробовали много вариантов стратегий раньше. Эта поправка называется DSR — [[deflated-sharpe-ratio|Deflated Sharpe Ratio]] (дефлированный коэффициент Шарпа). Вердикт PASS требует, чтобы прошли **все** проверки одновременно.

## Как это работает у нас

### Запуск команды

```bash
python -m src wfa \
  --symbols BTCUSDT,ETHUSDT,SOLUSDT \
  --start 2021-07-02 --end 2026-04-26 \
  --interval 60
```

Результат выводится в STDOUT в формате JSON, код возврата сигнализирует о вердикте:

| Код | Значение |
|-----|----------|
| `0` | PASS — все критерии пройдены |
| `2` | FAIL — хотя бы один критерий провален |
| `1` | ERROR — нет данных вообще (все Parquet-файлы пустые или отсутствуют) |

(src/__main__.py:497–500, 748)

### Шаг 1. Сборка символов и загрузка данных

Функция `_cmd_wfa` начинается с получения списка торговых пар (символов). Если задан `--symbols BTCUSDT,ETHUSDT,SOLUSDT`, прогон охватит все три. Для каждого символа бот загружает исторические свечи (OHLCV — Open, High, Low, Close, Volume) из Parquet-файла на диске. (src/__main__.py:530–540)

Если файл для символа отсутствует или пустой — этот символ **пропускается с предупреждением**, но прогон продолжается для остальных. Упасть с ошибкой (код 1) бот может только если не прошёл **ни один** символ. (src/__main__.py:533–539, 572–586)

---

### Шаг 2. Параметры окон WFA

Разбиение истории на «складки» управляется четырьмя параметрами:

| Параметр CLI | По умолчанию | Что значит |
|---|---|---|
| `--wfa-train` | 2000 баров | Длина обучающего окна |
| `--wfa-test` | 500 баров | Длина проверочного окна |
| `--wfa-folds` | 5 | Количество «складок» (окон) |
| `--wfa-embargo` | 20 баров | Зазор-карантин между обучением и проверкой |

(src/__main__.py:881–890, источник ADR 0014)

При интервале 1H (один бар = 1 час):
- обучающее окно 2000 баров ≈ 83 дня
- проверочное окно 500 баров ≈ 21 день
- зазор 20 баров ≈ 20 часов

Для 4H-интервала принято другое соотношение — 1000 обучающих и 250 проверочных баров (CC6 (b) консенсус). Это можно задать через CLI-флаги `--wfa-train 1000 --wfa-test 250`.

Класс `WindowSplitter` вычисляет границы каждой складки по формуле (src/backtest/walk_forward.py:40–59):

```python
train_start = k * test_bars          # каждая складка сдвигается вперёд на test_bars
train_end   = train_start + train_bars
test_start  = train_end + embargo_bars
test_end    = test_start + test_bars
```

Минимальное количество баров в датасете для запуска: `train_bars + embargo_bars + k_folds × test_bars` = 2000 + 20 + 5×500 = **4520 баров** при стандартных параметрах.

### Шаг 3. Приведение к году (annualization)

Многие финансовые метрики (Sharpe, Sortino) принято приводить к «годовому» масштабу, чтобы их можно было сравнивать между стратегиями с разными временными интервалами. Коэффициент пересчёта — `sqrt(bars_per_year)`.

Бот автоматически выбирает правильное значение в зависимости от интервала (src/__main__.py:518–529):

| Интервал | Баров в году | sqrt(N) |
|----------|-------------|---------|
| 5 минут  | 105 120     | ≈ 324.2 |
| 15 минут | 35 040      | ≈ 187.2 |
| 30 минут | 17 520      | ≈ 132.4 |
| **1 час (по умолчанию)** | **8 760** | **≈ 93.6** |
| 2 часа   | 4 380       | ≈ 66.2 |
| 4 часа   | 2 191       | ≈ 46.8 |
| 1 день   | 365         | ≈ 19.1 |

Если использовать неправильный множитель (например, взять 4380 вместо 8760 для 1H), Sharpe окажется занижен примерно вдвое — это создало бы ложные FAIL-вердикты. Именно поэтому значение берётся из таблицы по переданному `--interval`, а не фиксируется жёстко. (src/__main__.py:872–875, src/backtest/strategy_metrics.py:28–32)

### Шаг 4. Прогон WFA для каждого символа

Для каждой торговой пары вызывается [[single-symbol-wfa-and-data-loading|`_run_wfa_single_symbol`]] (src/backtest/data_loading.py:125–205). Она:

1. Создаёт `WindowSplitter` с параметрами из CLI.
2. Создаёт `WalkForwardRunner` — оркестратор, который запускает бэктест на каждой складке.
3. Для каждой складки запускает бэктест дважды: на обучающем окне (IS) и проверочном окне (OOS).
4. Считает отношение OOS-Sharpe / IS-Sharpe для данной складки.
5. Собирает все OOS-сделки через [[trade-extractor-and-records|`extract_trade_records`]].
6. Запускает тест Монте-Карло (см. Шаг 5).
7. Возвращает: список сделок, отношения Sharpe по складкам, результат раннера, p-значение MC.

(src/backtest/data_loading.py:125–205, src/backtest/walk_forward.py:66–152)

### Шаг 5. Монте-Карло p-value

[[monte-carlo-permutation|**Монте-Карло**]] — это способ проверить: «а вдруг стратегия зарабатывает просто случайно?». Мы берём все OOS-доходности и 2000 раз случайным образом переворачиваем знаки у каждой (+/-). Если оригинальная средняя доходность выше, чем у 95% таких «перекошенных» прогонов — значит, результат статистически значимый.

Технически: `sign_flip_p_value(returns, n_iterations=2000, seed=42)` — тест знакового переворота. p-value вычисляется как `(count_extreme + 1) / (2000 + 1)` — формула Phipson & Smyth (2010), которая гарантирует, что p-value никогда не равно ровно нулю при конечном числе перестановок. (src/backtest/mc_permutation.py:61–66, src/backtest/data_loading.py:168–170)

Seed=42 гарантирует **воспроизводимость**: одни и те же данные всегда дадут одно и то же p-value.

**При нескольких символах** берётся **максимум** из p-value всех символов — самый консервативный (наихудший) вариант. (src/__main__.py:588–589)

### Шаг 6. Агрегация результатов

После прогона по всем символам бот собирает:
- Все OOS-сделки в единый список `all_trades`
- Все отношения OOS/IS-Sharpe по складкам в `all_fold_sharpes`
- Все реальные аннуализированные OOS-Sharpe по складкам в `all_fold_oos_sharpes` — эти идут на вход DSR

(src/__main__.py:554–560)

### Шаг 7. DSR — поправка на перебор вариантов

**Deflated Sharpe Ratio (DSR)** — это «дефлированный» коэффициент Шарпа. Дефлированный означает: мы понижаем его, чтобы учесть, что прежде чем найти эту стратегию, мы уже перебрали много других вариантов. Чем больше вариантов перебрали — тем выше шанс, что хороший результат — просто удача.

Математически DSR использует формулу Bailey & López de Prado (2014), которая учитывает:
- Количество сделок (малая выборка — ненадёжнее)
- Форму распределения доходностей (асимметрия и тяжёлые хвосты)
- Сколько стратегий/параметров перебрали до этого (`n_trials`)
- Разброс Sharpe между прошлыми испытаниями (`sigma_SR`)

DSR > 0 означает: «с учётом всех поправок стратегия всё ещё превосходит нулевой бенчмарк». DSR ≤ 0 — вероятнее всего, просто удача.

**Порядок операций принципиален** (Bailey eq.13): текущее испытание записывается в журнал ([[cross-trial-log|`CrossTrialLog.append_trial`]]) **до** того, как читается разброс `sigma_SR`. Это включает текущий прогон в расчёт дисперсии — честная статистика. (src/__main__.py:607–617)

Для изоляции от других стратегий, `sigma_SR` вычисляется только по испытаниям с `strategy_class="wfa_meanrev"` — так результаты [[02-стратегии/atr-breakout-strategy|ATR-Breakout]] или [[02-стратегии/supertrend-strategy|Supertrend]] не «загрязняют» дисперсию [[02-стратегии/mean-reversion-strategy|Mean Reversion]]. Однако `n_trials` (ширина поискового пространства) берётся глобально — из всех записей журнала. (src/__main__.py:63–67, 624–625)

Если в журнале меньше 3 испытаний данного класса, `sigma_SR` считается статистически ненадёжной (степени свободы < 2). В этом случае бот вычисляет DSR с `n_trials=1` — без поправки на множественное тестирование. (src/analytics/cross_trial_log.py:197–232, src/__main__.py:638–639)

Путь данных журнала: `data/cross_trial_sharpes.json` (изменяется через переменную окружения `CROSS_TRIAL_LOG_PATH` — тесты используют это для изоляции). (src/analytics/cross_trial_log.py:52–70)

### Шаг 8. Шесть критериев приёмки T1–T6

После агрегации бот вычисляет метрики через `compute_t1_t6_metrics` и проверяет каждый из шести критериев. Все шесть должны пройти одновременно. (src/__main__.py:657–703, src/backtest/strategy_metrics.py)

| Критерий | Проверяет | Условие PASS | Что это значит простыми словами |
|----------|-----------|--------------|--------------------------------|
| **T1** | Sharpe OOS | ≥ 1.0 | Доходность хорошо превышает риск (аннуализировано) |
| **T2** | Sortino OOS | ≥ 1.5 | То же, но учитывает только убыточные сделки как риск |
| **T3** | Макс. просадка | < 25% | В худший момент капитал не проседал больше чем на четверть |
| **T4** | Винрейт + RR | Таблица ниже | Соотношение побед и средней прибыли/убытка согласовано |
| **T5** | Средняя доходность | > 0, t-стат ≥ 2.0, сделок ≥ 100 | Прибыль статистически значима при достаточной выборке |
| **T6** | OOS/IS Sharpe | среднее ≥ 0.7 | Результат на незнакомых данных близок к результату на обучающих |

(src/__main__.py:673–702)

**T4 подробнее** — двухпрофильный критерий (src/__main__.py:681–687):

| Средний RR (прибыль/убыток) | Минимальный винрейт |
|-----------------------------|---------------------|
| RR ≥ 2.0 | ≥ 35% |
| 1.5 ≤ RR < 2.0 | ≥ 45% |
| RR < 1.5 | FAIL безусловно |

T4 провален, если любое из условий не выполнено или если данных нет (NaN).

**T5 важный нюанс**: порог минимума сделок в `_cmd_wfa` — **100 сделок** (`metrics["t5_n_trades"] < 100`), что строже, чем в некоторых других путях системы. Почему t-статистика вообще требует минимальной выборки — разобрано в [[tstat-oos-is-metrics|T-статистика и OOS/IS Sharpe]]. (src/__main__.py:695)

### Шаг 9. Acceptance gate (внутренние ворота L1–L2)

Параллельно с T1–T6 вызывается `evaluate_acceptance_gate`, которая проверяет два дополнительных условия (src/__main__.py:663–666, src/backtest/walk_forward.py:155–242):

- **L1**: в каждой складке отношение OOS-Sharpe / IS-Sharpe ≥ 0.7 (порог `sharpe_threshold`)
- **L2**: MC p-value ≤ 0.05 (порог `p_threshold`)

Результат gate включается в JSON-вывод (`"acceptance_gate"`) для информации, но сам по себе **не блокирует** вердикт PASS — вердикт зависит только от T1–T6 и DSR. L1 и T6 частично перекрываются концептуально (оба про OOS/IS-ratio), но технически считаются отдельно. (src/__main__.py:663–666, 705)

dsr_pass = dsr_value is not None and dsr_value > 0
verdict = "PASS" if len(failed_criteria) == 0 and dsr_pass else "FAIL"

## Формулы и расчёты

### Sharpe Ratio (T1)

Подробный разбор [[sharpe-sortino-metrics|Sharpe и Sortino]] с интуицией «за не-финансиста» — на отдельной странице.

Формула: **Sharpe = mean(доходности) / std(доходности) × sqrt(баров_в_году)**

Что считает: насколько средняя доходность сделок превышает риск (разброс). Умножение на корень из числа баров в году приводит к «годовому» масштабу.

Реализация: (src/backtest/strategy_metrics.py:78–86)

```python
pnl_std = float(pnl_pcts.std(ddof=1))
sharpe_per_trade = float(pnl_pcts.mean()) / pnl_std
t1_sharpe_oos = sharpe_per_trade * annualization_factor  # annualization_factor = sqrt(bars_per_year)
```

Если std < 1e-12 (вырожденный ряд — все сделки одинаковые) — возвращается NaN, чтобы избежать деления на ноль. (src/backtest/strategy_metrics.py:82–86)

### Sortino Ratio (T2)

Формула: **Sortino = mean(доходности) / downside_dev × sqrt(баров_в_году)**

Отличие от Sharpe: знаменатель — не общий разброс, а только **нижнее отклонение** (среднеквадратичное от убыточных сделок, приведённое к нулю). Это справедливее: нас не должна пугать «нестабильность» прибыльных сделок.

```python
downside = np.minimum(pnl_pcts, 0.0)  # убыточные остаются, прибыльные → 0
downside_dev = float(np.sqrt(np.mean(downside**2)))
```

(src/backtest/strategy_metrics.py:88–101)

### Максимальная просадка (T3, max drawdown)

Формула: **MaxDD = max(peak − trough) / peak** по всей OOS-кривой капитала (подробнее — [[max-drawdown-winrate-rr|MaxDD, Win Rate и Risk-Reward]])

Что считает: самый глубокий провал от «пика» до «дна» — в долях от пика. Например, 0.20 означает просадку в 20%.

Особенность: к кривой капитала **добавляется начальный капитал** (10 000) как первая точка, чтобы первая убыточная сделка правильно считалась от стартового баланса. (src/backtest/strategy_metrics.py:103–114)

### DSR (Deflated Sharpe Ratio)

Итоговая формула Bailey & López de Prado (2014) eq. 13:

```
DSR = Φ((SR − SR*) × √(N−1) / √(1 − skew×SR + (kurt−1)/4 × SR²))
```

Где:
- `Φ` — функция нормального распределения (вероятность от −∞ до аргумента)
- `SR` — наш Sharpe (per-trade, не аннуализированный)
- `SR*` — «лучший Sharpe из N испытаний» (eq. 12: поправка на множественное тестирование через `sigma_SR` и `n_trials`)
- `N` — число сделок
- `kurt` — **полный** (Pearson) куртозис, а не избыточный (Fisher). Для нормального распределения Pearson=3 → в формуле даёт (3−1)/4 = 0.5, что воспроизводит Lo (2002). Если использовать Fisher (excess, где норм=0), формула занижала бы DSR.

(src/analytics/dsr.py:118–126, 165–172)

Единица измерения `sigma_SR`: поскольку fold-Sharpe берётся аннуализированным, а внутренний `sharpe` в `compute_dsr` — per-trade (не аннуализированный), перед eq.12 `sigma_SR` **делится** на `annualization_factor = sqrt(bars_per_year)`. Это восстанавливает единую шкалу (Bailey требует, чтобы SR, SR* и sigma_SR были в одних единицах). (src/analytics/dsr.py:153–157)

## Примеры / сценарии

### Сценарий: прогон на BTCUSDT, 1H, 5 складок

```bash
python -m src wfa --symbol BTCUSDT --start 2021-07-02 --end 2026-04-26 --interval 60
```

**Что происходит внутри:**

1. Загружается `data/BTCUSDT_1h.parquet` с данными 2021–2026.
2. Данные нарезаются на 5 складок: каждая — 2000 баров обучения + 20 баров карантин + 500 баров проверки.
3. На каждой из 5 складок бэктест запускается дважды (IS и OOS). Итого 10 прогонов.
4. Из 5 OOS-окон агрегируются все сделки — пусть 180 штук.
5. MC тест: 2000 раз переворачиваем знаки, получаем p = 0.031 < 0.05 — OK.
6. Средний OOS/IS-Sharpe ratio по 5 складкам = 0.78 > 0.7 — складки стабильны.
7. Записываем в `cross_trial_sharpes.json` наш аннуализированный OOS-Sharpe = 1.24.
8. Читаем sigma_SR (разброс Sharpe по предыдущим испытаниям класса `wfa_meanrev`). Если их ≥ 3 — применяем поправку DSR. Получаем DSR = 0.61 > 0 — OK.
9. T1=1.24 ✓, T2=1.67 ✓, T3=18.5% ✓, T4 win_rate=48% при RR=1.6 ✓, T5 t-stat=2.3 ✓, T6=0.78 ✓.
10. Вердикт: **PASS**, код возврата 0.

### Сценарий: первые 2 испытания класса → DSR без sigma_SR

При первом и втором запуске `wfa_meanrev` в журнале < 3 записей. `sigma_SR` возвращает NaN (недостаточно степеней свободы). Бот вызывает `compute_dsr(n_trials=1)` — без поправки на множественное тестирование. DSR всё равно вычисляется, но не учитывает прошлые испытания. (src/__main__.py:628–639, src/analytics/cross_trial_log.py:228–232)

### Сценарий: символ без Parquet-файла

Если `data/ETHUSDT_1h.parquet` отсутствует при запуске с `--symbols BTCUSDT,ETHUSDT`:

```

```

Прогон продолжается только по BTCUSDT. В финальном JSON: `"per_symbol": {"ETHUSDT": {"status": "missing_parquet", ...}}`. Вердикт выносится по имеющимся данным. (src/__main__.py:533–535)

## Подводные камни / что важно понимать

**1. Это инструмент защиты от самообмана, не гарантия прибыли.**
PASS означает: «стратегия прошла строгую проверку на исторических данных». Рынок меняется — прошлое не гарантирует будущее. PASS — необходимое, но не достаточное условие для реальной торговли.

**2. Порог T5 в этой команде — 100 сделок, не 50.**
В других частях системы встречается флор 50 (например, для дашборда). Но в `_cmd_wfa` жёстко прописано `< 100`: меньше 100 OOS-сделок — T5 провален. Это намеренно строже. (src/__main__.py:695)

**3. DSR требует ≥ 3 предыдущих испытаний одного класса для полной поправки.**
При первых 1–2 испытаниях класса `wfa_meanrev` поправка на множественное тестирование не применяется — DSR считается как будто испытание единственное. Это статистически обоснованно (ADR 0056), но означает: первые прогоны «мягче» к стратегии. (src/analytics/cross_trial_log.py:227–232)

**4. `acceptance_gate` в JSON — информация, не вердикт.**
Поле `"acceptance_gate"` показывает результаты L1 и L2, но финальный вердикт (`"verdict"`) зависит только от T1–T6 и DSR. Gate может быть `"passed": false`, а вердикт PASS — это не противоречие, а разные вещи. (src/__main__.py:663–666, 705)

**5. Журнал испытаний разделён по классам стратегий.**
`sigma_SR` берётся только из записей с `strategy_class="wfa_meanrev"`. Если в журнале много испытаний ATR-Breakout или Supertrend с экстремальными Sharpe — они не влияют на DSR Mean Reversion. Но `n_trials` (глобальный счётчик) учитывает всё — это честный штраф за поиск по всем стратегиям. (src/__main__.py:63–67, 624–625, src/analytics/cross_trial_log.py:197–232)

**6. MC тест — только sign-flip (знаковый переворот), не block-bootstrap.**
Block-bootstrap реализован в `mc_permutation.py`, но используется только как диагностика. Вердикт gate использует исключительно `sign_flip_p_value`. Это важно: block-bootstrap без инверсии знаков проверяет другое (дисперсию, не наличие преимущества). (src/backtest/mc_permutation.py:70–100)

**7. Нельзя запустить WFA без предварительного [[data-backfill-command|backfill]].**
Данные должны лежать в `data/<SYMBOL>_<INTERVAL>.parquet` — формат [[parquet-storage|Parquet-хранилища]] свечей. Если файла нет — символ пропускается с WARNING. Перед WFA нужно запустить: `python -m src backfill --symbol BTCUSDT --from 2021-07-02 --to 2026-04-26`.

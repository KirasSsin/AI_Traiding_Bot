# ADX: индикатор силы тренда

**TL;DR:** ADX — это «спидометр» рынка: он показывает не куда движется цена, а насколько сильно она движется. Значение выше 25 означает уверенный тренд; ниже 20 — рынок топчется на месте. Бот использует ADX как фильтр: входить в позицию только если тренд достаточно силён.

## Простыми словами

Представьте, что вы наблюдаете за автомобилем на трассе. Спидометр показывает скорость, но не говорит, едет ли машина на север или на юг. ADX — это именно спидометр рынка: он измеряет **силу** движения цены, но не его направление.

Если ADX высокий (например, 40) — цена движется уверенно, будь то вверх или вниз. Если ADX низкий (например, 12) — цена колеблется хаотично, без ясного направления. Такой рынок называют «боковым» или «флетовым» — цена ходит туда-сюда в узком диапазоне, как маятник.

Зачем это нужно боту? Стратегии, которые «ловят тренды», работают хорошо только когда тренд действительно есть. Если тренда нет, они генерируют множество ложных сигналов и теряют деньги. ADX играет роль вышибалы: он не пускает бота в сделку, пока рынок не «разгонится» до нужной скорости.

В дополнение к ADX система считает две «стрелки направления» — **+DI** (насколько сильно цена движется вверх) и **−DI** (насколько сильно вниз). Их сравнение помогает понять: раз уж тренд есть — а куда именно он направлен?

| Значение ADX | Что это значит |
|---|---|
| < 20 | Слабый рынок, боковик — бот не входит |
| 20–25 | Зарождающийся тренд |
| > 25 | Сильный тренд — порог входа в EMA Crossover стратегии |
| > 40–50 | Очень сильный, иногда «перегретый» тренд |

## Как это работает у нас

Все три функции — `adx()`, `plus_di()`, `minus_di()` — определены в одном файле и устроены одинаково просто: принимают на вход массивы свечей и возвращают рассчитанные значения.

### Шаг 1. Три функции-обёртки (indicators.py)

```python
def adx(high, low, close, period=14):
    _validate_hlc(high, low, close, period)
    return talib.ADX(high, low, close, timeperiod=period)

def plus_di(high, low, close, period=14):
    _validate_hlc(high, low, close, period)
    return talib.PLUS_DI(high, low, close, timeperiod=period)

def minus_di(high, low, close, period=14):
    _validate_hlc(high, low, close, period)
    return talib.MINUS_DI(high, low, close, timeperiod=period)
```

(src/signalgen/indicators.py:127–149)

Каждая функция сначала проверяет корректность входных данных через `_validate_hlc()` (одинаковая длина массивов, минимум period ≥ 2), а затем делегирует расчёт библиотеке **TA-Lib** — это стандартная промышленная библиотека технического анализа. По решению ADR 0011, для ADX бот использует сглаживание Уайлдера (α = 1/period), которое TA-Lib применяет по умолчанию для этого индикатора.

Функция `_validate_hlc()` выбрасывает исключение если: массивы разной длины, не одномерные, или period < 2. (src/signalgen/indicators.py:152–156)

**Параметры по умолчанию:** все три функции имеют `period=14` — стандарт Уайлдера из его книги 1978 года. В боте этот период задаётся через [[configuration-and-settings|конфиг]]: `strategy_adx_period: int = 14` (src/platform/config.py:94).

### Шаг 2. Как стратегия использует ADX

В стратегии [[ema-crossover-strategy|EMA Crossover]] бот вычисляет ADX при каждом закрытии свечи:

```python
adx_arr  = adx(highs, lows, closes, self._adx_n)
pdi_arr  = plus_di(highs, lows, closes, self._adx_n)
mdi_arr  = minus_di(highs, lows, closes, self._adx_n)
```

(src/signalgen/strategy.py:103–105)

Затем берётся последнее значение из каждого массива (текущая свеча, индекс `[-1]`) и записывается в «снимок» индикаторов (src/signalgen/strategy.py:112–114).

### Шаг 3. ADX в правиле входа

Чтобы открыть позицию в покупку, должны выполниться все четыре условия одновременно (src/signalgen/strategy.py:127–137):

```python
trend_strong = Decimal(str(snapshot["adx"])) > self._adx_threshold  # ADX > 25
bullish_dir  = snapshot["plus_di"] > snapshot["minus_di"]            # +DI > −DI
```

`self._adx_threshold` берётся из конфига как `Decimal("25")` (src/platform/config.py:95). Порог строгий: при ADX ровно 25 сигнал не выдаётся — только при строго большем значении.

Дополнительно проверяется **направление**: даже если тренд сильный (ADX > 25), он должен быть бычьим (+DI > −DI). Если, например, рынок падает с ADX = 40 — +DI < −DI, и бот не входит в покупку.

### Шаг 4. ADX в правиле выхода

Выход из позиции в стратегии EMA Crossover определяется комбинацией двух сигналов (src/signalgen/strategy.py:146–157):

```python
flip_down   = ema_fast_arr[-1] < ema_slow_arr[-1]      # быстрая EMA ушла ниже медленной
bearish_dir = snapshot["minus_di"] > snapshot["plus_di"] # −DI доминирует над +DI
if flip_down and bearish_dir:
    → выход
```

Важное замечание: в коде стратегии нет отдельной проверки «ADX упал ниже 20». Выход происходит только при одновременном выполнении обоих условий: разворот EMA И смена направления DI. Описание в [[documentation-tab|дашборде]] («ADX падает ниже 20») отражает общепринятую трактовку ADX как сигнала угасания тренда, но в исполняемом коде `strategy.py` этот порог отдельной проверкой не реализован.

### Шаг 5. Прогрев — сколько свечей нужно ждать

ADX использует **двойное сглаживание**: сначала рассчитываются +DI и −DI (требует `period` свечей), затем из них вычисляется DX, который снова сглаживается за `period` баров. Итого ADX «прогревается» за ≈ 2×period − 1 свечей.

Код стратегии явно учитывает это: минимальный буфер для начала работы задан как `max(ema_slow, 2 * adx_period) + 1` (src/signalgen/strategy.py:92). При настройках по умолчанию (adx_period=14, ema_slow=26): max(26, 28) + 1 = 29 свечей. Только после накопления 29 закрытых свечей стратегия начинает проверять сигналы.

Буфер скользящего окна при этом хранит `max(ema_slow, 2*adx_period, atr_period, rsi_period) + 5` баров = max(26, 28, 14, 14) + 5 = 33 свечи (src/signalgen/strategy.py:57).

## Формулы и расчёты

### True Range — «настоящий диапазон» свечи

Прежде чем считать направленное движение, нужно понять, насколько «широка» каждая свеча с учётом гэпов (разрывов между ценами закрытия соседних свечей):

```text
TR = max(High − Low, |High − PrevClose|, |Low − PrevClose|)
```

Простыми словами: TR — это максимальный из трёх промежутков: (1) диапазон самой свечи от минимума до максимума, (2) расстояние от предыдущего закрытия до текущего максимума, (3) расстояние от предыдущего закрытия до текущего минимума.

### +DM и −DM — «направленное движение»

```text
+DM = High[t] − High[t−1],  если > 0 и > |Low[t] − Low[t−1]|, иначе 0
−DM = Low[t−1] − Low[t],   если > 0 и > |High[t] − High[t−1]|, иначе 0
```

Простыми словами: +DM измеряет, насколько новый максимум выше предыдущего (движение вверх); −DM — насколько новый минимум ниже предыдущего (движение вниз). Если обе стороны двигались, засчитывается более сильная из них.

### +DI и −DI — нормализованные индикаторы направления

```text
+DI = 100 × Wilder-smooth(+DM, period) / Wilder-smooth(TR, period)
−DI = 100 × Wilder-smooth(−DM, period) / Wilder-smooth(TR, period)
```

Деление на [[atr-indicator|ATR]] (сглаженный TR) нормализует движение: оно выражается не в абсолютных единицах цены, а в процентах от «широты» рынка. Диапазон обоих индикаторов: 0–100.

### DX — индекс направленного движения

```text
DX = 100 × |+DI − −DI| / (+DI + −DI)
```

DX показывает, насколько сильно одно направление доминирует над другим. Если +DI = 30 и −DI = 30 — рынок сбалансирован, DX = 0. Если +DI = 50 и −DI = 10 — явное превосходство быков, DX = 67.

Эта формула явно указана в docstring функции `adx()` (src/signalgen/indicators.py:130):
```
ADX = Wilder-smooth(DX, period); DX = 100 · |+DI − −DI| / (+DI + −DI).
```

### ADX — сглаженный DX

```text
ADX = Wilder-smooth(DX, period)
```

**Сглаживание Уайлдера** (Wilder smoothing) — это особый вид экспоненциальной скользящей средней с коэффициентом α = 1/period (медленнее, чем классическая EMA с α = 2/(period+1)). Для period=14: α = 1/14 ≈ 0.071 — новые значения влияют слабо, старые «забываются» медленно. Именно из-за этой инерции ADX медленно реагирует на резкие смены рынка.

**Реализация:** TA-Lib применяет сглаживание Уайлдера внутри `talib.ADX()` по умолчанию согласно ADR 0011. Бот не переопределяет этот механизм — доверяет стандартной имплементации библиотеки (src/signalgen/indicators.py:137).

### ADX в снимке сигнала

Все три значения (adx_14, plus_di_14, minus_di_14) сохраняются в модели [[signal-architecture|Signal]] с валидацией диапазона 0–100 (src/signalgen/models.py:31–33):

```python
adx_14:      Decimal = Field(..., ge=0, le=100)
plus_di_14:  Decimal = Field(..., ge=0, le=100)
minus_di_14: Decimal = Field(..., ge=0, le=100)
```

## Примеры / сценарии

### Сценарий 1: Вход разрешён — сильный бычий тренд

Допустим, Bitcoin три дня подряд обновляет максимумы. Бот накопил 29 закрытых часовых свечей и вычислил:

- ADX = 32 → > 25, тренд сильный, условие выполнено
- +DI = 28, −DI = 12 → +DI > −DI, направление бычье, условие выполнено
- [[ema-rsi-indicators|EMA(12)]] пересекла EMA(26) снизу вверх на этой свече — крест подтверждён
- [[ema-rsi-indicators|RSI]] = 58 → < 70 (не перекуплено), условие выполнено

Все четыре условия выполнены одновременно → бот генерирует сигнал LONG.

### Сценарий 2: Вход заблокирован ADX — боковой рынок

Цена Bitcoin ходит в диапазоне $95,000–$97,000 несколько дней. Несмотря на то, что EMA(12) может периодически пересекать EMA(26), ADX = 14 < 25. Бот видит: тренда нет, входить нельзя — сигнал не выдаётся.

Это защищает от «ложных пересечений» (whipsaw): в боковике EMA-линии часто пересекаются туда-сюда, порождая убыточные сделки.

### Сценарий 3: Вход заблокирован направлением — сильный медвежий тренд

ADX = 38 (тренд очень сильный), но рынок падает: −DI = 40, +DI = 8. Условие `+DI > −DI` не выполнено → бот не входит в покупку. Это правильно: в спот-торговле (v0.1 не торгует в короткую) открывать LONG в падающем рынке нельзя.

### Сценарий 4: Прогрев — первые 28 свечей молчание

При старте бота на новой паре первые 28 закрытых свечей накапливаются в буфере без генерации каких-либо сигналов: `len(self._bars) < 29` → возвращается None (src/signalgen/strategy.py:92–94). Начиная с 29-й свечи бот начинает проверять условия входа.

### Сценарий 5: Выход из позиции через DI-разворот

Бот находится в позиции LONG. Через несколько дней тренд начинает угасать:

- EMA(12) опускается ниже EMA(26) (`flip_down = True`)
- −DI = 25 > +DI = 15 (`bearish_dir = True`)

Оба условия выполнены → бот генерирует сигнал FLAT с reason `EXIT_FLAT_SIGNAL_FLIP` (src/signalgen/strategy.py:150–156).

## Подводные камни / что важно понимать

**ADX запаздывает.** Из-за двойного сглаживания Уайлдера ADX реагирует на изменения рынка медленно: тренд уже начался — ADX ещё низкий; тренд закончился — ADX всё ещё высокий. Это нормально для фильтра (лучше войти чуть позже, но в настоящий тренд), но объясняет, почему выход из позиции не завязан только на ADX.

**ADX не говорит о направлении.** Значение ADX = 50 может означать и мощный рост, и мощное падение. Именно для этого нужны +DI и −DI. В коде бот проверяет их отдельно: `bullish_dir = snapshot["plus_di"] > snapshot["minus_di"]` (src/signalgen/strategy.py:128).

**Нулевые заглушки в других стратегиях.** В стратегиях, которые не используют ADX ([[donchian-channel-indicator|Donchian]], ATR Breakout, [[supertrend-indicator|Supertrend]], Volume Breakout, Mean Reversion, Kronos), поля `adx_14`, `plus_di_14`, `minus_di_14` заполняются нулём-заглушкой. Это не ошибка — это явный сигнал: «стратегия не вычисляет этот индикатор». Нули в этих полях нельзя интерпретировать как «ADX равен нулю» (src/signalgen/donchian_strategy.py:163–165, src/signalgen/atr_breakout_strategy.py:354–356).

**Разница между ADX-порогом входа и выхода.** Порог входа — 25 (строгий, из конфига). Порог выхода в коде `strategy.py` отдельно не задан: выход происходит по развороту EMA + смене направления DI. Описания в дашборде упоминают «ADX < 20» как сигнал выхода — это интерпретационный текст, а не исполняемая проверка в `strategy.py`.

**Двойная задержка прогрева.** Период 14 означает прогрев ≈ 27 свечей (2×14−1), а не 14. Буфер стратегии считает это явно через `2 * adx_period` в формуле `min_required` (src/signalgen/strategy.py:92). При period=14 и ema_slow=26: прогрев ждёт 29 свечей.

**TA-Lib, не ручная реализация.** ADX, +DI, −DI вычисляются через TA-Lib (промышленная библиотека), а не через собственный код. Это отличает их от [[wilder-atr-and-stops|`wilder_atr()`]] — вручную написанного варианта ATR, который используют другие стратегии. Для ADX ручной реализации в проекте нет, только обёртка вокруг `talib.ADX/PLUS_DI/MINUS_DI` (src/signalgen/indicators.py:127–149).

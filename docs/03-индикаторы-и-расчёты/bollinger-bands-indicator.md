# Полосы Боллинджера: канал волатильности

**TL;DR:** Полосы Боллинджера — это три линии вокруг скользящей средней цены: средняя, верхняя и нижняя. Когда цена вырывается за нижнюю полосу, стратегия [[mean-reversion-strategy|Mean Reversion]] считает это сигналом перепроданности. Ширина канала автоматически растёт при высокой волатильности и сужается при спокойном рынке.

---

## Простыми словами

Представьте, что вы отслеживаете ежедневную температуру воздуха за год. Большую часть времени она колеблется в «нормальном» диапазоне — скажем, от −5 до +25 градусов. Когда температура вдруг опускается до −20, вы понимаете: что-то экстремальное происходит, это сильно ниже нормы. Весной и летом «нормальный» диапазон смещается и расширяется, зимой — сжимается.

Полосы Боллинджера (англ. Bollinger Bands) работают точно так же, только вместо температуры — цена актива, а вместо сезонов — рыночная волатильность (изменчивость цен).

Три компонента:
- **Средняя полоса** (Middle Band) — обычная средняя цена за последние 20 свечей. Это и есть «нормальная» цена прямо сейчас.
- **Верхняя полоса** (Upper Band) — средняя плюс некоторое число стандартных отклонений. Это «потолок» нормального поведения.
- **Нижняя полоса** (Lower Band) — средняя минус то же число стандартных отклонений. Это «пол» нормального поведения.

**Стандартное отклонение** (сигма, σ) — мера того, насколько сильно цены разбросаны относительно средней. Если за 20 свечей цены шли почти ровно, стандартное отклонение маленькое → полосы узкие. Если цены прыгали туда-сюда, стандартное отклонение большое → полосы широкие. Канал буквально «дышит» вместе с рынком.

**Зачем это нашему боту?** Стратегия Mean Reversion («возврат к среднему») исходит из идеи: если цена ушла слишком далеко от нормы — скорее всего, она вернётся обратно. Когда цена пробивает нижнюю полосу Боллинджера, бот фиксирует аномально низкую цену и рассматривает её как потенциальный момент для покупки.

## Как это работает у нас

### Функция `bollinger_bands` — вычисление трёх массивов

Всё начинается с единственной функции в `src/signalgen/bollinger_bands.py`.

```python
def bollinger_bands(
    close: np.ndarray, *, period: int = 20, k: float = 2.0
) -> tuple[np.ndarray, np.ndarray, np.ndarray]:
```

Принимает массив цен закрытия (`close`) и возвращает три массива той же длины: `(upper, middle, lower)`.

**Параметры по умолчанию:**
- `period = 20` — количество свечей в скользящем окне. Именно столько последних цен учитывается при каждом расчёте.
- `k = 2.0` — множитель ширины канала. Сколько стандартных отклонений откладывать от средней.

(src/signalgen/bollinger_bands.py:15–17)

**Защита от неверного ввода.** Функция сразу проверяет три условия и выбрасывает ошибку, если что-то не так (src/signalgen/bollinger_bands.py:32–37):
- `period` должен быть не меньше 2 (одной свечи недостаточно для расчёта среднего);
- `k` должен быть строго больше нуля;
- массив `close` должен быть одномерным.

### Прогрев — первые (period − 1) значений равны NaN

Чтобы посчитать среднее из 20 свечей, нужно накопить хотя бы 20 свечей. Пока их меньше — значения не определены. Поэтому первые 19 позиций в каждом из трёх массивов заполняются специальным значением `NaN` («не число»). Первое осмысленное значение появляется на позиции с индексом 19 (двадцатая свеча, если считать с единицы).

```python
for i in range(period - 1, n):
    window = close[i - period + 1 : i + 1]
    m = float(np.mean(window))
    s = float(np.std(window, ddof=0))  # population stdev per Bollinger
    middle[i] = m
    upper[i] = m + k * s
    lower[i] = m - k * s
```

(src/signalgen/bollinger_bands.py:47–53)

Цикл идёт по каждому индексу начиная с `period − 1`. Для каждого индекса берётся скользящее окно ровно из `period` последних цен, вычисляется их среднее (`m`) и популяционное стандартное отклонение (`s`), а затем формируются три значения.

### Почему популяционное стандартное отклонение (ddof=0)?

Это ключевой технический выбор, который влияет на ширину канала.

Существует два варианта стандартного отклонения:
- **Выборочное** (ddof=1) — слегка увеличенное, применяется когда имеющиеся данные — лишь выборка из большей генеральной совокупности.
- **Популяционное** (ddof=0) — «честное» среднеквадратичное по всем имеющимся данным, без поправочного коэффициента.

В нашем случае 20 свечей скользящего окна — это не выборка, а **вся** совокупность данных, по которым мы считаем полосу. Поэтому применяется популяционное отклонение. Так же делал Джон Боллинджер в оригинальной спецификации 1980-х. Это намеренный выбор, зафиксированный в заголовке файла: `Population standard deviation (ddof=0) per Bollinger original spec.` (src/signalgen/bollinger_bands.py:7).

На практике разница невелика: для окна в 20 свечей популяционное отклонение примерно на **2.6%** меньше выборочного — канал будет чуть уже при ddof=0, чем при ddof=1. Это не ошибка, а осознанный архитектурный выбор.

### Реализация в бэктест-раннере

В `src/backtest/indicators.py` Полосы Боллинджера реализованы иначе — через pandas DataFrame с методами `rolling().mean()` и `rolling().std(ddof=0)` (подробнее об этой векторной ветке — в [[indicators-and-signals]]). Принципиальная разница: там используется параметр `min_periods=bb_period`, который гарантирует, что pandas тоже выдаёт `NaN` до накопления `period` баров — поведение полностью согласовано с функцией из `bollinger_bands.py` (src/backtest/indicators.py:116–117).

```python
rolling_mean = out["close"].rolling(window=bb_period, min_periods=bb_period).mean()
rolling_std  = out["close"].rolling(window=bb_period, min_periods=bb_period).std(ddof=0)
```

### Как полосы используются в стратегии Mean Reversion

Стратегия `MeanReversionRsiBBStrategy` вызывает `bollinger_bands` в методе `on_bar` при каждой новой закрытой свече (src/signalgen/mean_reversion_strategy.py:147–149):

```python
upper_bb, middle_bb, lower_bb = bollinger_bands(
    closes, period=self._bb_n, k=self._bb_std_mult
)
```

Затем берётся только **последнее** значение каждого массива — полоса на текущую свечу (src/signalgen/mean_reversion_strategy.py:153–158). Сигнал формируется двумя правилами:

**Вход в позицию (LONG):** цена закрытия текущей свечи вышла ниже нижней полосы, **и одновременно** [[ema-rsi-indicators|RSI]] упал ниже порога перепроданности. Оба условия обязательны (AND-логика). (src/signalgen/mean_reversion_strategy.py:167–175)

**Выход из позиции:** цена поднялась выше верхней полосы, **или** RSI поднялся выше порога перекупленности. Здесь достаточно одного из двух условий (OR-логика). (src/signalgen/mean_reversion_strategy.py:178–184)

**Минимальный буфер данных.** Перед расчётом стратегия проверяет, что в буфере достаточно свечей. Для параметров S17 (rsi_period=14, bb_period=20) минимум равен `max(14, 20) + 1 = 21` свеча. Пока свечей меньше — метод возвращает `None`, сигнал не формируется. (src/signalgen/mean_reversion_strategy.py:138–139)

## Формулы и расчёты

### Три формулы

```text
Средняя полоса:  middle[i] = среднее( close[i-period+1 : i+1] )
Верхняя полоса:  upper[i]  = middle[i] + k × σ
Нижняя полоса:   lower[i]  = middle[i] − k × σ
```

Где **σ (сигма)** — популяционное стандартное отклонение тех же `period` значений:

```text
σ = sqrt( Σ(xᵢ − mean)² / period )
```

**Расшифровка простыми словами:** для каждой свечи берём последние `period` цен, считаем их среднее, затем смотрим насколько каждая цена отклоняется от этого среднего, возводим отклонения в квадрат, усредняем и берём корень. Чем больше цены прыгали туда-сюда, тем больше σ — тем шире канал.

(src/signalgen/bollinger_bands.py:50, numpy параметр `ddof=0`)

### Параметры у нас

| Параметр | Значение по умолчанию | В стратегии Mean Reversion (S17-relaxed, LOCKED) |
|---|---|---|
| `period` | 20 | 20 |
| `k` (множитель σ) | 2.0 | **1.5** |

Источник LOCKED-параметра: `MEAN_REVERSION_S17_RELAXED_PARAMS["bb_std_mult"] = 1.5` (src/signalgen/mean_reversion_strategy.py:49). Подтверждено тестом: `tests/unit/test_s17_relaxed_params_constant.py:25`.

### Почему k=1.5, а не стандартные k=2.0?

Стандартный коэффициент Боллинджера — 2.0. При нормальном распределении цен примерно 95% всех свечей попадут внутрь канала k=2.0. Значит, пробой полосы — редкое событие.

При k=1.5 внутри канала оказывается около 87% свечей. Нижняя полоса при k=1.5 **выше**, чем при k=2.0 — то есть цена достигает её **чаще**. Это делает стратегию **более чувствительной**: сигналы появляются при менее экстремальных движениях.

Параметр был выбран по результатам бэктест-исследования: S15 с k=2.0 (и RSI 30/70) дал [[mc-permutation-test|монте-карло]] p=0.998 — статистический шум, а S17 с k=1.5 (и RSI 35/65) дал p=0.01 — статистически значимый результат. Именно поэтому параметры S17 зафиксированы как LOCKED и не подлежат изменению без повторной валидации. (src/signalgen/mean_reversion_strategy.py:34–52)

## Примеры / сценарии

### Пример 1 — расчёт «на пальцах»

Допустим, бот накопил 20 последних цен закрытия биткоина (в тысячах долларов):

```text
Последние 20 цен: равномерно распределены вокруг 50 000 $ со стандартным отклонением ~507 $
Средняя (middle):      50 116 $
Стандартное отклонение (σ, ddof=0): 507 $
```

**При k=2.0 (стандартный Боллинджер):**
```text
upper = 50 116 + 2.0 × 507 = 51 130 $
lower = 50 116 − 2.0 × 507 = 49 102 $
```

**При k=1.5 (наш S17-relaxed):**
```text
upper = 50 116 + 1.5 × 507 = 50 875 $
lower = 50 116 − 1.5 × 507 = 49 356 $
```

Нижняя полоса при k=1.5 находится на уровне 49 356 $, а при k=2.0 — на 49 102 $. Разница 254 $. Сигнал от k=1.5 сработает раньше (при более высокой цене), чем от k=2.0.

(Числа получены вычислением через `bollinger_bands()` с seed=0 и 25 барами.)

### Пример 2 — постоянная цена → нулевая ширина канала

Если цена 20 свечей подряд не менялась (например, всегда 50 000 $):

```text
σ = 0  →  upper = middle = lower = 50 000 $
```

Канал сжимается в одну точку. Любое движение цены немедленно пробьёт полосу. Это крайний случай: стандартное отклонение нуля — это тоже корректный результат, ошибки не будет. (tests/unit/test_bollinger_bands.py:13–19)

### Пример 3 — NaN-прогрев

Стратегия получает свечи одну за другой. Первые 19 свечей — полосы не определены (NaN). На 20-й свече появляется первое валидное значение:

```text
Свеча 1–19:   upper = NaN, middle = NaN, lower = NaN  (накапливаем данные)
Свеча 20:     первые валидные значения полос
Свеча 21+:    нормальная работа
```

Стратегия `MeanReversionRsiBBStrategy` дополнительно проверяет весь словарь `snapshot` на наличие NaN и возвращает `None` если хоть одно значение не готово — это второй уровень защиты от сигналов на основе неполных данных. (src/signalgen/mean_reversion_strategy.py:160–161)

## Подводные камни / что важно понимать

**ddof=0 — это намеренно, не ошибка.** Если вы сравниваете наш расчёт с Excel или другими библиотеками, которые по умолчанию используют выборочное отклонение (ddof=1), полосы будут чуть шире у них. Для окна в 20 свечей разница около 2.6%. Наш вариант соответствует оригинальной спецификации Боллинджера 1980-х и применяется одинаково в реальной торговле (`bollinger_bands.py`) и в бэктесте (`indicators.py`). Рассогласование было бы гораздо опаснее.

**k=1.5 — LOCKED параметр, нельзя менять произвольно.** Значение 1.5 для стратегии Mean Reversion зафиксировано в константе `MEAN_REVERSION_S17_RELAXED_PARAMS` и защищено `MappingProxyType` — любая попытка изменить словарь в runtime вызовет `TypeError`. Это защита от случайных мутаций в тестовых фикстурах или коде, которые могли бы переключить бота на «шумные» параметры S15 (k=2.0, RSI 30/70), статистически неотличимые от случайности (MC p=0.998). (src/signalgen/mean_reversion_strategy.py:39–52)

**Сигнал — на закрытой свече, исполнение — на открытии следующей.** Полосы вычисляются по `close[T]` (цена закрытия свечи T). Ордер выставляется по `open[T+1]` (цена открытия следующей свечи). Цена между ними может измениться — это нормально и намеренно: так исключается «заглядывание в будущее» (тот же принцип защиты от [[bar-source-live|look-ahead]] действует и в live-режиме). (src/signalgen/mean_reversion_strategy.py:11–12)

**Буфер ограничен.** Стратегия хранит в памяти не весь исторический ряд, а только последние `max(rsi_period, bb_period, atr_period) + 5 = 25` свечей (для S17-параметров). Это сделано для экономии памяти. Полосы пересчитываются по этому буферу целиком при каждой новой свече. (src/signalgen/mean_reversion_strategy.py:92)

**Сигнал только в сторону LONG.** Бот работает на спотовом рынке Bybit. Шортить (делать ставку на падение) невозможно. Поэтому нижняя полоса используется только для входа в покупку, верхняя — только как сигнал выхода. Стратегия никогда не открывает SHORT. (src/signalgen/mean_reversion_strategy.py:166–184)
